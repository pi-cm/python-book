본문을 읽다가 내적, 기울기, 로그, 소프트맥스 같은 말에서 걸리면 이 부록의 해당 절을 펼쳐 보세요. 절마다 마지막에 그 개념이 나오는 장을 적어 두었습니다. 거꾸로, 이 부록을 먼저 한 번 훑고 본문으로 들어가도 좋아요.

## B.1 벡터: 숫자 묶음은 화살표다

### 숫자 묶음을 화살표로 보기

서울의 오늘 날씨를 (기온 3도, 습도 4)라는 숫자 두 개로 적었다고 해 봅시다. 이 두 숫자를 가로 3칸, 세로 4칸 간 곳을 가리키는 **화살표**로 그릴 수 있어요. 이렇게 숫자를 순서대로 늘어놓은 묶음을 **벡터(vector)** 라고 합니다. 4장에서 만든 1차원 텐서가 바로 벡터예요.

숫자가 두 개면 종이 위의 화살표, 세 개면 방 안의 화살표입니다. 그 이상은 그림으로 그릴 수 없지만 계산은 똑같아요. 1장 1.2절에서 붓꽃 한 송이를 "4차원 공간의 점 하나"로 봤고, 13장의 단어 임베딩은 768차원 화살표였습니다. 차원이 몇이든 "길이"와 "방향"이라는 두 성질을 가진다는 점만 기억하면 됩니다.

```python
import torch

# 두 도시의 (기온, 습도)를 화살표로 본다
서울 = torch.tensor([3.0, 4.0])
부산 = torch.tensor([6.0, 8.0])

길이 = (서울 ** 2).sum().sqrt()            # 피타고라스: 제곱해서 더하고 제곱근
print("서울 화살표의 길이:", 길이.item(), torch.linalg.norm(서울).item())
print("두 점 사이 거리   :", torch.linalg.norm(부산 - 서울).item())
print("두 배로 늘리기    :", (서울 * 2).tolist())
```

```text
서울 화살표의 길이: 5.0 5.0
두 점 사이 거리   : 5.0
두 배로 늘리기    : [6.0, 8.0]
```

화살표의 **길이**는 피타고라스 정리 그대로, 각 숫자를 제곱해서 더한 뒤 제곱근을 씌운 값입니다. 3과 4면 9 + 16 = 25, 제곱근은 5죠. `torch.linalg.norm`이 같은 계산을 해 줍니다. 길이를 **노름(norm)** 이라고도 불러요. 두 점 사이의 거리는 "한 점에서 다른 점으로 가는 화살표"의 길이입니다. 1장 1.5절의 최근접 이웃이 이웃을 고를 때 쓴 거리가 이것이에요(유클리드 거리). 8장 8.2절의 weight decay가 작게 만드는 "가중치의 크기"도, 8.9절의 그래디언트 클리핑이 잘라 내는 "기울기의 길이"도 모두 이 노름입니다.

### 내적: 같은 자리끼리 곱해서 더하기

두 벡터를 하나의 숫자로 비교하는 가장 기본적인 방법이 **내적(dot product)** 입니다. 계산은 단순해요. 같은 자리끼리 곱하고, 모두 더합니다.

```python
import torch

a = torch.tensor([1.0, 2.0, 3.0])
b = torch.tensor([4.0, 5.0, 6.0])

print("같은 자리끼리 곱하기:", (a * b).tolist())
print("그걸 모두 더하기   :", (a * b).sum().item())   # 이것이 내적
print("@ 로 한 번에       :", (a @ b).item())
print("torch.dot          :", torch.dot(a, b).item())
```

```text
같은 자리끼리 곱하기: [4.0, 10.0, 18.0]
그걸 모두 더하기   : 32.0
@ 로 한 번에       : 32.0
torch.dot          : 32.0
```

1 × 4 + 2 × 5 + 3 × 6 = 32입니다. PyTorch에서는 `@` 기호로 한 번에 쓸 수 있어요. 그런데 이 숫자가 무엇을 뜻할까요? 길이는 그대로 두고 방향만 바꿔 가며 내적을 재 보면 보입니다.

```python
import torch

기준 = torch.tensor([1.0, 0.0])
비교 = {
    "같은 방향": torch.tensor([2.0, 0.0]),
    "45도"     : torch.tensor([1.0, 1.0]),
    "직각"     : torch.tensor([0.0, 3.0]),
    "반대 방향": torch.tensor([-2.0, 0.0]),
}
for 이름, v in 비교.items():
    print(f"{이름}: 내적 {(기준 @ v).item():.1f}")
```

```text
같은 방향: 내적 2.0
45도: 내적 1.0
직각: 내적 0.0
반대 방향: 내적 -2.0
```

방향이 같으면 크고, 직각이면 0, 반대면 음수입니다. **내적은 두 화살표가 같은 쪽을 가리키는 정도**예요. 12장 12.1절의 어텐션이 질문(쿼리)과 키의 내적으로 "얼마나 관련 있는지" 점수를 매기는 이유가 이것입니다.

### 코사인 유사도: 길이를 빼고 방향만 비교하기

그런데 내적은 길이에도 영향을 받습니다. 방향이 똑같아도 화살표가 10배 길면 내적도 10배가 되죠. 방향만 비교하고 싶다면 내적을 두 길이의 곱으로 나눠 줍니다. 이것이 **코사인 유사도(cosine similarity)** 예요. 결과는 언제나 -1에서 1 사이이고, 1이면 같은 방향, 0이면 직각, -1이면 정반대입니다.

```python
import torch
import torch.nn.functional as F

a = torch.tensor([1.0, 1.0])
b = torch.tensor([10.0, 10.0])     # a와 방향이 같고 길이만 10배
c = torch.tensor([1.0, 0.0])       # a와 45도
d = torch.tensor([-1.0, -1.0])     # a와 정반대


def 코사인(x: torch.Tensor, y: torch.Tensor) -> float:
    """내적을 두 길이의 곱으로 나눈다."""
    return ((x @ y) / (x.norm() * y.norm())).item()


for 이름, v in [("b", b), ("c", c), ("d", d)]:
    print(f"a와 {이름}: 내적 {(a @ v).item():6.1f}  코사인 {코사인(a, v):+.4f}")
print("내장 함수(a와 c):", round(F.cosine_similarity(a, c, dim=0).item(), 4))

# 길이를 1로 맞춘(단위 벡터) 뒤 행렬 곱 한 번이면 모든 쌍의 코사인이 나온다
단위 = F.normalize(torch.stack([a, b, c, d]), dim=1)
for 줄 in (단위 @ 단위.T).tolist():
    print([f"{값:+.2f}" for 값 in 줄])
```

```text
a와 b: 내적   20.0  코사인 +1.0000
a와 c: 내적    1.0  코사인 +0.7071
a와 d: 내적   -2.0  코사인 -1.0000
내장 함수(a와 c): 0.7071
['+1.00', '+1.00', '+0.71', '-1.00']
['+1.00', '+1.00', '+0.71', '-1.00']
['+0.71', '+0.71', '+1.00', '-0.71']
['-1.00', '-1.00', '-0.71', '+1.00']
```

a와 b는 길이가 10배 다르지만 코사인 유사도는 1입니다. 방향만 봤으니까요. 마지막 부분이 실전에서 쓰는 방법입니다. 먼저 모든 벡터의 길이를 1로 맞추고(`F.normalize`, 이런 벡터를 **단위 벡터**라고 해요), 행렬 곱 한 번(다음 절)으로 모든 쌍의 내적을 구하면 그것이 곧 모든 쌍의 코사인 유사도입니다. 4장 4.11절에서 기후가 닮은 도시를 찾을 때, 13장 13.7절에서 뜻이 비슷한 단어를 찾을 때 이 방법을 썼어요.

| 개념 | 처음 나오는 곳 | 다시 쓰이는 곳 |
|---|---|---|
| 벡터, 점으로 보는 샘플 | 1장 1.2절, 1.5절 | 4장 4.2절, 13장 13.7절 |
| 거리(유클리드 거리) | 1장 1.5절 | 3장 3.6절(k-means) |
| 노름(벡터의 길이) | 8장 8.2절(가중치 크기) | 8장 8.9절(그래디언트 클리핑) |
| 내적 | 12장 12.1절(계산은 4장 4.11절의 행렬 곱 안에 이미 있음) | 12장 12.2절, 13장 13.7절, 21장 21.5절 |
| 코사인 유사도 | 4장 4.11절 | 10장 10.4절, 12장 12.6절, 13장 13.7절, 21장 21.7절 |

## B.2 행렬 곱과 모양 규칙

### 모양 규칙 하나만 기억하기

**행렬**은 숫자를 가로세로 표로 늘어놓은 것, 즉 2차원 텐서입니다. 딥러닝 코드에서 가장 많이 하는 계산이 행렬 곱(`@`)이고, 가장 많이 나는 오류도 행렬 곱의 모양 오류예요. 규칙은 하나뿐입니다. **"앞 행렬의 열 수와 뒤 행렬의 행 수가 같아야 하고, 결과는 (앞의 행 수, 뒤의 열 수)가 된다."** 가운데 숫자가 맞물려 사라진다고 기억하면 쉬워요.

```python
import torch

A = torch.ones(2, 3)
B = torch.ones(3, 4)
print("(2, 3) @ (3, 4) ->", tuple((A @ B).shape))

try:
    A @ torch.ones(2, 4)
except RuntimeError as 오류:
    print("오류:", 오류)

# 맨 앞 차원은 배치로 보고 따로따로 곱한다
배치 = torch.ones(8, 2, 3)
print("(8, 2, 3) @ (3, 4) ->", tuple((배치 @ B).shape))
```

```text
(2, 3) @ (3, 4) -> (2, 4)
오류: mat1 and mat2 shapes cannot be multiplied (2x3 and 2x4)
(8, 2, 3) @ (3, 4) -> (8, 2, 4)
```

`(2, 3) @ (3, 4)`는 가운데 3이 맞물려 `(2, 4)`가 됩니다. `(2, 3) @ (2, 4)`는 가운데가 3과 2로 달라서 오류가 나요. 오류 메시지의 `2x3 and 2x4`를 보고 가운데 두 숫자부터 확인하는 습관을 들이세요(4장 4.10절). 마지막 줄처럼 3차원 이상이면 **맨 뒤 두 차원끼리** 곱하고, 앞쪽 차원은 배치로 보고 따로따로 계산합니다. 12장 12.5절의 멀티헤드 어텐션이 `(배치, 헤드, 글자, 칸)` 모양으로 한꺼번에 계산할 수 있는 것도 이 덕분이에요.

### 행렬 곱은 내적을 한꺼번에 하는 것

그럼 행렬 곱의 결과 한 칸은 무엇일까요? **앞 행렬의 한 줄과 뒤 행렬의 한 열의 내적**입니다.

```python
import torch

x = torch.tensor([[1.0, 2.0, 3.0],
                  [0.0, 1.0, 0.0]])      # 샘플 2개, 특성 3개
W = torch.tensor([[1.0, 0.0],
                  [0.0, 1.0],
                  [1.0, 1.0]])           # 특성 3개 -> 출력 2개

결과 = x @ W
print(결과)
# 결과[i, j]는 x의 i번째 줄과 W의 j번째 열의 내적
print("손으로 [0, 1]:", (x[0] @ W[:, 1]).item())
```

```text
tensor([[4., 5.],
        [0., 1.]])
손으로 [0, 1]: 5.0
```

결과의 `[0, 1]` 칸 5는 `x`의 0번 줄 `[1, 2, 3]`과 `W`의 1번 열 `[0, 1, 1]`의 내적(0 + 2 + 3)이에요. 그러니 `(샘플 수, 특성 수) @ (특성 수, 출력 수)`는 "샘플마다, 출력마다 내적 하나씩"을 한 번에 계산합니다. 반복문으로 하면 샘플 수 × 출력 수만큼 돌아야 할 일을 한 줄로 하는 거죠.

### nn.Linear 속의 행렬 곱

6장 6.1절의 `nn.Linear`는 이 행렬 곱에 편향을 더한 것입니다. 한 가지 헷갈리는 점은 PyTorch가 가중치를 `(출력 수, 입력 수)` 모양으로 저장한다는 거예요. 그래서 계산할 때 전치(`.T`, 가로세로 뒤집기)를 합니다.

```python
import torch
from torch import nn

torch.manual_seed(0)
층 = nn.Linear(3, 2)                      # 입력 3칸 -> 출력 2칸
x = torch.randn(5, 3)                     # 샘플 5개

print("가중치 모양:", tuple(층.weight.shape), " 편향 모양:", tuple(층.bias.shape))
직접 = x @ 층.weight.T + 층.bias           # 입력 @ 가중치(전치) + 편향
print("같은가:", torch.allclose(층(x), 직접))
print("파라미터 수:", sum(p.numel() for p in 층.parameters()), "= 3 x 2 + 2")
```

```text
가중치 모양: (2, 3)  편향 모양: (2,)
같은가: True
파라미터 수: 8 = 3 x 2 + 2
```

`층(x)`와 `x @ 층.weight.T + 층.bias`가 같습니다. 파라미터 수도 모양에서 바로 나와요. 가중치가 입력 수 × 출력 수, 편향이 출력 수만큼이니 3 × 2 + 2 = 8개입니다. 6장 6.4절에서 모델의 파라미터를 셀 때, 9장에서 합성곱과 완전 연결층의 파라미터 수를 비교할 때, 14장 14.7절에서 LoRA가 큰 행렬 하나를 작은 행렬 둘의 곱으로 바꿔 파라미터를 줄일 때 모두 이 모양 계산을 씁니다.

| 행렬 곱과 모양 규칙 | 4장 4.6절 | 6장 6.1절, 12장 12.1절, 12.5절, 21장 21.5절 |
| 전치 | 4장 4.5절 | 6장 6.1절, 12장 12.1절 |

## B.3 미분과 기울기

### 기울기: 조금 움직였을 때 얼마나 변하나

산길을 걷는다고 해 봅시다. 한 걸음 앞으로 갔더니 높이가 0.3m 올라갔다면, 그 자리의 경사는 "높이 변화 ÷ 걸어간 거리"로 잴 수 있죠. 5장 5.1절에서 본 **기울기**가 바로 이것입니다. 함수에서 입력을 아주 조금 움직였을 때 출력이 얼마나 변하는지의 비율이에요. 이 비율을 구하는 것을 **미분**이라고 합니다.

```python
def f(x: float) -> float:
    return x ** 2

# 기울기 = 높이 변화 / 움직인 거리. 움직이는 거리를 점점 줄여 본다
x = 3.0
for h in [1.0, 0.1, 0.01, 0.001]:
    print(f"h={h:<6} 기울기 ≈ {(f(x + h) - f(x)) / h:.4f}")
print("x ** 2의 기울기 공식 2 * x =", 2 * x)
```

```text
h=1.0    기울기 ≈ 7.0000
h=0.1    기울기 ≈ 6.1000
h=0.01   기울기 ≈ 6.0100
h=0.001  기울기 ≈ 6.0010
x ** 2의 기울기 공식 2 * x = 6.0
```

`x ** 2`에서 x = 3일 때, 움직이는 거리 h를 1, 0.1, 0.01로 줄여 갈수록 비율이 6에 다가갑니다. 이 "아주 조금 움직였을 때의 비율"이 x = 3에서의 기울기 6이에요. 미분 공식(`x ** 2`의 기울기는 `2 * x`)은 이 값을 바로 알려 주는 지름길일 뿐입니다. 5장 5.3절에서 손으로 구한 기울기 공식을 이렇게 직접 잰 값과 비교해 검사하기도 했어요(기울기 검사).

기울기의 부호와 크기에는 각각 뜻이 있습니다.

- **부호**: 양수면 오른쪽으로 갈수록 올라가는 오르막, 음수면 내리막입니다.
- **크기**: 클수록 가파릅니다. 바닥(가장 낮은 곳)에서는 0이에요.

### 변수가 여럿일 때와 경사하강법

모델에는 숫자(파라미터)가 수천, 수백만 개 있습니다. 그럴 때는 **파라미터마다 따로** 기울기를 잽니다. "다른 것은 그대로 두고 이것 하나만 조금 움직이면 손실이 얼마나 변하나"를 파라미터마다 구하는 거예요. 이 기울기들을 모은 것이 **그래디언트(gradient)** 이고, 손실이 가장 가파르게 올라가는 방향을 가리킵니다.

```python
import torch

# 변수가 둘인 함수: 손실 = (w * 2 + b - 7) ** 2
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.5, requires_grad=True)
손실 = (w * 2 + b - 7) ** 2
손실.backward()
print("손실:", 손실.item())
print("w 방향 기울기:", w.grad.item(), " b 방향 기울기:", b.grad.item())

# 경사하강법 한 걸음: 기울기의 반대쪽으로 조금
학습률 = 0.05
with torch.no_grad():
    w -= 학습률 * w.grad
    b -= 학습률 * b.grad
print("한 걸음 뒤 손실:", ((w * 2 + b - 7) ** 2).item())
```

```text
손실: 20.25
w 방향 기울기: -18.0  b 방향 기울기: -9.0
한 걸음 뒤 손실: 5.0625
```

`w`와 `b` 둘 다 기울기가 음수이니, 둘 다 키우면 손실이 줄어든다는 뜻입니다. 그래서 **기울기의 반대 방향으로, 학습률만큼** 조금 움직였더니 손실이 20.25에서 5.0625로 줄었어요. 이 한 걸음을 반복하는 것이 5장의 **경사하강법**이고, 6장의 `optimizer.step()`이 하는 일의 기본형입니다. 학습률이 너무 크면 골짜기 건너편으로 튀어 발산하고, 너무 작으면 한참 걸려요(5장 5.10절).

### 연쇄 법칙: 기울기는 곱해서 전달된다

신경망은 계산을 여러 단계로 이어 붙인 것입니다. 그럼 처음 입력이 마지막 손실에 주는 영향은 어떻게 구할까요? 톱니바퀴를 떠올려 보세요. 첫 바퀴가 1바퀴 돌 때 둘째가 3바퀴 돌고, 둘째가 1바퀴 돌 때 셋째가 2바퀴 돈다면, 첫 바퀴 1바퀴에 셋째는 3 × 2 = 6바퀴 돕니다. **단계마다의 기울기를 곱하면** 전체 기울기가 됩니다. 이것이 5장 5.6절의 **연쇄 법칙(chain rule)** 이에요.

```python
import torch

# y = (3 * x + 1) ** 2 를 두 단계로: u = 3 * x + 1, y = u ** 2
x = torch.tensor(2.0, requires_grad=True)
u = 3 * x + 1
y = u ** 2
y.backward()

du_dx = 3                 # u는 x가 1 움직이면 3 움직인다
dy_du = 2 * u.item()      # y는 u가 1 움직이면 2 * u 움직인다
print("단계별 기울기의 곱:", dy_du * du_dx)
print("PyTorch가 구한 값 :", x.grad.item())
```

```text
단계별 기울기의 곱: 42.0
PyTorch가 구한 값 : 42.0
```

x = 2에서 u = 7이고, u는 x의 3배로 움직이고(기울기 3), y는 u의 2 × 7 = 14배로 움직입니다(기울기 14). 둘을 곱한 42가 PyTorch가 `backward()`로 구한 값과 같아요. 역전파는 이 곱셈을 마지막 단계부터 거꾸로 차례차례 해 나가는 것입니다.

곱해서 전달된다는 성질에는 함정이 있습니다. 단계가 많아지면 1보다 작은 수가 수십 번 곱해져서 기울기가 사라지거나, 1보다 큰 수가 곱해져 폭주해요. 11장 11.4절에서 0.9를 100번 곱하면 0.0000266, 1.1을 100번 곱하면 1만 3천이 되는 것을 봤죠. 8장의 가중치 초기화와 배치 정규화, 9장 9.8절의 잔차 연결, 11장의 LSTM은 모두 이 곱셈이 1 근처에 머물도록 만드는 장치입니다.

| 개념 | 처음 나오는 곳 | 다시 쓰이는 곳 |
|---|---|---|
| 기울기(미분) | 5장 5.1절 | 5장 5.3절(기울기 검사) |
| 그래디언트, 경사하강법 | 5장 5.2절, 5.3절 | 6장 6.6절, 8장 8.7절 |
| 학습률 | 5장 5.2절, 5.10절 | 6장 6.6절, 8장 8.7절, 18장 18.5절 |
| 연쇄 법칙, 역전파 | 5장 5.6절 | 8장 8.6절, 11장 11.4절 |
| 기울기 소실과 폭주 | 8장 8.6절 | 9장 9.8절, 11장 11.4절 |

## B.4 지수와 로그

### exp와 log는 서로 되돌리는 짝

**지수 함수** `exp(x)`는 약 2.718(이 수를 e라고 불러요)을 x번 곱한 값입니다. **로그** `log(x)`는 그 반대로, "e를 몇 번 곱해야 x가 되나"를 답해요. 그래서 둘은 서로를 되돌립니다. 이 책에서 그냥 `log`라고 하면 e를 밑으로 하는 자연로그이고, PyTorch의 `torch.log`, 파이썬의 `math.log`가 모두 자연로그예요.

```python
import math

print("exp(0) =", math.exp(0), " exp(1) =", round(math.exp(1), 4))
print("exp(2 + 3) == exp(2) * exp(3):", math.isclose(math.exp(5), math.exp(2) * math.exp(3)))
print("log(2 * 3) == log(2) + log(3):", math.isclose(math.log(6), math.log(2) + math.log(3)))
print("log(exp(4)) =", math.log(math.exp(4)))
for p in [1.0, 0.5, 0.1, 0.01]:
    print(f"log({p}) = {math.log(p):.3f}")
```

```text
exp(0) = 1.0  exp(1) = 2.7183
exp(2 + 3) == exp(2) * exp(3): True
log(2 * 3) == log(2) + log(3): True
log(exp(4)) = 4.0
log(1.0) = 0.000
log(0.5) = -0.693
log(0.1) = -2.303
log(0.01) = -4.605
```

딥러닝에서 쓰는 성질은 세 가지면 충분합니다.

- **exp는 언제나 양수입니다.** 입력이 -1000이어도 0보다 커요. 그래서 아무 점수나 양수로 바꿀 때 씁니다(B.5절의 소프트맥스, 15장 15.6절에서 로그분산을 표준편차로 바꿀 때).
- **log는 곱셈을 덧셈으로 바꿉니다.** `log(2 * 3)`은 `log(2) + log(3)`이에요. 작은 확률 여러 개를 곱하는 계산을 로그의 덧셈으로 바꾸면 훨씬 안전해집니다(아래).
- **1보다 작은 수의 log는 음수이고, 0에 가까울수록 급격히 작아집니다.** `log(0.5)`는 -0.693, `log(0.01)`은 -4.605예요. 이 숫자들은 6장 6.5절의 교차 엔트로피 표에 그대로 나옵니다(B.6절).

### 로그 눈금: 곱하기로 늘어나는 값 고르기

학습률을 0.0001에서 0.1 사이에서 고른다고 해 봅시다. 후보를 고르게 7개 뽑으면 어떻게 될까요?

```python
import numpy as np

# 0.0001에서 0.1 사이에서 후보 7개 고르기
print("고르게  :", np.round(np.linspace(1e-4, 1e-1, 7), 4))
print("로그 눈금:", np.round(np.logspace(-4, -1, 7), 5))
print("log10   :", np.round(np.log10(np.logspace(-4, -1, 7)), 2))
```

```text
고르게  : [0.0001 0.0168 0.0334 0.0501 0.0667 0.0834 0.1   ]
로그 눈금: [0.0001  0.00032 0.001   0.00316 0.01    0.03162 0.1    ]
log10   : [-4.  -3.5 -3.  -2.5 -2.  -1.5 -1. ]
```

고르게 뽑으면 0.0001 다음이 바로 0.0168입니다. 0.001이나 0.003 같은 작은 값은 하나도 시험하지 못해요. 학습률은 "0.001이냐 0.002냐"보다 "0.001이냐 0.01이냐"가 중요한 값이라, **같은 비율로 늘어나게** 고르는 편이 맞습니다. 이것이 **로그 눈금**이에요. 마지막 줄처럼 로그 눈금으로 고른 값에 `log10`(10을 밑으로 하는 로그)을 씌우면 -4, -3.5, -3, …으로 고르게 늘어섭니다. 8장 8.11절의 학습률 범위 테스트 그래프가 가로축을 로그 눈금으로 그렸고, 18장 18.5절의 Optuna가 `suggest_float(..., log=True)`로 학습률을 고른 것도 같은 이유예요.

### 작은 확률은 로그로 더한다

언어 모델은 문장의 확률을 토큰마다의 확률을 곱해서 구합니다. 그런데 0.01을 200번 곱하면 어떻게 될까요?

```python
import math

import torch

# 확률 0.01을 200번 곱하면? (토큰 200개짜리 문장의 확률을 생각해 보자)
p = torch.full((200,), 0.01)
print("그냥 곱하기 (float32):", torch.prod(p).item())
print("로그를 더하기        :", torch.log(p).sum().item())
print("손으로 200 * log(0.01):", 200 * math.log(0.01))
```

```text
그냥 곱하기 (float32): 0.0
로그를 더하기        : -921.0341796875
손으로 200 * log(0.01): -921.0340371976182
```

진짜 답은 10의 -400제곱인데, float32가 나타낼 수 있는 가장 작은 수보다 훨씬 작아서 0이 돼 버렸습니다. 이런 현상을 **언더플로(underflow)** 라고 해요. 로그를 씌워 더하면 -921.03이라는 멀쩡한 숫자가 나옵니다. 곱셈이 덧셈으로 바뀌었기 때문이죠. 그래서 확률을 다루는 손실 함수는 거의 언제나 **로그 확률**로 계산합니다. 6장의 `nn.CrossEntropyLoss`가 안에서 소프트맥스 대신 로그 소프트맥스를 쓰는 이유(8장 8.11절의 "소프트맥스 두 번" 버그)도 여기에 있어요.

| 개념 | 처음 나오는 곳 | 다시 쓰이는 곳 |
|---|---|---|
| 지수 함수 exp | 3장 3.3절(시그모이드) | 6장 6.2절, 15장 15.6절 |
| 로그, -log | 4장 4.4절(정답 확률의 -log) | 6장 6.5절, 8장 8.11절 |
| 로그 눈금 | 8장 8.11절 | 18장 18.5절 |

## B.5 확률과 소프트맥스

### 점수를 확률로: 소프트맥스

분류 모델의 마지막 층은 클래스마다 점수(**로짓**)를 하나씩 냅니다. 이 점수는 음수도 되고 합도 제멋대로라 확률로 읽을 수가 없어요. 확률이 되려면 두 조건을 지켜야 합니다. **모두 0 이상이고, 다 더하면 1.** 이 두 조건을 만드는 함수가 **소프트맥스(softmax)** 입니다. 하는 일은 두 단계예요. exp를 씌워 모두 양수로 만들고, 그 합으로 나눠 합을 1로 맞춥니다.

```python
import torch

점수 = torch.tensor([2.0, 1.0, 0.1])          # 로짓
지수 = torch.exp(점수)
확률 = 지수 / 지수.sum()
print("exp 씌우기:", 지수.round(decimals=4))
print("나눠서 합 1:", 확률.round(decimals=4), 확률.sum().item())
print("내장 함수  :", torch.softmax(점수, dim=0).round(decimals=4))
print("모두 +100 :", torch.softmax(점수 + 100, dim=0).round(decimals=4))
```

```text
exp 씌우기: tensor([7.3891, 2.7183, 1.1052])
나눠서 합 1: tensor([0.6590, 0.2424, 0.0986]) 0.9999999403953552
내장 함수  : tensor([0.6590, 0.2424, 0.0986])
모두 +100 : tensor([0.6590, 0.2424, 0.0986])
```

점수 2.0, 1.0, 0.1이 확률 0.659, 0.242, 0.099가 됐습니다. 이 확률 0.6590은 6장 6.5절에서 교차 엔트로피를 손으로 풀 때 나온 숫자와 같아요. 합계가 정확히 1이 아니라 0.99999994로 찍힌 것은 float32의 반올림 오차입니다(4장 4.3절).

마지막 줄을 보세요. 점수에 모두 100을 더해도 확률이 그대로입니다. 소프트맥스는 **점수의 차이만** 보거든요. 이 성질이 다음의 안전장치에 쓰입니다.

### 큰 점수와 안전한 계산

exp는 입력이 조금만 커져도 엄청나게 커집니다. float32에서는 exp(89)쯤이면 이미 나타낼 수 있는 가장 큰 수를 넘어서 `inf`(무한대)가 돼요.

```python
import torch

점수 = torch.tensor([1000.0, 999.0, 0.0])
지수 = torch.exp(점수)
print("그대로 exp:", 지수, "->", 지수 / 지수.sum())

# 가장 큰 값을 빼고 계산해도 결과는 같다 (모두에 같은 수를 빼도 소프트맥스는 그대로)
빼고 = torch.exp(점수 - 점수.max())
print("최댓값 빼기:", (빼고 / 빼고.sum()).round(decimals=4))
print("내장 함수  :", torch.softmax(점수, dim=0).round(decimals=4))
```

```text
그대로 exp: tensor([inf, inf, 1.]) -> tensor([nan, nan, 0.])
최댓값 빼기: tensor([0.7311, 0.2689, 0.0000])
내장 함수  : tensor([0.7311, 0.2689, 0.0000])
```

그대로 계산하면 `inf / inf`가 되어 `nan`(숫자가 아님)이 나옵니다. 그런데 점수에서 가장 큰 값을 빼고 계산하면 exp에 들어가는 가장 큰 수가 0이 되니 넘칠 일이 없어요. 앞에서 본 대로 모두에 같은 수를 빼도 결과는 같고요. `torch.softmax`는 안에서 이렇게 계산하기 때문에 6장 6.2절에서 본 것처럼 `[1000, 0]` 같은 점수도 문제없습니다. 직접 소프트맥스를 짤 일이 있다면(20장 20.11절에서 NumPy로 짰듯이) 최댓값 빼기를 잊지 마세요.

### 온도: 확률을 날카롭게, 또는 평평하게

14장 14.3절에서 언어 모델이 다음 토큰을 뽑을 때 쓴 **온도**는 소프트맥스에 넣기 전에 점수를 나누는 숫자입니다.

```python
import torch

로짓 = torch.tensor([2.0, 1.0, 0.1])
for 온도 in [0.5, 1.0, 2.0]:
    print(f"온도 {온도}:", [f"{p:.3f}" for p in torch.softmax(로짓 / 온도, dim=0).tolist()])
```

```text
온도 0.5: ['0.864', '0.117', '0.019']
온도 1.0: ['0.659', '0.242', '0.099']
온도 2.0: ['0.502', '0.304', '0.194']
```

온도가 1보다 작으면 점수 차이가 커져서 확률이 1등에게 쏠리고(0.864), 1보다 크면 차이가 줄어 확률이 고르게 퍼집니다(0.502, 0.304, 0.194). 12장 12.2절의 "점수를 d의 제곱근으로 나누기"도 같은 원리예요. 점수가 너무 커져서 소프트맥스가 한 칸으로 쏠리는 것을 막으려고 나눕니다.

### 시그모이드: 두 칸짜리 소프트맥스

3장 3.3절의 로지스틱 회귀와 6장의 이진 분류에서 쓴 **시그모이드(sigmoid)** 는 점수 하나를 0과 1 사이의 확률로 바꿉니다. 식은 `1 / (1 + exp(-z))`예요. 사실 시그모이드는 소프트맥스의 특별한 경우입니다.

```python
import torch

z = torch.tensor([-4.0, -1.0, 0.0, 1.0, 4.0])
print("시그모이드       :", [f"{p:.4f}" for p in torch.sigmoid(z).tolist()])
print("1 / (1 + exp(-z)):", [f"{p:.4f}" for p in (1 / (1 + torch.exp(-z))).tolist()])

# 두 칸 소프트맥스 [z, 0]의 첫 칸 = 시그모이드(z)
두칸 = torch.stack([z, torch.zeros_like(z)], dim=1)
print("두 칸 소프트맥스 :", [f"{p:.4f}" for p in torch.softmax(두칸, dim=1)[:, 0].tolist()])
```

```text
시그모이드       : ['0.0180', '0.2689', '0.5000', '0.7311', '0.9820']
1 / (1 + exp(-z)): ['0.0180', '0.2689', '0.5000', '0.7311', '0.9820']
두 칸 소프트맥스 : ['0.0180', '0.2689', '0.5000', '0.7311', '0.9820']
```

세 줄이 똑같죠? 점수 `[z, 0]`에 소프트맥스를 씌운 첫 칸이 시그모이드(z)입니다. "양성일 점수 z, 음성일 점수 0"인 두 칸짜리 분류라는 뜻이에요. 그래서 이진 분류에는 출력 하나와 시그모이드(`BCEWithLogitsLoss`)를, 클래스가 셋 이상이면 출력 여러 개와 소프트맥스(`CrossEntropyLoss`)를 씁니다. 점수가 0이면 확률 0.5, 4면 0.982, -4면 0.018이에요.

## B.6 교차 엔트로피: 정답 확률에 매기는 벌점

분류 모델이 얼마나 틀렸는지는 어떻게 숫자로 잴까요? 아이디어는 간단합니다. **정답 칸에 준 확률이 높을수록 잘한 것**이에요. 그 확률에 `-log`를 씌우면 벌점이 됩니다. 확률이 1이면 벌점 0, 확률이 0에 가까울수록 벌점이 끝없이 커지죠(B.4절의 로그 성질). 이것을 샘플마다 구해 평균 낸 것이 **교차 엔트로피(cross entropy)** 손실입니다.

```python
import math

import torch
import torch.nn.functional as F

로짓 = torch.tensor([[2.0, 1.0, 0.1],
                    [0.5, 2.5, 0.3]])     # 샘플 2개, 클래스 3개
정답 = torch.tensor([0, 2])               # 두 번째 샘플은 확률이 낮은 칸이 정답

확률 = torch.softmax(로짓, dim=1)
정답_확률 = 확률[torch.arange(2), 정답]
print("정답 칸의 확률:", [f"{p:.4f}" for p in 정답_확률.tolist()])
print("-log 평균     :", round((-torch.log(정답_확률)).mean().item(), 4))
print("F.cross_entropy:", round(F.cross_entropy(로짓, 정답).item(), 4))
print("클래스 10개를 찍을 때 손실 -log(1/10):", round(-math.log(1 / 10), 4))
```

```text
정답 칸의 확률: ['0.6590', '0.0889']
-log 평균     : 1.4185
F.cross_entropy: 1.4185
클래스 10개를 찍을 때 손실 -log(1/10): 2.3026
```

첫 샘플은 정답 칸에 0.659를 줘서 벌점이 작고, 둘째 샘플은 정답 칸에 0.089밖에 주지 않아서 벌점이 큽니다. 두 벌점의 평균 1.4185가 `F.cross_entropy`의 결과와 같아요. `F.cross_entropy`에는 확률이 아니라 **로짓을 그대로** 넣는다는 점을 기억하세요. 소프트맥스는 안에서 해 줍니다.

마지막 줄은 학습을 시작할 때 쓸모 있는 숫자입니다. 아무것도 배우지 않은 모델은 클래스 10개에 고르게 0.1씩 주니, 손실이 `-log(0.1)`, 약 2.303에서 시작해요. 6장 6.5절 Q&A와 8장 8.11절에서 첫 손실이 이 근처인지 확인하라고 한 이유입니다. 클래스가 k개면 `log(k)` 근처에서 시작해야 정상이에요.

이름에 "엔트로피"가 붙은 것은 정보 이론에서 온 말이라서인데, 이 책을 따라가는 데는 "정답 확률의 -log 평균"이라는 뜻이면 충분합니다. 15장 15.6절의 VAE에 나오는 **KL 발산**도 같은 집안의 개념으로, 두 확률 분포가 얼마나 다른지를 재는 값이에요. VAE에서는 잠재 벡터의 분포가 표준 정규분포(평균 0, 표준편차 1)에서 너무 멀어지지 않게 하는 벌점으로 쓰였습니다.

## B.7 평균·분산·표준편차와 표준화

### 흔들림을 숫자 하나로: 분산과 표준편차

두 반의 시험 평균이 똑같이 70점이라고 같은 반일까요? 한 반은 모두 70점 근처이고, 다른 반은 50점부터 90점까지 흩어져 있을 수 있습니다. 평균만으로는 이 차이가 보이지 않아요. 흩어진 정도를 재는 숫자가 **분산(variance)** 과 **표준편차(standard deviation)** 입니다.

```python
import torch

점수_a = torch.tensor([70.0, 71.0, 69.0, 70.0, 70.0])
점수_b = torch.tensor([50.0, 90.0, 60.0, 80.0, 70.0])
for 이름, x in [("A반", 점수_a), ("B반", 점수_b)]:
    평균 = x.mean()
    분산 = ((x - 평균) ** 2).mean()          # 평균에서 떨어진 거리의 제곱을 평균
    print(f"{이름} 평균 {평균.item():.1f}  분산 {분산.item():6.1f}  표준편차 {분산.sqrt().item():5.2f}")

print("torch.std 기본값  :", round(점수_b.std().item(), 2))            # n - 1로 나눔
print("correction=0     :", round(점수_b.std(correction=0).item(), 2))    # n으로 나눔
```

```text
A반 평균 70.0  분산    0.4  표준편차  0.63
B반 평균 70.0  분산  200.0  표준편차 14.14
torch.std 기본값  : 15.81
correction=0     : 14.14
```

분산은 "각 값이 평균에서 떨어진 거리"를 제곱해서 평균 낸 것입니다. 제곱하는 이유는 위로 떨어진 것과 아래로 떨어진 것이 서로 지워지지 않게 하려는 거예요. 그런데 제곱을 했으니 단위가 "점의 제곱"이 되어 버리죠. 그래서 제곱근을 씌워 원래 단위로 돌린 것이 표준편차입니다. B반은 평균에서 대략 14점쯤 흩어져 있다고 읽으면 돼요.

마지막 두 줄은 자주 헷갈리는 부분입니다. `torch.std`는 기본으로 개수(n) 대신 **n - 1로 나눠서** 15.81이 나왔어요. 갖고 있는 데이터가 전체가 아니라 일부(표본)라고 보고 조금 크게 추정하는 방식입니다. `correction=0`을 주면(n에서 1 대신 0을 빼라는 뜻) n으로 나눠서 직접 계산한 14.14와 같아집니다. NumPy의 `np.std`는 반대로 기본이 n이라 PyTorch와 결과가 다를 수 있어요. 데이터가 많으면 둘의 차이는 무시할 만큼 작아집니다.

### 표준화: 단위가 다른 특성을 같은 눈금으로

키(cm)와 몸무게(kg)를 함께 쓰는 모델을 생각해 봅시다. 키는 160~180, 몸무게는 55~80이라 숫자의 범위가 다릅니다. 1장 1.8절에서 봤듯 거리를 재는 모델은 범위가 큰 특성에 휘둘리고, 경사하강법도 눈금이 다른 특성이 섞이면 길쭉한 골짜기에서 헤매요(2장 2.6절). 그래서 **각 특성에서 평균을 빼고 표준편차로 나눕니다.** 이것이 **표준화(standardization)** 예요.

```python
import torch

키_cm = torch.tensor([160.0, 170.0, 180.0, 175.0, 165.0])
몸무게_kg = torch.tensor([55.0, 65.0, 80.0, 72.0, 60.0])
표 = torch.stack([키_cm, 몸무게_kg], dim=1)        # (사람 5, 특성 2)

평균 = 표.mean(dim=0)
표준편차 = 표.std(dim=0)
표준화 = (표 - 평균) / 표준편차                    # 브로드캐스팅 (4장 4.6절)
print(표준화.round(decimals=3))
print("열 평균:", 표준화.mean(dim=0).round(decimals=3).tolist(),
      " 열 표준편차:", 표준화.std(dim=0).round(decimals=3).tolist())
```

```text
tensor([[-1.2650, -1.1560],
        [ 0.0000, -0.1420],
        [ 1.2650,  1.3790],
        [ 0.6320,  0.5680],
        [-0.6320, -0.6490]])
열 평균: [0.0, -0.0]  열 표준편차: [1.0, 1.0]
```

표준화한 뒤에는 모든 열이 평균 0, 표준편차 1이 됩니다. 이제 값은 "평균보다 표준편차 몇 개만큼 크거나 작은가"를 뜻해요. 키 180cm는 1.265, 즉 평균보다 표준편차 1.3개쯤 큽니다. 열 평균의 `-0.0`은 아주 작은 음수가 반올림된 것이라 0과 같아요.

표준화는 이 책 여러 곳에 다른 이름으로 나옵니다.

- 2장 2.6절의 `StandardScaler`는 이 계산을 하는 scikit-learn 도구이고, 평균과 표준편차는 **학습 데이터로만** 구해야 합니다(2장 2.3절의 데이터 누수).
- 7장과 10장 10.2절의 `transforms.Normalize(평균, 표준편차)`는 사진의 채널마다 같은 계산을 합니다. 사전학습 모델을 쓸 때는 그 모델이 학습한 ImageNet의 평균과 표준편차를 써야 해요.
- 8장 8.4절의 **배치 정규화**와 12장 12.7절의 **층 정규화**는 신경망 중간에서 이 표준화를 하는 층입니다. 배치 정규화는 배치 안의 샘플끼리, 층 정규화는 샘플 하나 안의 숫자끼리 평균과 표준편차를 구한다는 점이 달라요.

### 더하면 커지고, 평균 내면 작아진다

마지막으로 본문 여러 곳에 숨어 있는 규칙 하나를 확인해 보겠습니다. 서로 상관없이 흔들리는 숫자를 여러 개 더하거나 평균 내면 흔들림이 어떻게 될까요?

```python
import torch

torch.manual_seed(0)
# 표준편차 1인 무작위 수 n개를 "더하기"와 "평균 내기"를 10000번씩 해 보고 흔들림을 잰다
for n in [4, 64, 512]:
    묶음 = torch.randn(10000, n)
    합_흔들림 = 묶음.sum(dim=1).std().item()
    평균_흔들림 = 묶음.mean(dim=1).std().item()
    print(f"n={n:3}  합의 표준편차 {합_흔들림:6.2f} (n의 제곱근 {n ** 0.5:5.2f})"
          f"  평균의 표준편차 {평균_흔들림:.4f} (1 / n의 제곱근 {1 / n ** 0.5:.4f})")
```

```text
n=  4  합의 표준편차   2.02 (n의 제곱근  2.00)  평균의 표준편차 0.5050 (1 / n의 제곱근 0.5000)
n= 64  합의 표준편차   7.96 (n의 제곱근  8.00)  평균의 표준편차 0.1244 (1 / n의 제곱근 0.1250)
n=512  합의 표준편차  22.37 (n의 제곱근 22.63)  평균의 표준편차 0.0437 (1 / n의 제곱근 0.0442)
```

표준편차 1인 수를 n개 **더하면** 흔들림이 n의 제곱근배로 커지고, n개를 **평균 내면** n의 제곱근분의 1로 작아집니다. n배가 아니라 n의 제곱근배라는 점이 핵심이에요. 이 규칙이 세 장에 나옵니다.

- **12장 12.2절**: 내적은 숫자 d개를 곱해서 **더한** 값이라, d가 커지면 점수의 표준편차가 d의 제곱근배로 커집니다. 그래서 점수를 d의 제곱근으로 나눠 흔들림을 1로 되돌렸어요.
- **8장 8.6절**: 층 하나는 입력 256개에 가중치를 곱해 더하니, 가중치의 표준편차가 1이면 출력이 크게 불어납니다(ReLU가 절반을 0으로 만들어 실제로는 층마다 10배쯤). Kaiming 초기화는 가중치의 표준편차를 입력 수의 제곱근에 맞춰 줄여서 흔들림을 유지해요.
- **18장 18.6절**: 씨앗을 바꿔 n번 돌린 결과의 **평균**은 한 번 돌린 결과보다 덜 흔들립니다. 그 흔들림, 즉 "표준편차 ÷ n의 제곱근"이 **표준오차**예요. 씨앗을 4번에서 16번으로 늘리면 표준오차가 절반이 됩니다.

### 오차를 재는 법: MAE, MSE, RMSE

평균과 제곱근은 회귀 모델의 오차를 잴 때도 씁니다. 3장 3.8절에서 본 세 지표를 작은 예로 다시 보면 이렇습니다.

```python
import torch

정답 = torch.tensor([3.0, 5.0, 2.0, 7.0])
예측 = torch.tensor([2.5, 5.0, 4.0, 8.0])
오차 = 예측 - 정답
print("오차      :", 오차.tolist())
print("MAE  (절댓값 평균)       :", 오차.abs().mean().item())
print("MSE  (제곱 평균)         :", (오차 ** 2).mean().item())
print("RMSE (MSE의 제곱근)      :", round((오차 ** 2).mean().sqrt().item(), 4))
```

```text
오차      : [-0.5, 0.0, 2.0, 1.0]
MAE  (절댓값 평균)       : 0.875
MSE  (제곱 평균)         : 1.3125
RMSE (MSE의 제곱근)      : 1.1456
```

**MAE**는 오차의 절댓값 평균(0.875), **MSE**는 오차 제곱의 평균(1.3125), **RMSE**는 MSE에 제곱근을 씌워 원래 단위로 돌린 것(1.1456)입니다. 분산과 표준편차의 관계와 똑같죠. 제곱을 하기 때문에 MSE와 RMSE는 **큰 오차 하나에 크게 반응**합니다. 위에서 오차 2.0인 샘플 하나가 MSE의 대부분을 차지해요. 6장 6.5절의 `nn.MSELoss`가 이 MSE이고, 5장 5.13절과 11장 11.10절에서는 결과를 읽기 쉽게 RMSE로 보고했습니다.

## B.8 확률 분포에서 뽑기: 정규분포와 샘플링

### 정규분포: 가운데가 두툼한 종 모양

4장 4.1절부터 거의 모든 장에서 `torch.randn`으로 무작위 숫자를 만들었습니다. 이 숫자들은 아무렇게나 나오는 게 아니라 **정규분포(normal distribution)** 를 따릅니다. 키나 시험 점수처럼 평균 근처에 많이 몰리고 양 끝으로 갈수록 드물어지는, 종 모양의 분포예요. `randn`은 그중에서도 평균 0, 표준편차 1인 **표준 정규분포**에서 뽑습니다.

```python
import torch

torch.manual_seed(0)
z = torch.randn(100000)                      # 평균 0, 표준편차 1인 정규분포에서 뽑기
print(f"평균 {z.mean().item():+.3f}  표준편차 {z.std().item():.3f}")
for k in [1, 2, 3]:
    print(f"평균에서 표준편차 {k}개 안쪽: {(z.abs() < k).float().mean().item():.1%}")

# 평균 5, 표준편차 2인 정규분포가 필요하면: 평균 + 표준편차 × z
x = 5 + 2 * z
print(f"옮기고 늘린 뒤: 평균 {x.mean().item():.3f}  표준편차 {x.std().item():.3f}")
```

```text
평균 -0.002  표준편차 1.001
평균에서 표준편차 1개 안쪽: 68.1%
평균에서 표준편차 2개 안쪽: 95.5%
평균에서 표준편차 3개 안쪽: 99.7%
옮기고 늘린 뒤: 평균 4.995  표준편차 2.002
```

10만 개를 뽑았더니 평균이 거의 0, 표준편차가 거의 1입니다. 그리고 평균에서 표준편차 1개 안쪽에 약 68%, 2개 안쪽에 약 95%, 3개 안쪽에 99.7%가 들어 있어요. 이 비율은 정규분포라면 어디서나 같아서, "표준편차 3개 밖은 거의 없다"는 감각으로 쓰기 좋습니다.

마지막 줄이 중요합니다. 평균 5, 표준편차 2인 정규분포가 필요하면 새로 만들 필요 없이 **표준 정규분포에서 뽑은 값에 2를 곱하고 5를 더하면** 됩니다. B.7절의 표준화를 거꾸로 한 계산이죠. 15장 15.6절의 VAE가 쓴 **재매개변수화**가 바로 이것입니다. "평균 + 표준편차 × 무작위 값"으로 쓰면 무작위 값은 따로 뽑아 두고 평균과 표준편차는 평범한 계산이 되니, 뽑기 과정이 끼어 있어도 기울기가 흐를 수 있어요. 15.8절의 확산 모델이 사진에 섞는 잡음도 `randn`으로 뽑은 정규분포 잡음입니다.

### 확률대로 뽑기

언어 모델이 다음 토큰을 고를 때는 두 가지 방법이 있습니다. 확률이 가장 높은 것을 고르거나(`argmax`, 탐욕), 확률대로 뽑거나(샘플링). 확률대로 뽑는다는 게 어떤 뜻인지 B.5절의 확률로 확인해 볼까요?

```python
import torch

torch.manual_seed(0)
확률 = torch.tensor([0.659, 0.242, 0.099])           # B.5절 소프트맥스 결과
뽑기 = torch.multinomial(확률, num_samples=10000, replacement=True)
횟수 = torch.bincount(뽑기, minlength=3)
print("뽑힌 횟수:", 횟수.tolist())
print("뽑힌 비율:", [f"{c / 10000:.3f}" for c in 횟수.tolist()])
print("argmax   :", 확률.argmax().item(), "(언제나 같은 답)")
```

```text
뽑힌 횟수: [6545, 2423, 1032]
뽑힌 비율: ['0.654', '0.242', '0.103']
argmax   : 0 (언제나 같은 답)
```

`torch.multinomial`로 1만 번 뽑았더니 0번이 65.4%, 1번이 24.2%, 2번이 10.3%로, 주어진 확률 0.659, 0.242, 0.099와 거의 같은 비율로 나왔습니다. 확률이 낮은 2번도 열 번에 한 번쯤은 뽑혀요. 그래서 샘플링은 실행할 때마다 다른 답을 내고, `argmax`는 언제나 같은 답을 냅니다. 11장 11.11절의 속담 짓기, 12장 12.9절의 글 만들기, 14장 14.3절의 디코딩이 모두 이 `multinomial`을 썼고, 온도(B.5절)로 확률을 날카롭게 하거나 평평하게 해서 뽑히는 정도를 조절했습니다.

| 개념 | 처음 나오는 곳 | 다시 쓰이는 곳 |
|---|---|---|
| 정규분포, `randn` | 4장 4.1절 | 8장 8.6절(초기화), 15장 15.6절, 15.8절 |
| 재매개변수화(평균 + 표준편차 × 무작위 값) | 15장 15.6절 | — |
| 확률대로 뽑기(샘플링) | 11장 11.11절 | 12장 12.9절, 14장 14.3절 |
