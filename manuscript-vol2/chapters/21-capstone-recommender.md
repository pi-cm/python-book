## 21.1 좋은 추천이란 무엇일까요?

### 별점을 맞히는 문제일까요?

추천을 처음 떠올리면 "이 사람이 이 식당에 별점 몇 점을 줄까?"를 맞히는 문제로 생각하기 쉽습니다. 3장의 회귀처럼 예측한 별점과 실제 별점의 차이(RMSE)를 줄이면 될 것 같죠. 그런데 사용자가 보는 화면을 떠올려 보세요. 앱은 별점 예측값을 보여 주지 않습니다. **목록 맨 위의 열 곳 남짓**을 보여 줄 뿐이에요. 사용자는 거기서 마음에 드는 곳을 고르거나, 없으면 앱을 닫습니다.

그러니 중요한 것은 "별점을 소수점까지 맞혔나"가 아니라 "사용자가 실제로 가서 좋아할 곳이 **목록 위쪽에** 있었나"입니다. 4.2점짜리 식당을 4.0점으로 예측해도 목록 1등에 올렸다면 성공이고, 별점을 정확히 맞혀도 그 식당이 목록 50등에 있었다면 사용자는 끝내 보지 못해요. 추천은 **순위를 맞히는 문제**입니다.

데이터도 별점만 있는 게 아닙니다. 별점이나 "좋아요"처럼 사용자가 직접 남긴 평가를 **명시적 피드백**, 방문·클릭·구매처럼 행동으로 드러난 기록을 **암묵적 피드백**이라고 해요. 별점을 남기는 사람은 드물어도 방문 기록은 모두에게 쌓이니, 실제 서비스는 대개 암묵적 피드백을 중심으로 배웁니다. 이 장에서도 방문 기록을 쓰되, 다녀와서 1~2점을 준 곳은 "좋아한다"는 신호가 아니니 빼고 **3점 이상 준 방문**만 "좋았던 방문"으로 칩니다.

정리하면 이 장의 과제는 이렇습니다. **어느 날까지의 기록을 보고, 그 뒤 기간에 사용자가 처음 가서 좋았던 식당을 상위 K개 안에 넣어라.** 이미 가 본 식당은 후보에서 뺍니다. 단골집을 다시 추천하는 건 쉽지만, 친구에게 바라는 건 "아직 안 가 본 좋은 곳"이니까요.

### Recall@K와 NDCG@K

순위를 채점하는 지표 두 가지를 쓰겠습니다.

- **Recall@K**: 정답 식당 중 상위 K개 안에 들어간 비율입니다. 3장 3.7절의 **재현율**("진짜 양성 중 찾아낸 비율")을 "상위 K개 안에서"로 좁힌 것이에요. 정답이 두 곳인데 한 곳만 목록 열 칸 안에 있으면 Recall@10은 0.5입니다.
- **NDCG@K**: Recall은 1등에 있든 10등에 있든 똑같이 셉니다. 그런데 사용자는 위에서부터 보니 1등에 있는 편이 훨씬 좋죠. NDCG(정규화 할인 누적 이득)는 맞힌 식당마다 `1 / log2(순위 + 1)`을 더합니다. 1등이면 1, 2등이면 0.63, 3등이면 0.5, 10등이면 0.29로 아래로 갈수록 덜 쳐 줘요. 이 합(DCG)을 "정답을 가장 위에 모두 놓았을 때의 합"(IDCG)으로 나누면 0~1 사이의 값이 됩니다.

이 장에서 함께 쓸 지표 도구를 `순위지표.py`로 저장하세요. 앞쪽 두 함수가 지금 설명한 지표이고, 뒤쪽의 `평가셋`, `평가셋_만들기`, `평가하기`는 여러 사용자를 한꺼번에 채점하는 도구로 21.3절에서 설명합니다.

```python
"""21장 순위 지표: 추천 목록 하나를 채점하고, 여러 사용자를 한꺼번에 평가한다."""
from dataclasses import dataclass

import numpy as np
import pandas as pd

좋은_평점 = 3                                 # 3점 이상 준 방문을 '좋았던 방문'으로 본다


def recall_at_k(추천: list[int], 정답: set[int], k: int) -> float:
    """정답 식당 중 상위 k개 안에 든 비율."""
    return len(set(추천[:k]) & 정답) / len(정답)


def ndcg_at_k(추천: list[int], 정답: set[int], k: int) -> float:
    """맞힌 식당이 위에 있을수록 높은 점수. 가장 좋은 순서일 때 1."""
    dcg = sum(1 / np.log2(순위 + 2) for 순위, 식당 in enumerate(추천[:k]) if 식당 in 정답)
    idcg = sum(1 / np.log2(순위 + 2) for 순위 in range(min(len(정답), k)))
    return dcg / idcg


@dataclass
class 평가셋:
    사용자: np.ndarray          # 평가할 사용자 번호들
    정답: list[set[int]]        # 사용자마다 '처음 가서 좋았던' 식당들
    제외: np.ndarray            # (사용자, 식당) 참이면 후보에서 뺀다


def 평가셋_만들기(이전: pd.DataFrame, 대상: pd.DataFrame, 식당: pd.DataFrame) -> 평가셋:
    """이전 기록이 있는 사용자가 대상 기간에 '처음 가서 좋았던' 식당을 맞히는 문제를 만든다."""
    가본_곳 = 이전.groupby("사용자")["식당"].apply(set)
    좋았던 = 대상[대상["평점"] >= 좋은_평점]
    사용자들, 정답들 = [], []
    for u, 식당들 in 좋았던.groupby("사용자")["식당"]:
        새_곳 = set(식당들) - 가본_곳.get(u, set())
        if u in 가본_곳.index and 새_곳:           # 이전 기록이 있고, 새로 간 곳이 있는 사람만
            사용자들.append(u)
            정답들.append(새_곳)
    마지막_날 = 대상["날짜"].max()
    제외 = np.zeros((len(사용자들), len(식당)), dtype=bool)
    제외[:, 식당["개업일"].to_numpy() > 마지막_날] = True     # 아직 문을 열지 않은 식당
    for 줄, u in enumerate(사용자들):
        제외[줄, list(가본_곳[u])] = True                     # 이미 가 본 식당
    return 평가셋(np.array(사용자들), 정답들, 제외)


def 평가하기(점수: np.ndarray, 셋: 평가셋, k: int = 10) -> dict[str, float]:
    """점수: (평가 사용자 수, 식당 수). 제외할 칸을 지우고 상위 k개로 두 지표의 평균을 낸다."""
    점수 = np.where(셋.제외, -np.inf, 점수)
    상위 = np.argsort(-점수, axis=1, kind="stable")[:, :k]
    return {f"Recall@{k}": float(np.mean([recall_at_k(list(줄), 답, k) for 줄, 답 in zip(상위, 셋.정답)])),
            f"NDCG@{k}": float(np.mean([ndcg_at_k(list(줄), 답, k) for 줄, 답 in zip(상위, 셋.정답)]))}
```

손으로 확인해 보겠습니다. 어떤 사용자가 다음 달에 처음 가서 좋았던 곳이 "성수 고기"와 "종로 분식" 두 곳이라고 해 봅시다. 같은 다섯 식당을 순서만 바꾼 목록 셋을 채점해요.

```python
from 순위지표 import ndcg_at_k, recall_at_k

이름 = {41: "성수 고기", 17: "종로 분식", 102: "강남 카페", 233: "홍대 일식", 5: "잠실 한식"}
정답 = {41, 17}                       # 이 사용자가 다음 달에 처음 가서 좋았던 두 곳

목록들 = {
    "가": [41, 102, 17, 233, 5],       # 정답이 1등, 3등
    "나": [102, 233, 5, 17, 41],       # 같은 다섯 곳, 정답이 4등, 5등
    "다": [17, 41, 102, 233, 5],       # 정답이 1등, 2등
}
for 이름표, 목록 in 목록들.items():
    print(f"목록 {이름표}: {[이름[i] for i in 목록[:3]]} ...")
    for k in (3, 5):
        print(f"   k={k}: Recall {recall_at_k(목록, 정답, k):.3f}, NDCG {ndcg_at_k(목록, 정답, k):.3f}")
```

```text
목록 가: ['성수 고기', '강남 카페', '종로 분식'] ...
   k=3: Recall 1.000, NDCG 0.920
   k=5: Recall 1.000, NDCG 0.920
목록 나: ['강남 카페', '홍대 일식', '잠실 한식'] ...
   k=3: Recall 0.000, NDCG 0.000
   k=5: Recall 1.000, NDCG 0.501
목록 다: ['종로 분식', '성수 고기', '강남 카페'] ...
   k=3: Recall 1.000, NDCG 1.000
   k=5: Recall 1.000, NDCG 1.000
```

- **목록 가**는 정답을 1등과 3등에 두었습니다. 상위 3개 안에 정답이 둘 다 있으니 Recall@3은 1입니다. NDCG는 DCG가 1/log2(2) + 1/log2(4) = 1 + 0.5 = 1.5, 가장 좋은 경우(1등, 2등)의 IDCG가 1 + 0.631 = 1.631이라서 1.5 ÷ 1.631 = 0.920이에요.
- **목록 나**는 같은 다섯 곳인데 정답을 4등과 5등에 두었습니다. 상위 3개만 보는 사용자에게는 아무것도 맞히지 못한 목록이라 Recall@3과 NDCG@3이 모두 0이에요. k를 5로 늘리면 Recall@5는 1이 되지만 NDCG@5는 0.501에 그칩니다. 둘 다 찾았지만 너무 아래에 있다는 뜻이죠.
- **목록 다**는 정답을 1등과 2등에 두어 두 지표 모두 1입니다.

목록 가와 다는 Recall로는 구분되지 않고 NDCG로만 구분됩니다. 그래서 두 지표를 함께 보고, 모델을 고를 때는 순서까지 따지는 NDCG를 주로 봐요.

## 21.2 예제용 데이터 만들기

### 왜 직접 만들까요?

실제 맛집 리뷰 데이터를 쓰면 좋겠지만 두 가지 문제가 있습니다. 첫째, **개인정보**입니다. 누가 언제 어느 식당에 갔는지는 그 사람의 동선이에요. 이름을 지워도 방문 기록 몇 개만으로 사람을 짐작할 수 있습니다. 둘째, **이용 약관과 라이선스**입니다. 플랫폼의 리뷰를 모아 책에 싣거나 나눠 주는 것은 대개 허락되지 않아요. 그래서 이 장은 **예제용으로 직접 만든 데이터**를 씁니다. 동네와 음식 이름은 친숙하게 붙였지만 식당, 사용자, 방문 기록은 모두 가짜예요.

직접 만들면 좋은 점도 있습니다. 데이터 속에 어떤 취향 구조가 들어 있는지 **정답을 알고 있어서**, 나중에 모델이 그 구조를 배웠는지 확인할 수 있어요(21.7절). 대신 진짜 데이터보다 훨씬 깔끔하니, 이 장의 숫자를 실제 서비스의 성능으로 읽으면 안 됩니다.

### 숨은 취향을 심기

데이터를 만드는 규칙은 이렇습니다.

| | 모델이 볼 수 있는 것 | 모델이 볼 수 없는 것(숨은 열) |
|---|---|---|
| 식당 400곳 | 이름, 지역(8곳), 음식 종류(8가지), 가격대(1~3), 개업일 | 매운 정도, 분위기(조용함~시끌벅적), 품질 |
| 사용자 3,000명 | 사는 동네, 가입일 | 직장 지역, 매운맛 선호, 분위기 선호, 가격 민감도, 음식 종류 선호, 활동량 |
| 방문 기록 | 누가, 언제(0~364일), 어디에, 평점 1~5 | |

사용자마다 식당마다 **끌림 점수**를 계산합니다. 좋아하는 음식 종류이면, 매운맛 선호와 식당의 매운 정도가 맞으면, 분위기 취향이 맞으면, 사는 동네나 직장 근처이면, 품질이 좋으면 점수가 오르고, 가격에 민감한 사람에게 비싼 곳은 점수가 내려가요. 방문할 때마다 그날 문을 연 식당 중에서 끌림이 큰 곳을 **확률적으로** 고릅니다. 늘 1등만 고르면 사람이 아니죠.

확률적으로 고르는 데는 **굼벨(Gumbel) 트릭**을 썼습니다. 점수마다 굼벨 분포에서 뽑은 잡음을 더한 뒤 가장 큰 것을 고르면, 점수에 소프트맥스를 씌운 확률대로 뽑은 것과 같아진다는 성질이에요. 14장에서 다음 토큰을 확률대로 뽑던 것과 같은 일을, 반복문 없이 배열 계산 한 번으로 하는 요령입니다. 평점은 고른 식당의 끌림이 클수록 높게 주되 잡음을 섞어 1~5점으로 만들었어요. 끌림이 큰 곳을 골랐어도 그날따라 별로였을 수 있으니까요.

마지막으로 두 가지 "늦게 온 손님"을 넣었습니다. 식당 40곳은 300일 이후에, 사용자 300명은 300일 이후에 처음 등장해요. 21.9절의 콜드 스타트 문제를 위해서입니다. 아래 내용을 `맛집데이터.py`로 저장하세요. `숨은_`으로 시작하는 열은 정답 확인용이고, 모델에는 절대 넣지 않습니다.

```python
"""21장 예제용 맛집 데이터: 숨은 취향을 넣어 만든 가짜 사용자·식당·방문 기록 (실제 데이터가 아니다)."""
from dataclasses import dataclass

import numpy as np
import pandas as pd

지역들 = ["강남", "홍대", "성수", "종로", "여의도", "잠실", "이태원", "신촌"]
음식들 = ["한식", "중식", "일식", "양식", "분식", "고기", "해산물", "카페"]
음식별_매운맛 = np.array([0.6, 0.7, 0.2, 0.2, 0.7, 0.4, 0.4, 0.05])
기간 = 365                                   # 1년치 기록 (0일 ~ 364일)


@dataclass
class 맛집데이터:
    식당: pd.DataFrame
    사용자: pd.DataFrame
    방문: pd.DataFrame


def 식당_만들기(rng: np.random.Generator, 개수: int, 새_식당: int) -> pd.DataFrame:
    음식 = rng.integers(0, len(음식들), 개수)
    지역 = rng.integers(0, len(지역들), 개수)
    개업일 = np.zeros(개수, dtype=int)
    개업일[-새_식당:] = rng.integers(300, 350, 새_식당)   # 마지막 몇 곳은 나중에 문을 연다
    이름 = [f"{지역들[j]} {음식들[c]} {i:03d}" for i, (j, c) in enumerate(zip(지역, 음식))]
    return pd.DataFrame({
        "식당": np.arange(개수), "이름": 이름, "지역": 지역, "음식": 음식,
        "가격대": rng.integers(1, 4, 개수), "개업일": 개업일,
        # '숨은_'으로 시작하는 열은 정답 확인용이다. 모델에는 절대 주지 않는다
        "숨은_매운맛": np.clip(음식별_매운맛[음식] + rng.normal(0, 0.25, 개수), 0, 1),
        "숨은_분위기": rng.uniform(-1, 1, 개수),             # -1 조용함 ~ +1 시끌벅적
        "숨은_품질": rng.normal(0, 1, 개수),
    })


def 사용자_만들기(rng: np.random.Generator, 개수: int, 새_사용자: int) -> pd.DataFrame:
    가입일 = np.zeros(개수, dtype=int)
    가입일[-새_사용자:] = rng.integers(300, 340, 새_사용자)   # 마지막 몇 명은 늦게 가입한다
    return pd.DataFrame({
        "사용자": np.arange(개수), "동네": rng.integers(0, len(지역들), 개수),
        "가입일": 가입일,
        "숨은_직장": rng.integers(0, len(지역들), 개수),
        "숨은_매운맛선호": rng.normal(0, 1, 개수),
        "숨은_분위기선호": rng.normal(0, 1, 개수),
        "숨은_가격민감": rng.uniform(0, 1, 개수),
        "숨은_활동량": rng.lognormal(np.log(18), 0.6, 개수),
    })


def 끌림_계산(식당: pd.DataFrame, 사용자: pd.DataFrame, 음식_선호: np.ndarray) -> np.ndarray:
    """사용자 × 식당 끌림 점수. 숨은 취향과 식당의 숨은 성질이 맞을수록 크다."""
    u, r = 사용자, 식당
    끌림 = (1.5 * 음식_선호[:, r["음식"]]
          + 1.6 * np.outer(u["숨은_매운맛선호"], r["숨은_매운맛"] - 0.4)
          + 1.2 * np.outer(u["숨은_분위기선호"], r["숨은_분위기"])
          - 1.0 * np.outer(u["숨은_가격민감"], r["가격대"] - 2)
          + 0.8 * r["숨은_품질"].to_numpy())
    끌림 += 2.2 * (u["동네"].to_numpy()[:, None] == r["지역"].to_numpy())
    끌림 += 1.6 * (u["숨은_직장"].to_numpy()[:, None] == r["지역"].to_numpy())
    return 끌림


def 데이터_만들기(씨앗: int = 0, 식당_수: int = 400, 사용자_수: int = 3000) -> 맛집데이터:
    rng = np.random.default_rng(씨앗)
    식당 = 식당_만들기(rng, 식당_수, 새_식당=40)
    사용자 = 사용자_만들기(rng, 사용자_수, 새_사용자=300)
    끌림 = 끌림_계산(식당, 사용자, rng.normal(0, 1, (사용자_수, len(음식들))))
    개업일 = 식당["개업일"].to_numpy()
    기록 = []
    for u, 가입 in enumerate(사용자["가입일"]):
        횟수 = max(3, int(사용자["숨은_활동량"][u] * (기간 - 가입) / 기간))
        날짜 = np.sort(rng.integers(가입, 기간, 횟수))
        # 날마다 그날 문을 연 식당 중에서 끌림이 큰 곳을 확률적으로 고른다 (굼벨 트릭)
        점수 = 끌림[u] + rng.gumbel(size=(횟수, 식당_수))
        점수[개업일[None, :] > 날짜[:, None]] = -np.inf
        고른_곳 = 점수.argmax(axis=1)
        기록.append(pd.DataFrame({"사용자": u, "식당": 고른_곳, "날짜": 날짜, "끌림": 끌림[u, 고른_곳]}))
    방문 = pd.concat(기록).sort_values(["날짜", "사용자"]).reset_index(drop=True)
    # 평점: 끌림이 클수록 높게, 잡음을 섞어 1~5점으로
    z = (방문["끌림"] - 방문["끌림"].mean()) / 방문["끌림"].std()
    방문["평점"] = np.clip(np.round(3.6 + 0.9 * z + rng.normal(0, 0.8, len(방문))), 1, 5).astype(int)
    방문 = 방문.drop(columns="끌림")
    return 맛집데이터(식당, 사용자, 방문)


def 시간으로_나누기(방문: pd.DataFrame, 검증_시작: int = 300,
                  시험_시작: int = 330) -> tuple[pd.DataFrame, pd.DataFrame, pd.DataFrame]:
    """날짜로 자른다(2장 2.9절): 학습 < 검증_시작 <= 검증 < 시험_시작 <= 시험."""
    학습 = 방문[방문["날짜"] < 검증_시작]
    검증 = 방문[(방문["날짜"] >= 검증_시작) & (방문["날짜"] < 시험_시작)]
    시험 = 방문[방문["날짜"] >= 시험_시작]
    return 학습, 검증, 시험
```

`끌림_계산`의 `np.outer(사용자 쪽, 식당 쪽)`은 4장 4.6절의 브로드캐스팅과 같은 계산으로, 사용자 3,000명 × 식당 400곳의 표를 한 번에 만듭니다. 만든 데이터를 살펴보겠습니다. 1권 20장에서 쓴 pandas 그대로예요.

- **표는 거의 비어 있습니다.** 사용자 × 식당 120만 칸 중 한 번이라도 간 칸은 3.48%뿐이에요. 추천은 이 빈칸 대부분을 채워 넣는 일입니다.

## 21.3 시간 순서로 나누기

### 미래를 학습에 쓰지 않기

2장 2.9절에서 시간 순서가 있는 데이터는 **섞지 않고 시점으로 자른다**고 했습니다. 추천도 마찬가지예요. 실제 서비스는 오늘까지의 기록으로 내일을 추천하니까요. 무작위로 섞어 나누면 "다음 달에 문을 연 식당"이나 "다음 달에 가입한 사용자"의 기록이 학습에 섞여, 정작 서비스에서 가장 어려운 상황을 평가에서 볼 수 없게 됩니다. 2장 2.3절의 데이터 누수 그대로예요.

`시간으로_나누기`는 0~299일을 학습, 300~329일을 검증, 330~364일을 시험으로 자릅니다. 검증 기간으로 학습을 언제 멈출지와 어떤 모델이 좋은지를 정하고, 시험 기간은 마지막 비교에만 써요.

```python
import pandas as pd

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 순위지표 import 평가셋_만들기

데이터 = 데이터_만들기(씨앗=0)
학습, 검증, 시험 = 시간으로_나누기(데이터.방문)
for 이름, 조각 in [("학습", 학습), ("검증", 검증), ("시험", 시험)]:
    print(f"{이름}: {조각['날짜'].min():3}일 ~ {조각['날짜'].max():3}일, 방문 {len(조각):6,}번")

처음_보는_사용자 = set(시험["사용자"]) - set(학습["사용자"])
처음_보는_식당 = set(시험["식당"]) - set(학습["식당"])
print(f"시험 기간 사용자 중 학습 기록이 없는 사람: {len(처음_보는_사용자)}명")
print(f"시험 기간 식당 중 학습 기록이 없는 곳: {len(처음_보는_식당)}곳")

검증셋 = 평가셋_만들기(학습, 검증, 데이터.식당)
시험셋 = 평가셋_만들기(pd.concat([학습, 검증]), 시험, 데이터.식당)
for 이름, 셋 in [("검증", 검증셋), ("시험", 시험셋)]:
    정답_수 = sum(len(답) for 답 in 셋.정답)
    print(f"{이름} 평가: 사용자 {len(셋.사용자):,}명, 맞힐 식당 평균 {정답_수 / len(셋.사용자):.2f}곳, "
          f"후보에서 빼는 칸 평균 {셋.제외.sum(axis=1).mean():.1f}곳")
```

### 여러 사용자를 한꺼번에 채점하기

여기서 21.1절 `순위지표.py`의 뒷부분이 쓰입니다. `평가셋_만들기(이전, 대상, 식당)`는 이렇게 문제를 만들어요.

1. **누구를 채점하나**: `이전` 기간에 기록이 있고, `대상` 기간에 **처음 가서 좋았던** 식당이 하나라도 있는 사용자.
2. **정답**: 그 사용자가 대상 기간에 처음 가서 3점 이상을 준 식당들.
3. **후보에서 뺄 곳(`제외`)**: 이전 기간에 이미 가 본 식당과, 대상 기간이 끝날 때까지 문을 열지 않은 식당.

`평가하기(점수, 셋)`는 모델이 낸 (사용자 수 × 식당 수) 점수표를 받아, 뺄 칸을 `-inf`로 지우고 위에서부터 k개를 골라 두 지표의 평균을 냅니다. 모델이 무엇이든 점수표만 만들어 넘기면 같은 방법으로 채점되니, 기준선과 모델을 공정하게 비교할 수 있어요.

출력 마지막 두 줄을 보면 검증에서는 1,412명, 시험에서는 1,707명을 채점하고, 한 사람이 맞혀야 할 식당은 평균 1.5곳 남짓입니다. 후보에서 빼는 곳은 검증이 평균 34.0곳, 시험이 14.1곳인데, 검증에는 330일 이후에 문을 여는 식당 20곳이 더 빠지기 때문이에요. 나머지 14곳 남짓이 사용자마다 이미 가 본 식당입니다.

> **Q. 시험할 때 검증 기간의 기록은 어떻게 쓰나요?**
> 이 장에서는 모델 비교를 공정하게 하려고 모든 모델을 **학습 기간 기록으로만** 학습합니다. 다만 시험 문제를 만들 때는 검증 기간까지를 "이전 기록"으로 봐서, 검증 기간에 이미 간 곳을 다시 정답으로 세지 않게 했어요. 비교가 끝나고 서비스에 올릴 모델은 검증 기간까지 모두 써서 다시 학습합니다(21.11절).

## 21.4 기준선부터: 인기순과 동네 인기순

모델을 만들기 전에 **간단한 방법이 몇 점을 내는지**부터 재 둡니다. 3장에서 평균만 찍는 기준선과 비교했던 것처럼요. 기준선이 없으면 모델이 0.14를 냈을 때 그게 좋은 건지 알 수가 없습니다.

- **무작위**: 아무렇게나 섞은 목록. 바닥 점수입니다.
- **인기순**: 이전 기간에 방문이 많았던 식당부터. 모든 사람에게 같은 목록이에요.
- **최근 30일 인기순**: 요즘 뜨는 곳을 반영하려고 마지막 30일만 셉니다.
- **동네 인기순**: 사용자가 사는 동네의 식당을 먼저, 그 안에서는 인기순. 가입할 때 적은 동네 하나만 쓰는 아주 단순한 개인화입니다.

```python
import numpy as np
import pandas as pd

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 순위지표 import 평가셋_만들기, 평가하기

데이터 = 데이터_만들기(씨앗=0)
학습, 검증, 시험 = 시간으로_나누기(데이터.방문)
셋들 = {"검증": 평가셋_만들기(학습, 검증, 데이터.식당),
       "시험": 평가셋_만들기(pd.concat([학습, 검증]), 시험, 데이터.식당)}
식당_지역 = 데이터.식당["지역"].to_numpy()
사용자_동네 = 데이터.사용자["동네"].to_numpy()


def 기준선_점수(이름: str, 이전: pd.DataFrame, 사용자: np.ndarray) -> np.ndarray:
    """(사용자 수, 식당 수) 점수표. 클수록 위에 추천한다."""
    인기 = np.bincount(이전["식당"], minlength=len(식당_지역)).astype(float)
    if 이름 == "무작위":
        return np.random.default_rng(0).random((len(사용자), len(식당_지역)))
    if 이름 == "최근 30일 인기순":
        최근 = 이전[이전["날짜"] >= 이전["날짜"].max() - 29]
        인기 = np.bincount(최근["식당"], minlength=len(식당_지역)).astype(float)
    점수 = np.tile(인기, (len(사용자), 1))
    if 이름 == "동네 인기순":            # 내 동네 식당을 먼저, 그 안에서는 인기순
        점수 += 1e6 * (식당_지역[None, :] == 사용자_동네[사용자][:, None])
    return 점수


print("검증 Recall@10  NDCG@10 | 시험 Recall@10  NDCG@10 | 방법")
for 이름 in ["무작위", "인기순", "최근 30일 인기순", "동네 인기순"]:
    칸 = []
    for 셋_이름, 셋 in 셋들.items():
        이전 = 학습 if 셋_이름 == "검증" else pd.concat([학습, 검증])
        결과 = 평가하기(기준선_점수(이름, 이전, 셋.사용자), 셋)
        칸.append(f"{결과['Recall@10']:14.4f} {결과['NDCG@10']:8.4f}")
    print(" | ".join(칸), "|", 이름)
```

```text
        0.0977   0.0524 |         0.0875   0.0487 | 인기순
```

이제 목표가 생겼습니다. 모델은 **동네 인기순(시험 NDCG@10 0.0946)을 넘어야** 만든 보람이 있어요. 이 숫자를 넘지 못하는 모델이라면, 복잡한 모델 대신 동네 인기순을 서비스하는 편이 낫습니다.

## 21.5 행렬 분해: 사용자와 식당을 화살표로

### 빈칸 많은 표를 작은 표 두 개로

21.2절의 사용자 × 식당 표를 다시 떠올려 보세요. 3,000줄 × 400칸 중 3.48%만 채워져 있었습니다. 이 표의 빈칸을 채우는 고전적인 방법이 **행렬 분해(matrix factorization)** 예요. 큰 표를 **작은 표 두 개의 곱**으로 나타냅니다.

- 사용자마다 숫자 32개짜리 화살표: 3,000 × 32 표
- 식당마다 숫자 32개짜리 화살표: 400 × 32 표
- 사용자 u와 식당 i의 점수 = 두 화살표의 **내적**

4장 4.6절의 행렬 곱으로 쓰면 `사용자표 @ 식당표.T`가 (3,000 × 400) 점수표 전체가 됩니다. 4장 4.11절에서 도시의 기온 패턴을 화살표로 보고 방향이 비슷한지 쟀던 것, 13장 13.7절에서 토큰마다 화살표를 하나씩 준 **임베딩**과 같은 생각이에요. 다만 이번에는 화살표의 숫자를 사람이 정하지 않고, "간 곳의 점수는 높게"를 맞추도록 학습합니다. 학습이 끝나면 매운 걸 좋아하는 사용자의 화살표와 매운 식당의 화살표가 비슷한 쪽을 가리키게 될 거라고 기대하는 거죠. 번호로 화살표를 꺼내는 표는 11장 11.11절에서 처음 만난 `nn.Embedding`이 그대로 맡습니다.

### 안 간 곳은 싫어하는 곳일까요?

학습 데이터에는 "간 곳"만 있습니다. 그런데 모델에게 "간 곳은 높게"만 가르치면, 모든 식당에 높은 점수를 주는 게으른 답이 정답이 돼요. "안 간 곳은 낮게"도 알려 줘야 합니다.

문제는 안 간 곳이 곧 싫어하는 곳은 아니라는 점입니다. 몰라서 못 갔을 수도, 아직 기회가 없었을 수도 있어요. 그래도 360곳 중 무작위로 하나를 고르면, 그곳은 대개 그 사람이 별로 끌리지 않는 곳일 겁니다. 그래서 배치마다 사용자의 "간 곳" 하나에 **무작위로 뽑은 식당 하나**를 짝지어 "이쪽은 낮게"라고 가르칩니다. 이를 **음성 샘플링(negative sampling)** 이라고 해요. 가끔은 사용자가 좋아할 곳이 음성으로 뽑히기도 하지만, 그런 잡음은 감수합니다. 음성 후보는 학습 기간에 문을 연 360곳으로 한정했어요. 아직 문을 열지 않은 식당을 "안 간 곳"으로 가르치면 안 되니까요.

### 학습 도구

모델과 학습 루프를 `추천학습.py`로 저장하세요.

```python
"""21장 추천 모델 학습 도구: 행렬 분해 모델, 음성 샘플링, BCE·BPR 손실, 학습 루프."""
import copy
from collections.abc import Callable
from dataclasses import dataclass

import pandas as pd
import torch
from torch import nn

from 순위지표 import 좋은_평점


@dataclass(frozen=True)
class 학습설정:
    손실: str = "bpr"           # "bce" 또는 "bpr"
    차원: int = 32
    에폭: int = 50
    배치_크기: int = 1024
    학습률: float = 0.005
    가중치_감쇠: float = 1e-4
    씨앗: int = 0


class 내적추천(nn.Module):
    """점수 = 사용자 벡터 · 식당 벡터. 행렬 분해와 투-타워가 함께 쓰는 틀."""

    def forward(self, 사용자: torch.Tensor, 식당: torch.Tensor) -> torch.Tensor:
        return (self.사용자_벡터(사용자) * self.식당_벡터(식당)).sum(dim=-1)

    def 모든_점수(self, 사용자: torch.Tensor) -> torch.Tensor:
        """사용자들 × 모든 식당의 점수표."""
        return self.사용자_벡터(사용자) @ self.식당_벡터(torch.arange(self.식당_수)).T


class 행렬분해(내적추천):
    def __init__(self, 사용자_수: int, 식당_수: int, 차원: int = 32) -> None:
        super().__init__()
        self.식당_수 = 식당_수
        self.사용자 = nn.Embedding(사용자_수, 차원)
        self.식당 = nn.Embedding(식당_수, 차원)
        self.편향 = nn.Embedding(식당_수, 1)            # 식당마다 '누구에게나 끌리는 정도'
        nn.init.normal_(self.사용자.weight, std=0.1)
        nn.init.normal_(self.식당.weight, std=0.1)
        nn.init.zeros_(self.편향.weight)

    def 사용자_벡터(self, 사용자: torch.Tensor) -> torch.Tensor:
        u = self.사용자(사용자)
        return torch.cat([u, torch.ones_like(u[..., :1])], dim=-1)    # 끝에 1을 붙이면

    def 식당_벡터(self, 식당: torch.Tensor) -> torch.Tensor:
        return torch.cat([self.식당(식당), self.편향(식당)], dim=-1)   # 내적에 편향이 더해진다


def 좋았던_쌍(방문: pd.DataFrame) -> torch.Tensor:
    """좋았던 방문을 (사용자, 식당) 짝으로. 같은 곳을 여러 번 가도 한 번만 센다."""
    좋았던 = 방문[방문["평점"] >= 좋은_평점][["사용자", "식당"]].drop_duplicates()
    return torch.tensor(좋았던.to_numpy())


def 손실_계산(모델: 내적추천, 사용자: torch.Tensor, 양성: torch.Tensor,
              음성: torch.Tensor, 종류: str) -> torch.Tensor:
    양성_점수, 음성_점수 = 모델(사용자, 양성), 모델(사용자, 음성)
    if 종류 == "bce":     # 간 곳은 1, 무작위로 뽑은 곳은 0으로 맞히는 분류 문제
        점수 = torch.cat([양성_점수, 음성_점수])
        정답 = torch.cat([torch.ones_like(양성_점수), torch.zeros_like(음성_점수)])
        return nn.functional.binary_cross_entropy_with_logits(점수, 정답)
    # bpr: 간 곳의 점수가 무작위로 뽑은 곳보다 높기만 하면 된다
    return -nn.functional.logsigmoid(양성_점수 - 음성_점수).mean()


def 학습하기(모델: 내적추천, 쌍: torch.Tensor, 후보_식당: torch.Tensor, 설정: 학습설정,
            검증: Callable[[내적추천], float] | None = None) -> list[dict]:
    """미니배치마다 음성 식당을 무작위로 뽑아 학습한다. 검증 점수가 가장 좋던 에폭으로 되돌린다."""
    생성기 = torch.Generator().manual_seed(설정.씨앗)
    옵티마이저 = torch.optim.Adam(모델.parameters(), lr=설정.학습률, weight_decay=설정.가중치_감쇠)
    기록, 최고, 최고_상태 = [], -1.0, None
    for 에폭 in range(1, 설정.에폭 + 1):
        모델.train()
        순서 = torch.randperm(len(쌍), generator=생성기)
        합계 = 0.0
        for 시작 in range(0, len(쌍), 설정.배치_크기):
            u, 양성 = 쌍[순서[시작:시작 + 설정.배치_크기]].T
            음성 = 후보_식당[torch.randint(len(후보_식당), (len(u),), generator=생성기)]
            손실 = 손실_계산(모델, u, 양성, 음성, 설정.손실)
            옵티마이저.zero_grad()
            손실.backward()
            옵티마이저.step()
            합계 += 손실.item() * len(u)
        모델.eval()
        점수 = 검증(모델) if 검증 else float("nan")
        기록.append({"에폭": 에폭, "손실": 합계 / len(쌍), "검증": 점수})
        if 점수 > 최고:
            최고, 최고_상태 = 점수, copy.deepcopy(모델.state_dict())
    if 최고_상태 is not None:
        모델.load_state_dict(최고_상태)          # 조기 종료처럼 가장 좋던 때로 (8장 8.8절)
    return 기록
```

- **`내적추천`**: 점수를 "사용자 벡터 · 식당 벡터"로 내는 모델들의 공통 틀입니다. `forward`는 짝 하나하나의 점수를, `모든_점수`는 사용자들 × 모든 식당의 점수표를 냅니다. 21.8절의 투-타워도 이 틀을 물려받아요.
- **편향 붙이기**: `행렬분해`에는 식당마다 숫자 하나짜리 **편향**을 두었습니다. "누구에게나 끌리는 정도", 즉 인기를 담는 칸이에요. 사용자 벡터 끝에 1을, 식당 벡터 끝에 편향을 붙이면 내적 = 화살표끼리의 내적 + 편향이 됩니다. 점수가 언제나 순수한 내적 하나로 나오니, 21.11절에서 서빙할 때 계산이 단순해져요.
- **`좋았던_쌍`**: 3점 이상 받은 방문을 (사용자, 식당) 짝으로 만들고, 같은 곳을 여러 번 간 기록은 한 번만 셉니다.
- **`학습하기`**: 6장 6.7절의 학습 루프에 음성 샘플링을 더한 모양입니다. 섞는 순서와 음성 뽑기는 4장 4.1절의 나만 쓰는 `torch.Generator`로 고정했고, Adam의 `weight_decay`(8장 8.2절)로 화살표가 너무 길어지지 않게 했어요. 에폭마다 검증 점수를 재서 가장 좋던 때의 `state_dict`를 기억했다가 끝에 되돌립니다. 8장 8.8절의 조기 종료에서 멈추는 부분만 뺀 것이에요.
- **`손실_계산`**: 지금은 앞쪽의 `"bce"`만 봅니다. 간 곳은 1, 뽑은 곳은 0으로 맞히는 이진 분류이고, 6장 6.5절의 `BCEWithLogits`와 같은 손실이에요. 뒤쪽 `"bpr"`은 다음 절에서 봅니다.

이제 학습해 보겠습니다.

```python
for 줄 in [기록[0]] + 기록[9::10]:

최고 = max(기록, key=lambda 줄: 줄["검증"])
```

## 21.6 순위를 직접 배우기: BPR

BCE 손실은 모델에게 "간 곳은 확률 1, 뽑은 곳은 확률 0"이라는 **절대적인 답**을 요구합니다. 그런데 우리가 원하는 건 순위예요. "이 사람에게 A가 B보다 위"이기만 하면 점수가 3이든 30이든 상관없습니다. 시험에 비유하면 BCE는 모든 과목의 점수를 정확히 맞히라는 것이고, 우리가 원하는 건 등수만 맞히는 거예요.

**BPR(Bayesian Personalized Ranking)** 은 이 생각을 그대로 손실로 옮겼습니다. 같은 사용자의 간 곳(양성)과 뽑은 곳(음성)을 짝지어 `-log sigmoid(양성 점수 - 음성 점수)`를 줄입니다. 두 점수의 **차이**만 보니, 양성이 음성보다 충분히 위에 있으면 손실이 0에 가까워지고, 음성이 더 위에 있으면 크게 벌을 받아요. 시그모이드와 로그를 함께 계산하는 `logsigmoid`를 쓴 것은 6장 6.5절에서 `BCEWithLogits`가 넘침을 막던 것과 같은 이유입니다. `추천학습.py`의 `손실_계산`에서 마지막 줄이 BPR이에요. 같은 씨앗으로 두 손실을 비교해 보겠습니다.

```python
import numpy as np
import pandas as pd
import torch

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 순위지표 import 평가셋_만들기, 평가하기
from 추천학습 import 행렬분해, 학습설정, 학습하기, 좋았던_쌍

데이터 = 데이터_만들기(씨앗=0)
학습, 검증, 시험 = 시간으로_나누기(데이터.방문)
검증셋 = 평가셋_만들기(학습, 검증, 데이터.식당)
시험셋 = 평가셋_만들기(pd.concat([학습, 검증]), 시험, 데이터.식당)
쌍 = 좋았던_쌍(학습)
후보_식당 = torch.tensor(np.flatnonzero(데이터.식당["개업일"] < 300))


def 점수표(모델: 행렬분해, 사용자: np.ndarray) -> np.ndarray:
    with torch.no_grad():
        return 모델.모든_점수(torch.tensor(사용자)).numpy()


기록들, 시험_결과 = {}, {}
for 손실 in ["bce", "bpr"]:
    torch.manual_seed(0)
    모델 = 행렬분해(len(데이터.사용자), len(데이터.식당), 차원=32)
    기록들[손실] = 학습하기(모델, 쌍, 후보_식당, 학습설정(손실=손실),
                       lambda m: 평가하기(점수표(m, 검증셋.사용자), 검증셋)["NDCG@10"])
    시험_결과[손실] = 평가하기(점수표(모델, 시험셋.사용자), 시험셋)

print("에폭   BCE 검증 NDCG   BPR 검증 NDCG")
for 에폭 in [1, 5, 10, 20, 30, 40, 50]:
    print(f"{에폭:4} {기록들['bce'][에폭 - 1]['검증']:15.4f} {기록들['bpr'][에폭 - 1]['검증']:15.4f}")
for 손실, 결과 in 시험_결과.items():
    print(f"{손실.upper()} 시험: Recall@10 {결과['Recall@10']:.4f}, NDCG@10 {결과['NDCG@10']:.4f}")
```

같은 모델, 같은 씨앗, 같은 음성 뽑기인데 손실만 바꿨더니 BPR이 5에폭부터 앞서기 시작해 30에폭에 0.18을 넘었습니다. BCE는 50에폭이 지나도 0.13 근처예요. 시험 기간에서도 BPR의 NDCG@10이 0.1409로 BCE의 0.1082보다 30% 높고, 동네 인기순(0.0946)보다는 49% 높습니다. 반면 BCE는 시험에서 동네 인기순을 겨우 넘었어요. 손실 하나가 "기준선과 비슷한 모델"과 "확실히 나은 모델"을 갈랐습니다.

BCE가 불리한 이유는 BCE가 맞히려는 문제가 우리 목표와 다르기 때문입니다. BCE는 모든 사용자의 점수를 "0이냐 1이냐"라는 같은 눈금에 맞추느라 힘을 씁니다. 사람마다 다른 점수의 높낮이는 순위에 아무 영향이 없는데도요. BPR은 그 힘을 "누가 누구보다 위인가"에만 쓰니 순위 지표가 더 좋아집니다. 손실을 고를 때는 **평가 지표와 같은 것을 가르치는 손실**을 고르라는 교훈이에요. 이제부터는 BPR을 기본으로 씁니다. 다만 한 씨앗의 결과이니, 21.10절에서 씨앗을 바꿔 다시 확인하겠습니다.

### 비슷한 식당 찾기

학습이 끝난 식당 화살표에는 무엇이 담겼을까요? 13장 13.7절에서 KLUE BERT의 임베딩 표로 닮은 토큰을 찾은 것처럼, 코사인 유사도로 닮은 식당을 찾아보겠습니다. 이번에는 정답지(숨은 열)가 있으니 이웃들의 숨은 매운맛과 분위기도 함께 찍어요. 같은 동네 안에서 찾는 것과, 다른 동네에서 찾는 것을 나눠 봤습니다. "성수에서 즐겨 가던 곳과 비슷한 곳을 홍대에서 찾기" 같은 기능을 떠올리면 됩니다.

```python
import torch

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 추천학습 import 행렬분해, 학습설정, 학습하기, 좋았던_쌍

torch.manual_seed(0)
모델 = 행렬분해(len(데이터.사용자), len(식당), 차원=32)
학습하기(모델, 좋았던_쌍(학습), torch.tensor(np.flatnonzero(식당["개업일"] < 300)),
        학습설정(손실="bpr"))

    for i in 번호들:
        줄 = 식당.loc[i]
        print(f"  유사도 {유사도[i]:.2f} | 가격대 {줄['가격대']} | 매운맛 {줄['숨은_매운맛']:.2f} | "
              f"분위기 {줄['숨은_분위기']:+.2f} | {줄['이름']}")


for 기준 in [17, 5]:
    줄 = 식당.loc[기준]
    print(f"[기준] 가격대 {줄['가격대']} | 매운맛 {줄['숨은_매운맛']:.2f} | "
          f"분위기 {줄['숨은_분위기']:+.2f} | {줄['이름']}")
    유사도 = 단위 @ 단위[기준]
    유사도[기준] = -1                                      # 자기 자신은 빼고
    유사도[~아는_식당] = -1                                # 학습 기간에 없던 식당도 빼고
    print(" 가장 비슷한 곳")
    보여_주기(유사도.topk(3).indices.tolist(), 유사도)
    다른_동네 = 유사도.clone()
    다른_동네[torch.tensor((식당["지역"] == 줄["지역"]).to_numpy())] = -1
    print(" 다른 동네에서 가장 비슷한 곳")
    보여_주기(다른_동네.topk(3).indices.tolist(), 유사도)
```

### 임베딩은 숨은 성질을 배웠을까요?

몇 개만 골라 보면 우연일 수도 있습니다. 숫자로 확인해 보겠습니다. 식당 화살표 32개 숫자로 숨은 성질을 **직선 하나로** 맞힐 수 있는지 재는 거예요. 화살표 안에 그 성질의 "방향"이 있다면 직선으로 잘 맞힐 겁니다. 짝수 번호 식당으로 직선을 맞추고 홀수 번호 식당에서 3장 3.8절의 R²를 쟀습니다. 비교 대상은 모델이 볼 수 있는 특징(지역·음식 원-핫과 가격대)으로 맞혔을 때예요. 이렇게 학습된 표현에 단순한 직선 모델을 얹어 무엇이 담겼는지 확인하는 방법을 **선형 탐침(linear probe)** 이라고 합니다. `torch.linalg.lstsq`는 최소 제곱으로 직선을 맞춰 주는 함수예요.

```python
import numpy as np
import torch

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 추천학습 import 행렬분해, 학습설정, 학습하기, 좋았던_쌍

데이터 = 데이터_만들기(씨앗=0)
학습, _, _ = 시간으로_나누기(데이터.방문)
식당 = 데이터.식당
torch.manual_seed(0)
모델 = 행렬분해(len(데이터.사용자), len(식당), 차원=32)
학습하기(모델, 좋았던_쌍(학습), torch.tensor(np.flatnonzero(식당["개업일"] < 300)),
        학습설정(손실="bpr"))


def 설명력(X: torch.Tensor, y: torch.Tensor, 배울: np.ndarray, 볼: np.ndarray) -> float:
    """배울 식당들로 X → y 직선을 맞추고(최소 제곱), 볼 식당들에서 R²를 잰다(3장 3.8절)."""
    X = torch.cat([X, torch.ones(len(X), 1)], dim=1)       # 절편 칸
    w = torch.linalg.lstsq(X[배울], y[배울, None]).solution
    오차 = y[볼] - (X[볼] @ w)[:, 0]
    return (1 - 오차.pow(2).sum() / (y[볼] - y[볼].mean()).pow(2).sum()).item()


아는 = np.flatnonzero(식당["개업일"] < 300)
배울, 볼 = 아는[아는 % 2 == 0], 아는[아는 % 2 == 1]              # 짝수 번호로 배우고 홀수로 확인
원핫 = torch.nn.functional.one_hot
보이는_특징 = torch.cat([원핫(torch.tensor(식당["지역"].to_numpy()), 8),
                     원핫(torch.tensor(식당["음식"].to_numpy()), 8),
                     torch.tensor(식당["가격대"].to_numpy())[:, None]], dim=1).float()
임베딩 = 모델.식당.weight.detach()
편향 = 모델.편향.weight.detach()

print("보이는 특징  학습된 임베딩  임베딩+편향 | 맞힐 숨은 성질")
for 열 in ["숨은_매운맛", "숨은_분위기", "숨은_품질"]:
    y = torch.tensor(식당[열].to_numpy()).float()
    결과 = [설명력(X, y, 배울, 볼) for X in (보이는_특징, 임베딩, torch.cat([임베딩, 편향], dim=1))]
    print(f"{결과[0]:11.3f} {결과[1]:14.3f} {결과[2]:12.3f} | {열}")

방문수 = np.bincount(학습["식당"], minlength=len(식당))[아는]
print(f"편향과 log(방문 수)의 상관계수: {np.corrcoef(편향[아는, 0], np.log1p(방문수))[0, 1]:.3f}")
```

```text
      0.452          0.766        0.766 | 숨은_매운맛
     -0.124          0.847        0.846 | 숨은_분위기
     -0.133          0.068        0.796 | 숨은_품질
```

결과가 꽤 놀랍습니다.

- **분위기**: 보이는 특징으로는 R²가 -0.124, 아무것도 못 맞힙니다. 분위기는 지역·음식·가격과 상관없이 정했으니까요. 그런데 학습된 임베딩으로는 0.847입니다. 모델은 "분위기"라는 말을 들어 본 적도 없는데, 사람들의 방문 기록만 보고 화살표 안에 분위기 축을 만들어 냈어요.
- **매운맛**: 음식 종류가 매운 정도를 어느 정도 알려 주니(분식·중식은 맵다) 보이는 특징으로도 0.452가 나오지만, 임베딩은 0.766으로 그보다 훨씬 잘 맞힙니다. 같은 분식집 안에서도 더 매운 곳과 덜 매운 곳의 차이까지 배웠다는 뜻이에요.
- **품질**: 화살표만으로는 0.068로 거의 못 맞히는데, 편향을 더하면 0.796으로 뜁니다. 품질은 "누구에게나 끌리는 정도"라서 사람마다 다른 취향을 담는 화살표가 아니라 편향 칸에 들어갔어요. 마지막 줄처럼 편향은 방문 수의 로그와 0.987의 상관을 보입니다. 21.5절에서 "편향은 인기를 담는 칸"이라고 한 것이 그대로 확인됐어요.

진짜 데이터에는 이런 정답지가 없으니 이렇게 깔끔하게 확인할 수는 없습니다. 그래도 "가격대처럼 알고 있는 성질이 임베딩에 담겼나"를 선형 탐침으로 재 보는 것은 실무에서도 모델을 이해하는 좋은 방법이에요.

## 21.8 특징을 함께 쓰는 투-타워 모델

### 번호만 아는 모델의 한계

행렬 분해는 사용자와 식당을 **번호로만** 압니다. 학습 기간에 한 번도 방문 기록이 없는 식당은 화살표가 학습되지 않으니, 21.3절의 새 식당 40곳에는 아무 말도 할 수 없어요. 그런데 새 식당이라도 "성수에 있는 매운 중식집, 가격대 1"이라는 정보는 문을 여는 날부터 압니다. 이 정보를 쓸 수 없을까요?

**투-타워(two-tower) 모델**은 사용자와 식당에 탑을 하나씩 세웁니다. 사용자 탑은 사용자 번호와 동네를, 식당 탑은 식당 번호와 지역·음식·가격대를 받아 각자 화살표 하나를 만들고, 점수는 행렬 분해처럼 두 화살표의 내적이에요. 탑 안은 6장의 작은 신경망(`nn.Linear` - ReLU - `nn.Linear`)입니다. 두 탑이 서로를 보지 않고 각자 화살표를 만든다는 점이 중요한데, 그 덕분에 21.11절에서 화살표를 미리 계산해 둘 수 있어요.

### 번호 가리기

특징을 넣는다고 끝이 아닙니다. 학습할 때 번호가 늘 함께 들어가면 모델은 편한 번호에만 기대고 특징은 무시할 수 있어요. 그러면 번호 없이 특징만 들어오는 새 식당에서는 엉뚱한 답이 나옵니다. 그래서 학습 중에 30%의 확률로 번호를 **"처음 보는 번호"(표의 맨 끝 줄)로 바꿔 넣습니다.** 8장 8.3절의 드롭아웃을 번호에 적용한 셈이에요. 모델은 번호가 가려진 경우에도 맞히려고 특징에서 쓸 만한 정보를 뽑아내게 됩니다. 평가 모드(`eval()`)에서는 가리지 않아요.

```python
"""21장 투-타워 모델: 사용자 탑과 식당 탑이 각자 번호와 특징으로 벡터를 만든다."""
import pandas as pd
import torch
from torch import nn

from 맛집데이터 import 음식들, 지역들
from 추천학습 import 내적추천


class 투타워(내적추천):
    def __init__(self, 사용자: pd.DataFrame, 식당: pd.DataFrame, 차원: int = 32,
                 번호_가리기: float = 0.3) -> None:
        super().__init__()
        self.식당_수, self.번호_가리기 = len(식당), 번호_가리기
        self.모르는_사용자, self.모르는_식당 = len(사용자), len(식당)     # 맨 끝 번호 = '처음 보는'
        # 모델이 볼 수 있는 특징: 사용자는 동네, 식당은 지역·음식·가격대 (숨은_ 열은 쓰지 않는다)
        self.register_buffer("동네", torch.tensor(사용자["동네"].to_numpy()))
        self.register_buffer("식당_특징", torch.tensor(식당[["지역", "음식", "가격대"]].to_numpy()))
        self.사용자_번호 = nn.Embedding(len(사용자) + 1, 차원)
        self.식당_번호 = nn.Embedding(len(식당) + 1, 차원)
        self.동네_표 = nn.Embedding(len(지역들), 차원)
        self.지역_표 = nn.Embedding(len(지역들), 차원)
        self.음식_표 = nn.Embedding(len(음식들), 차원)
        self.가격_표 = nn.Embedding(4, 차원)
        self.사용자_탑 = nn.Sequential(nn.Linear(2 * 차원, 2 * 차원), nn.ReLU(), nn.Linear(2 * 차원, 차원))
        self.식당_탑 = nn.Sequential(nn.Linear(4 * 차원, 2 * 차원), nn.ReLU(), nn.Linear(2 * 차원, 차원))

    def 가리기(self, 번호: torch.Tensor, 모르는_번호: int) -> torch.Tensor:
        """학습 중에는 일부 번호를 '처음 보는' 번호로 바꿔, 특징만으로도 맞히게 훈련한다."""
        if not self.training:
            return 번호
        return torch.where(torch.rand(번호.shape) < self.번호_가리기, 모르는_번호, 번호)

    def 사용자_벡터(self, 사용자: torch.Tensor, 번호_쓰기: bool = True) -> torch.Tensor:
        번호 = self.가리기(사용자, self.모르는_사용자) if 번호_쓰기 else torch.full_like(사용자, self.모르는_사용자)
        return self.사용자_탑(torch.cat([self.사용자_번호(번호), self.동네_표(self.동네[사용자])], dim=-1))

    def 식당_벡터(self, 식당: torch.Tensor, 번호_쓰기: bool = True) -> torch.Tensor:
        번호 = self.가리기(식당, self.모르는_식당) if 번호_쓰기 else torch.full_like(식당, self.모르는_식당)
        지역, 음식, 가격 = self.식당_특징[식당].unbind(dim=-1)
        return self.식당_탑(torch.cat([self.식당_번호(번호), self.지역_표(지역),
                                     self.음식_표(음식), self.가격_표(가격)], dim=-1))
```

`register_buffer`는 학습하지 않는 텐서(여기서는 사용자의 동네와 식당의 특징 표)를 모델에 달아 두는 방법입니다. 파라미터는 아니지만 `state_dict`에 함께 저장되고 `.to(장치)`로 함께 옮겨져요. `번호_쓰기=False`를 주면 진짜 번호 대신 "처음 보는 번호"를 넣어, 특징만으로 화살표를 만듭니다. 21.9절의 새 식당과 새 사용자에게 쓸 길이에요.

같은 조건(BPR, 60에폭, 씨앗 0)에서 행렬 분해와 비교해 보겠습니다.

```python
import numpy as np
import pandas as pd
import torch

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 순위지표 import 평가셋_만들기, 평가하기
from 추천학습 import 내적추천, 행렬분해, 학습설정, 학습하기, 좋았던_쌍
from 투타워 import 투타워

데이터 = 데이터_만들기(씨앗=0)
학습, 검증, 시험 = 시간으로_나누기(데이터.방문)
검증셋 = 평가셋_만들기(학습, 검증, 데이터.식당)
시험셋 = 평가셋_만들기(pd.concat([학습, 검증]), 시험, 데이터.식당)
쌍 = 좋았던_쌍(학습)
후보_식당 = torch.tensor(np.flatnonzero(데이터.식당["개업일"] < 300))


def 점수표(모델: 내적추천, 사용자: np.ndarray) -> np.ndarray:
    with torch.no_grad():
        return 모델.모든_점수(torch.tensor(사용자)).numpy()


모델들 = {"행렬 분해": lambda: 행렬분해(len(데이터.사용자), len(데이터.식당)),
        "투-타워": lambda: 투타워(데이터.사용자, 데이터.식당)}
for 이름, 만들기 in 모델들.items():
    torch.manual_seed(0)
    모델 = 만들기()
    기록 = 학습하기(모델, 쌍, 후보_식당, 학습설정(손실="bpr", 에폭=60),
                 lambda m: 평가하기(점수표(m, 검증셋.사용자), 검증셋)["NDCG@10"])
    최고 = max(기록, key=lambda 줄: 줄["검증"])
    결과 = 평가하기(점수표(모델, 시험셋.사용자), 시험셋)
    print(f"{이름}: 파라미터 {sum(p.numel() for p in 모델.parameters()):,}개, "
          f"검증 곡선 {[round(기록[i]['검증'], 3) for i in (0, 9, 19, 39, 59)]}")
    print(f"   가장 좋던 에폭 {최고['에폭']} → 시험 Recall@10 {결과['Recall@10']:.4f}, "
          f"NDCG@10 {결과['NDCG@10']:.4f}")
```


투-타워는 탑 안의 신경망만큼 파라미터가 조금 더 많습니다(126,336개). 검증 곡선을 보면 1에폭부터 0.077로 행렬 분해(0.042)보다 높게 출발해요. 첫 에폭부터 "같은 동네, 같은 음식"이라는 특징을 쓸 수 있으니까요. 그런데 끝은 행렬 분해가 조금 앞섭니다. 시험 NDCG@10은 행렬 분해 0.1451, 투-타워 0.1392이고(행렬 분해가 21.6절의 0.1409와 다른 것은 이번에 60에폭으로 늘려 학습했기 때문이에요), Recall@10은 거꾸로 투-타워가 조금 높아요. 이미 기록이 충분한 사용자와 식당에게는 특징이 번호 이상의 정보를 주지 못한 셈입니다. 이 차이가 진짜인지는 21.10절에서 씨앗을 바꿔 보겠습니다. 투-타워가 진가를 보이는 곳은 다음 절이에요.

## 21.9 콜드 스타트: 처음 보는 식당과 사용자

기록이 없어서 추천을 시작하지 못하는 문제를 **콜드 스타트(cold start)** 라고 합니다. 차가운 엔진에 시동이 잘 안 걸리는 데서 온 말이에요. 두 가지가 있습니다.

### 새 식당

학습 기간 뒤에 문을 연 식당 40곳만 놓고 문제를 만들었습니다. 학습 기록이 있는 사용자가 시험 기간에 새 식당에 처음 가서 좋았다면, 새 식당 40곳 중 그곳을 상위 5개 안에 넣는지 채점해요. 비교하는 방법은 다섯 가지입니다. 행렬 분해에는 흔히 쓰는 응급 처치도 하나 붙였어요. 새 식당의 화살표를 **같은 지역·같은 음식 식당들의 화살표 평균**으로 채우는 방법입니다.

```python
import numpy as np
import pandas as pd
import torch

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 순위지표 import 좋은_평점, ndcg_at_k, recall_at_k
from 추천학습 import 행렬분해, 학습설정, 학습하기, 좋았던_쌍
from 투타워 import 투타워

데이터 = 데이터_만들기(씨앗=0)
식당, 사용자 = 데이터.식당, 데이터.사용자
학습, 검증, 시험 = 시간으로_나누기(데이터.방문)
쌍, 후보_식당 = 좋았던_쌍(학습), torch.tensor(np.flatnonzero(식당["개업일"] < 300))
새_식당 = np.flatnonzero(식당["개업일"] >= 300)              # 학습 기간 뒤에 문을 연 40곳

# 문제: 학습 기록이 있는 사용자가 시험 기간에 '새 식당'에 처음 가서 좋았다. 새 식당 40곳 중에서 맞히기
가본_곳 = pd.concat([학습, 검증]).groupby("사용자")["식당"].apply(set)
좋았던 = 시험[(시험["평점"] >= 좋은_평점) & 시험["식당"].isin(새_식당)]
문제들 = [(u, set(g) - 가본_곳[u]) for u, g in 좋았던.groupby("사용자")["식당"]
        if u in set(학습["사용자"]) and set(g) - 가본_곳[u]]
print(f"평가할 사용자 {len(문제들)}명, 후보는 새 식당 {len(새_식당)}곳")


def 채점(점수_함수, k: int = 5) -> str:
```

## 21.10 실험 기록과 여러 씨앗

지금까지의 비교는 모두 씨앗 하나짜리였습니다. 18장 18.6절에서 본 것처럼 씨앗 하나의 차이로는 결론을 내리면 안 되죠. 서비스에 올릴 모델을 고르기 전에, 세 후보(행렬 분해·BCE, 행렬 분해·BPR, 투-타워·BPR)를 씨앗 세 개로 다시 돌리고 18장 방식으로 기록하겠습니다.

- 실험 설정은 `frozen=True` dataclass로(18장 18.2절), 설정의 지문은 SHA-256으로 남깁니다.
- 데이터의 지문도 남깁니다(18장 18.7절). pandas의 `hash_pandas_object`가 표의 줄마다 해시를 내 주니, 그것을 다시 SHA-256으로 묶었어요.
- 결과는 한 줄에 실험 하나씩 JSON Lines 파일에 덧붙이고, 줄마다 `flush`합니다(18장 18.4절).

```python
import hashlib
import json
import statistics
from dataclasses import asdict, dataclass
from pathlib import Path

import numpy as np
import pandas as pd
import torch

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 순위지표 import 평가셋_만들기, 평가하기
from 추천학습 import 내적추천, 행렬분해, 학습설정, 학습하기, 좋았던_쌍
from 투타워 import 투타워


@dataclass(frozen=True)
class 실험:
    모델: str                   # "행렬분해" 또는 "투타워"
    손실: str                   # "bce" 또는 "bpr"
    씨앗: int
    에폭: int = 60
    데이터_씨앗: int = 0


데이터 = 데이터_만들기(씨앗=0)
데이터_지문 = hashlib.sha256(pd.util.hash_pandas_object(데이터.방문).to_numpy().tobytes()).hexdigest()
학습, 검증, 시험 = 시간으로_나누기(데이터.방문)
검증셋 = 평가셋_만들기(학습, 검증, 데이터.식당)
시험셋 = 평가셋_만들기(pd.concat([학습, 검증]), 시험, 데이터.식당)
쌍, 후보_식당 = 좋았던_쌍(학습), torch.tensor(np.flatnonzero(데이터.식당["개업일"] < 300))


def 점수표(모델: 내적추천, 사용자: np.ndarray) -> np.ndarray:
    with torch.no_grad():
        return 모델.모든_점수(torch.tensor(사용자)).numpy()


def 돌리기(설정: 실험) -> dict:
    torch.manual_seed(설정.씨앗)
    모델 = (행렬분해(len(데이터.사용자), len(데이터.식당)) if 설정.모델 == "행렬분해"
          else 투타워(데이터.사용자, 데이터.식당))
    기록 = 학습하기(모델, 쌍, 후보_식당, 학습설정(손실=설정.손실, 에폭=설정.에폭, 씨앗=설정.씨앗),
                 lambda m: 평가하기(점수표(m, 검증셋.사용자), 검증셋)["NDCG@10"])
    최고 = max(기록, key=lambda 줄: 줄["검증"])
    return {"최고_에폭": 최고["에폭"], "검증_NDCG@10": 최고["검증"],
            **{f"시험_{k}": v for k, v in 평가하기(점수표(모델, 시험셋.사용자), 시험셋).items()}}


기록_파일 = Path("실험기록") / "21장_비교.jsonl"
기록_파일.parent.mkdir(exist_ok=True)
설정들 = [실험(모델, 손실, 씨앗) for 모델, 손실 in [("행렬분해", "bce"), ("행렬분해", "bpr"), ("투타워", "bpr")]
        for 씨앗 in (0, 1, 2)]
with 기록_파일.open("w", encoding="utf-8") as f:
    for 설정 in 설정들:
        글 = json.dumps(asdict(설정), ensure_ascii=False, sort_keys=True)
        줄 = {"설정_지문": hashlib.sha256(글.encode()).hexdigest()[:10], "설정": asdict(설정),
             "데이터_지문": 데이터_지문[:16], "torch": torch.__version__, **돌리기(설정)}
        f.write(json.dumps(줄, ensure_ascii=False) + "\n")
        f.flush()                                    # 중간에 끊겨도 끝난 실험은 남는다 (18장 18.4절)

결과 = pd.DataFrame([json.loads(줄) for 줄 in 기록_파일.read_text(encoding="utf-8").splitlines()])
결과["이름"] = [f"{s['모델']}·{s['손실']}" for s in 결과["설정"]]
print("기록", len(결과), "줄, 데이터 지문", 결과["데이터_지문"][0], "\n")
print("시험 NDCG@10 (씨앗 0, 1, 2)          평균 ± 표준편차  | 실험")
for 이름, 묶음 in 결과.groupby("이름", sort=False):
    값 = 묶음["시험_NDCG@10"].tolist()
    print(" ".join(f"{v:.4f}" for v in 값), f"  {statistics.mean(값):.4f} ± {statistics.stdev(값):.4f}  | {이름}")

for 상대 in ["행렬분해·bce", "투타워·bpr"]:

          - 결과[결과["이름"] == "행렬분해·bpr"]["시험_NDCG@10"].to_numpy())
    print(f"{상대} - 행렬분해·bpr (같은 씨앗끼리): {np.round(차이, 4).tolist()}")
```

## 21.11 서빙 준비: 벡터를 미리 계산해 두기

### 요청마다 탑을 돌릴 필요가 있을까요?

투-타워의 점수는 "사용자 탑의 화살표 · 식당 탑의 화살표"입니다. 그런데 두 탑의 화살표는 **모델을 다시 학습하기 전까지 바뀌지 않아요.** 사용자 0번의 화살표는 오늘 아침에 계산하든 저녁에 계산하든 같습니다. 그렇다면 요청이 올 때마다 탑을 돌릴 이유가 없죠. 학습이 끝나면 모든 사용자와 식당의 화살표를 **한 번만 계산해 표로 저장**하고, 서버는 그 표에서 꺼내 내적만 하면 됩니다. 두 탑이 서로를 보지 않게 만든 이유가 여기 있어요(21.8절).

세 가지 방법으로 요청 하나에 걸리는 시간을 재 보겠습니다. 20장 20.9절처럼 준비 운동 뒤에 여러 번 재서 중앙값을 썼어요.

```python
import statistics
import time

import numpy as np
import torch

from 맛집데이터 import 데이터_만들기, 시간으로_나누기
from 추천학습 import 학습설정, 학습하기, 좋았던_쌍
from 투타워 import 투타워

데이터 = 데이터_만들기(씨앗=0)
학습, _, _ = 시간으로_나누기(데이터.방문)
torch.manual_seed(0)
타워 = 투타워(데이터.사용자, 데이터.식당)
학습하기(타워, 좋았던_쌍(학습), torch.tensor(np.flatnonzero(데이터.식당["개업일"] < 300)),
        학습설정(에폭=3))                          # 시간만 잴 것이라 짧게
타워.eval()
전체_식당 = torch.arange(len(데이터.식당))


def 모델로_바로(u: int) -> list[int]:
    """요청마다 두 탑을 모두 돌린다."""
    with torch.no_grad():
        점수 = 타워.사용자_벡터(torch.tensor([u])) @ 타워.식당_벡터(전체_식당).T
    return 점수[0].topk(10).indices.tolist()


with torch.no_grad():
    식당_행렬 = 타워.식당_벡터(전체_식당)                       # (400, 32): 한 번만
    사용자_행렬 = 타워.사용자_벡터(torch.arange(len(데이터.사용자)))  # (3000, 32): 한 번만


def 식당만_미리(u: int) -> list[int]:
    with torch.no_grad():
        점수 = 타워.사용자_벡터(torch.tensor([u])) @ 식당_행렬.T
    return 점수[0].topk(10).indices.tolist()


식당_np, 사용자_np = 식당_행렬.numpy(), 사용자_행렬.numpy()


def 모두_미리_numpy(u: int) -> list[int]:
    점수 = 식당_np @ 사용자_np[u]                              # (400,): 곱셈 한 번
    상위 = np.argpartition(-점수, 10)[:10]                     # 상위 10개만 골라 놓고
    return 상위[np.argsort(-점수[상위])].tolist()              # 그 10개만 정렬


print("세 방법의 답이 같은가:", all(모델로_바로(u) == 식당만_미리(u) == 모두_미리_numpy(u)
                                  for u in range(100)))
for 이름, 함수 in [("요청마다 두 탑 모두", 모델로_바로), ("식당 벡터만 미리", 식당만_미리),
                  ("모두 미리 + NumPy", 모두_미리_numpy)]:
    for u in range(50):
        함수(u)                                                # 준비 운동
    시간 = []
    for u in range(2000):
        시작 = time.perf_counter()
        함수(u % 3000)
        시간.append((time.perf_counter() - 시작) * 1e6)
    print(f"요청 하나에 {statistics.median(시간):7.1f}µs (중앙값) | {이름}")
print(f"미리 계산한 벡터: 사용자 {사용자_np.nbytes / 1024:.0f}KB, 식당 {식당_np.nbytes / 1024:.0f}KB")
```

이 책의 실행 환경(Apple M4 Max, CPU)에서 잰 값입니다. 세 방법의 상위 10개는 모두 같은데, 요청마다 두 탑을 돌리면 72µs, 식당 화살표만 미리 계산해 두면 26µs, 모두 미리 계산해 NumPy로 내적만 하면 8µs입니다. 아홉 배 가까이 빨라졌어요. 실행할 때마다 앞자리 숫자는 조금씩 달라지지만 순서는 늘 같습니다. 상위 10개를 고를 때는 400개를 모두 정렬하지 않고 `np.argpartition`으로 상위 10개만 골라낸 뒤 그 10개만 정렬했습니다. 식당이 수만 곳으로 늘면 이 차이가 커져요.

속도보다 더 큰 이득은 **서버에 PyTorch가 필요 없어진다**는 점입니다. 저장한 표는 사용자 375KB, 식당 50KB짜리 NumPy 배열이고, 내적은 NumPy만으로 충분해요. 20장 20.8절에서 ONNX Runtime으로 torch를 빼서 이미지가 작아진 것처럼, 이번에는 아예 NumPy만으로 서빙합니다.

> **Q. 식당이 수백만 곳이면 어떻게 하나요?**
> 요청마다 수백만 번 내적하고 정렬하면 느려집니다. 그때는 **근사 최근접 이웃 검색(approximate nearest neighbor, ANN)** 을 씁니다. 화살표들을 미리 비슷한 것끼리 묶어 색인을 만들어 두고, 요청이 오면 가까운 묶음만 뒤지는 방법이에요. 정확한 상위 10개 대신 "거의 정확한" 상위 10개를 훨씬 빨리 찾습니다. 이 일을 전문으로 하는 라이브러리와 벡터 데이터베이스가 따로 있어요. 4권 「에이전트 엔지니어링 편」에서 문서를 벡터로 바꿔 찾는 RAG를 만들 때 같은 문제를 다시 만납니다.

### 서비스에 넘길 파일 만들기

이제 서비스에 넘길 파일을 만듭니다. 두 가지를 정했어요.

- **다시 학습하기**: 지금까지는 공정한 비교를 위해 학습 기간(0~299일)만 썼지만, 서비스에 올릴 모델은 서비스를 여는 날(330일) 전의 기록을 **모두** 써서 다시 학습합니다. 최근 기록일수록 소중하니까요. 검증 기간까지 써 버렸으니 검증 점수로 멈출 때를 정할 수 없어서, 21.8절에서 투-타워의 검증 점수가 가장 좋았던 55에폭으로 정해 두고 돌렸습니다.
- **두 파일로 나누기**: 숫자 표는 `vectors.npz`(NumPy의 배열 묶음 형식)에, 식당 이름·지역·방문 수와 사용자의 동네·가 본 곳 같은 정보는 `catalog.json`에 담습니다. 서비스는 이 두 파일만 있으면 돌아가요. JSON의 키는 20장처럼 다른 프로그램도 읽기 쉽게 영어로 붙였습니다.

```python
from typing import Protocol

import numpy as np

추천목록 = list[tuple[int, float]]                    # (식당 번호, 점수)를 점수 높은 순으로


class 추천기(Protocol):
    지역들: list[str]
    식당: list[dict]

    def 사용자_수(self) -> int: ...
    def 추천(self, 사용자: int, k: int, 지역: str | None = None) -> tuple[str, 추천목록]: ...
    def 새_사용자_추천(self, 동네: str, 가본_곳: list[int], k: int, 지역: str | None = None) -> 추천목록: ...
    def 비슷한_식당(self, 식당: int, k: int) -> 추천목록: ...


class 벡터추천기:
    def __init__(self, 폴더: Path) -> None:
        벡터 = np.load(폴더 / "vectors.npz")
        self.사용자_벡터, self.식당_벡터 = 벡터["user_vectors"], 벡터["restaurant_vectors"]
        self.아는_사용자 = 벡터["known_users"]
        목록 = json.loads((폴더 / "catalog.json").read_text(encoding="utf-8"))
        self.지역들, self.식당, self.사용자 = 목록["areas"], 목록["restaurants"], 목록["users"]
        self.영업중 = np.array([r["open"] for r in self.식당])
        self.식당_지역 = np.array([self.지역들.index(r["area"]) for r in self.식당])
        self.인기 = np.log1p([r["visits"] for r in self.식당])
        단위 = self.식당_벡터 / np.linalg.norm(self.식당_벡터, axis=1, keepdims=True)
        self.비슷함 = 단위 @ 단위.T                       # 식당 × 식당 코사인 유사도, 미리 한 번

    def 사용자_수(self) -> int:
        return len(self.사용자)

    def _상위(self, 점수: np.ndarray, 뺄_곳: list[int], k: int, 지역: str | None) -> 추천목록:
        점수 = np.where(self.영업중, 점수, -np.inf)       # 문을 닫았거나 아직 안 연 곳은 빼고
        점수[뺄_곳] = -np.inf                              # 이미 가 본 곳(또는 자기 자신)도 빼고
        if 지역 is not None:
            점수[self.식당_지역 != self.지역들.index(지역)] = -np.inf
        상위 = np.argsort(-점수, kind="stable")[:k]
        return [(int(i), round(float(점수[i]), 4)) for i in 상위 if np.isfinite(점수[i])]

    def 추천(self, 사용자: int, k: int, 지역: str | None = None) -> tuple[str, 추천목록]:
        정보 = self.사용자[사용자]
        if not self.아는_사용자[사용자]:                  # 학습 기록이 없으면 새 사용자처럼
            return "new_user", self.새_사용자_추천(정보["home"], 정보["visited"], k, 지역)
        점수 = self.식당_벡터 @ self.사용자_벡터[사용자]
        return "personal", self._상위(점수, 정보["visited"], k, 지역)

    def 새_사용자_추천(self, 동네: str, 가본_곳: list[int], k: int, 지역: str | None = None) -> 추천목록:
        점수 = self.인기 + 3.0 * (self.식당_지역 == self.지역들.index(동네))     # 동네 인기순
        if 가본_곳:                                                          # + 다녀온 곳과 비슷한 곳
            점수 = 점수 + 2.0 * self.비슷함[가본_곳].mean(axis=0)
        return self._상위(점수, 가본_곳, k, 지역)

    def 비슷한_식당(self, 식당: int, k: int) -> 추천목록:
        return self._상위(self.비슷함[식당], [식당], k, None)
```

- **`추천기(Protocol)`**: 20장 20.11절의 `예측기`처럼 경로 함수가 믿을 약속입니다. 테스트에서는 이 약속을 지키는 가짜를 끼워요.
- **`__init__`**: 서버가 켜질 때 두 파일을 읽고, 식당끼리의 코사인 유사도 표(400 × 400)도 **미리 한 번** 계산해 둡니다. 비슷한 식당 요청에는 표에서 한 줄을 꺼내기만 하면 돼요.
- **`_상위`**: 모든 추천이 거치는 마지막 관문입니다. 영업하지 않는 곳, 이미 가 본 곳을 지우고, 지역이 주어지면 그 지역만 남긴 뒤 상위 k개를 고릅니다.
- **`추천`**: 화살표가 있는 사용자는 내적으로(`personal`), 없는 사용자는 21.9절에서 가장 좋았던 "동네 인기순 + 다녀온 곳과 비슷한 곳"으로(`new_user`) 추천합니다. 어떤 방법을 썼는지 이름을 함께 돌려줘서, 응답만 보고도 알 수 있게 했어요.

### 경로 함수

```python
"""맛집 추천 서비스: 미리 계산한 사용자·식당 벡터로 추천한다."""
import hashlib
import logging
import os
import time
from contextlib import asynccontextmanager
from pathlib import Path
from typing import Annotated, Literal

from fastapi import Depends, FastAPI, HTTPException, Query, Request
from pydantic import BaseModel, Field

from app.recommender import 벡터추천기, 추천기, 추천목록

앱_버전 = "1.0.0"
Area = Literal["강남", "홍대", "성수", "종로", "여의도", "잠실", "이태원", "신촌"]   # catalog.json과 같아야 한다
로그 = logging.getLogger("uvicorn.error")


class Restaurant(BaseModel):
    id: int
    name: str
    area: str
    cuisine: str
    price: int
    score: float


class Recommendations(BaseModel):
    strategy: str                         # personal, new_user, similar
    items: list[Restaurant]


class NewUserRequest(BaseModel):
    home: Area
    visited: list[int] = Field(default=[], max_length=50)
    k: int = Field(default=10, ge=1, le=50)


@asynccontextmanager
async def lifespan(app: FastAPI):
    폴더 = Path(os.environ.get("ARTIFACT_DIR", "artifacts"))
    app.state.추천기 = 벡터추천기(폴더)
    app.state.지문 = hashlib.sha256((폴더 / "vectors.npz").read_bytes()).hexdigest()[:12]
    로그.info("벡터 준비 완료: 사용자 %d명, 식당 %d곳, sha256=%s",
             app.state.추천기.사용자_수(), len(app.state.추천기.식당), app.state.지문)
    yield


app = FastAPI(title="맛집 추천 API", version=앱_버전, lifespan=lifespan)


@app.middleware("http")
async def 처리_시간_기록(request: Request, call_next):
    시작 = time.perf_counter()
    응답 = await call_next(request)
    응답.headers["X-Process-Time-ms"] = f"{(time.perf_counter() - 시작) * 1000:.2f}"
    return 응답


def 추천기_얻기(request: Request) -> 추천기:
    """경로 함수가 쓸 추천기. 테스트에서는 가짜로 바꿔 끼운다."""
    return request.app.state.추천기


def 응답_만들기(추천기_: 추천기, 전략: str, 목록: 추천목록) -> Recommendations:
    식당들 = [Restaurant(**{키: 추천기_.식당[i][키] for 키 in ("id", "name", "area", "cuisine", "price")},
                         score=점수) for i, 점수 in 목록]
    return Recommendations(strategy=전략, items=식당들)


def 식당_번호_확인(추천기_: 추천기, 번호들: list[int]) -> None:
    for 번호 in 번호들:
        if not 0 <= 번호 < len(추천기_.식당):
            raise HTTPException(status_code=404, detail=f"식당 {번호}을(를) 찾을 수 없습니다")


@app.get("/health")
def 살아있나() -> dict:
    return {"status": "ok"}


@app.get("/version")
def 버전(request: Request) -> dict:
    return {"app": 앱_버전, "vectors_sha256": request.app.state.지문}


@app.get("/users/{user_id}/recommendations")
def 사용자_추천(user_id: int, k: Annotated[int, Query(ge=1, le=50)] = 10, area: Area | None = None,
              추천기_: 추천기 = Depends(추천기_얻기)) -> Recommendations:
    if not 0 <= user_id < 추천기_.사용자_수():
        raise HTTPException(status_code=404, detail=f"사용자 {user_id}을(를) 찾을 수 없습니다")
    전략, 목록 = 추천기_.추천(user_id, k, area)
    return 응답_만들기(추천기_, 전략, 목록)


@app.post("/recommendations/new-user")
def 새_사용자_추천(요청: NewUserRequest, 추천기_: 추천기 = Depends(추천기_얻기)) -> Recommendations:
    식당_번호_확인(추천기_, 요청.visited)
    return 응답_만들기(추천기_, "new_user", 추천기_.새_사용자_추천(요청.home, 요청.visited, 요청.k))


@app.get("/restaurants/{restaurant_id}/similar")
def 비슷한_식당(restaurant_id: int, k: Annotated[int, Query(ge=1, le=50)] = 5,
              추천기_: 추천기 = Depends(추천기_얻기)) -> Recommendations:
    식당_번호_확인(추천기_, [restaurant_id])
    return 응답_만들기(추천기_, "similar", 추천기_.비슷한_식당(restaurant_id, k))
```

20장의 서비스와 같은 뼈대(lifespan, `Depends`로 꺼내는 추천기, 처리 시간 미들웨어, `/health`·`/version`) 위에 경로 세 개를 얹었습니다.

| 경로 | 하는 일 |
|---|---|
| `GET /users/{user_id}/recommendations?k=10&area=성수` | 사용자에게 아직 안 가 본 식당 k곳. `area`를 주면 그 지역에서만 |
| `POST /recommendations/new-user` | 앱에 처음 온 사람: 동네와 다녀온 곳(있으면)으로 추천 |
| `GET /restaurants/{restaurant_id}/similar?k=5` | 비슷한 식당 k곳 |

- **`Area = Literal[...]`**: 지역은 여덟 곳 중 하나여야 합니다. `Literal`로 적어 두면 Pydantic이 다른 값을 422로 돌려보내고, 자동 문서에도 고를 수 있는 값이 표시돼요. 다만 지역 목록이 `catalog.json`에도 있으니 둘이 어긋날 위험이 생깁니다. 바로 다음 테스트가 그 위험을 막아요.
- **`Query(ge=1, le=50)`**: 1권 19.3절에서 `/restaurants?지역=서울`로 맛집을 거르던 쿼리 매개변수에 범위 검사를 붙였습니다. 누군가 `k=1000000`을 보내 응답을 키우는 일을 막아요.
- **404**: 없는 사용자 번호나 식당 번호는 `HTTPException(404)`로 답합니다. 검사하지 않으면 NumPy 배열 인덱싱에서 `IndexError`가 나 500이 되거나, 음수 번호는 오류 없이 **맨 뒤 사용자**의 추천이 나가요(4장 4.4절의 음수 인덱스). 오류가 안 나서 더 위험한 경우입니다.

- **임베딩 들여다보기**: 코사인 유사도로 비슷한 식당, 선형 탐침으로 숨은 분위기(R² 0.847)와 매운맛(0.766)이 화살표 안에 있음을 확인

### 2권을 마치며

2권을 시작할 때 1장에서 "if 문으로 스팸을 거를 수 있을까?"라고 물었습니다. 규칙을 짜는 대신 데이터로 배우는 프로그램이라는 생각에서 출발해, 1부에서 데이터를 나누고 평가하는 감각을, 2부에서 텐서와 자동 미분과 학습 루프라는 도구를, 3부에서 CNN·RNN·트랜스포머·생성 모델이라는 여러 구조를, 4부에서 실험을 관리하고 모델을 가볍게 만들어 서비스로 내놓는 일을 익혔어요. 그리고 이 장에서 그 모두를 하나로 엮었습니다.

돌아보면 2권 전체에 걸쳐 되풀이된 습관이 몇 가지 있습니다. 모델보다 **기준선을 먼저** 잰다. 데이터를 나눌 때 **미래를 엿보지 않는다**. 점수 하나보다 **여러 씨앗의 평균과 흔들림**을 본다. 결과가 기대보다 나쁘면 **감추지 않고 이유를 찾는다**. 그리고 서비스로 내놓을 때는 **약속을 테스트로 적어 둔다**. 도구와 모델은 몇 년이면 바뀌지만, 이 습관들은 오래 갑니다.

다음 3권 「로봇 편」에서는 지능이 화면 밖으로 나가 몸을 얻습니다. 파이썬과 MuJoCo 시뮬레이터를 중심으로(ROS 2는 한 파트에서 다룹니다), 로봇 팔과 몸의 좌표계와 기구학부터 시작해요. 카메라와 센서로 주변을 보는 인지에는 9장의 CNN이, 사람의 자세와 동작을 이해하는 로봇에는 3부의 모델 구조들이 다시 쓰입니다. 경로를 계획하고 제어하는 법을 익힌 뒤에는 강화 학습과 모방 학습으로 로봇이 스스로 배우게 하는데, 여기서 6장의 학습 루프와 18장의 실험 관리가 그대로 필요해요. 14장의 언어 모델이 로봇과 만나 말로 지시를 받아 움직이는 로봇 파운데이션 모델도 만나고, 마지막으로 시뮬레이션에서 배운 것을 현실의 로봇으로 옮기는 문제를 다룹니다.

4권 「에이전트 엔지니어링 편」에서는 14장에서 만난 언어 모델이 주인공이 됩니다. 모델을 직접 학습하는 대신 LLM API로 부르고, 모델이 답을 말하는 데서 그치지 않고 도구를 써서(MCP) 일을 끝내는 **에이전트**를 만들어요. 14장 실습에서 "적은 데이터의 LoRA는 말투와 형식을 가르치는 데 강하고, 새로운 사실을 넣는 데는 약하다"는 결론을 얻었죠. 그 약점을 메우는 방법이 4권의 RAG입니다. 사실을 모델에 외우게 하지 않고, 질문과 관련된 문서를 찾아 건네주는 거예요. 이때 문서를 화살표로 바꿔 가까운 것을 찾는 일은 이 장에서 식당을 화살표로 바꿔 비슷한 곳을 찾은 것과 같은 계산입니다. 4권은 여기에 기억, 여러 에이전트의 협업, 에이전트를 평가하고 안전하게 만드는 법을 더하고, 완성한 에이전트를 20장과 이 장에서 익힌 FastAPI로 배포합니다. 여기까지 따라온 여러분이라면 충분히 준비됐습니다.
