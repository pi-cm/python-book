## 들어가며: 함수가 뭔가요?

수학 시간에 함수를 배우면서 이런 식을 본 적이 있을 거예요.

```text
f(x) = 3x + 2
f(2) = 8
```

입력 `x`를 받아 정해진 계산을 하고, 그 결과를 내놓죠. 파이썬의 함수도 기본은 똑같습니다. **입력을 받아 일을 하고 결과를 돌려주는 상자**예요. 사실 우리는 앞 장들에서 이미 함수를 많이 써 왔습니다. `print()`, `input()`, `len()`처럼 이름 뒤에 괄호가 붙은 것들이 모두 함수예요.

다만 파이썬의 함수는 수학의 함수보다 할 수 있는 일이 많습니다. 아무 값도 돌려주지 않을 수도 있고, 파일을 만들거나 지우거나 고칠 수도 있고, 심지어 **다른 함수를 돌려줄** 수도 있어요. 마지막 성질이 이 장 후반부의 주인공입니다.

> **Q. 한 줄씩 쭉 써도 잘 돌아가는데, 왜 굳이 귀찮게 함수를 쓰나요?**
> 나중에 **더 귀찮아지지 않으려고** 씁니다. 회원가입, 로그인, 정보 수정 화면 세 곳에서 이메일 주소가 올바른지 검사한다고 해 봅시다. 검사 코드를 세 군데에 복사해 두었다면, "이메일에 느낌표도 허용하자"는 요청이 왔을 때 세 군데를 모두 찾아서 고쳐야 하고, 하나라도 빠뜨리면 버그가 됩니다. 검사 코드를 함수 하나로 만들어 세 곳에서 불러 쓰고 있었다면? 함수 한 곳만 고치면 끝이에요.

이 장에서는 함수를 만들고 부르는 기초를 다집니다. 정의와 호출, 매개변수와 인자, 이름이 사는 곳(스코프), 그리고 자기 자신을 부르는 재귀까지 가 보겠습니다. 함수를 값처럼 주고받는 **함수형 프로그래밍**은 다음 10장에서 이어집니다.


## 9.1 함수 정의와 호출

### 함수를 어떻게 만드나요?

함수는 `def` 키워드로 만듭니다. `def`는 정의(definition)의 줄임말이에요.

```text
def 함수이름(매개변수1, 매개변수2, ...):
    할 일
    return 돌려줄_값
```

규칙은 다섯 가지만 기억하면 됩니다.

1. `def` 다음에 함수 이름을 쓰고, 괄호 안에 매개변수를 씁니다.
2. 괄호 뒤의 **콜론(`:`)** 을 빠뜨리는 실수가 생각보다 자주 일어납니다. 그다음 줄부터는 들여쓰기한 만큼이 함수의 몸통이에요.
3. 매개변수는 여러 개여도 되고 하나도 없어도 됩니다. 없으면 빈 괄호 `()`를 씁니다.
4. `return`은 안 써도 됩니다. 그러면 함수는 자동으로 `None`을 돌려줍니다.
5. 이름만 봐도 하는 일을 알 수 있게 짓습니다. `f`보다는 `calculate_total`이 좋아요.

만든 함수는 이름 뒤에 괄호를 붙여 **부릅니다(호출)**. 위의 수학 함수를 파이썬으로 옮기고(수학 식을 그대로 옮기느라 이름을 `f`로 두었어요), `return`이 없는 함수도 하나 만들어 봅시다.

```python
# 수학의 f(x) = 3x + 2를 파이썬으로
def f(x):
    return 3 * x + 2

print(f(2))  # 8

# return이 없는 함수
def say_hello():
    print("안녕하세요!")

result = say_hello()  # 안녕하세요!
print(result)         # None
```

`say_hello()`는 화면에 인사를 찍었지만 돌려준 값은 없습니다. 그래서 `result`에는 "아무것도 없음"을 뜻하는 `None`이 들어가요. **화면에 출력하는 것(`print`)과 값을 돌려주는 것(`return`)은 다릅니다.** 출력은 사람에게 보여 주는 것이고, 반환은 프로그램의 다른 부분이 그 값을 받아 쓸 수 있게 넘겨주는 거예요.

### 매개변수와 인자

함수의 입력에는 이름이 둘 있습니다.

- **매개변수(parameter)**: 함수를 **정의할 때** 괄호 안에 쓰는 변수입니다. 위의 `x`처럼 들어올 값을 받아 둘 빈 그릇이에요.
- **인자(argument)**: 함수를 **부를 때** 실제로 넣는 값입니다. `f(2)`의 `2`예요.
- 그리고 함수가 내놓는 결과가 **반환값(return value)** 입니다.

인자를 넣는 방법은 두 가지입니다. **위치 인자(positional argument)** 는 순서로 짝을 지어요. 첫 번째 값은 첫 번째 매개변수로, 두 번째 값은 두 번째 매개변수로 들어갑니다. **키워드 인자(keyword argument)** 는 `name="김철수"`처럼 매개변수 이름을 직접 적어서 짝을 짓습니다.

> **Q. 인자가 많을 때 순서를 헷갈리면 어떡하나요?**
> 키워드 인자를 쓰면 됩니다. 매개변수가 다섯 개쯤 되면 순서를 정확히 외우기 어렵고, 순서가 꼬이면 엉뚱한 칸에 값이 들어가요. 이름표를 붙여 넘기면 순서를 외울 필요가 없고, 나중에 코드를 읽을 때도 어떤 값이 무엇인지 바로 보입니다. 몇 달 뒤 자기 코드를 다시 읽을 때 스스로에게 고마워하게 될 거예요.

```python
def make_profile(name, age, city, job, hobby):
    return f"{name}({age}) / {city} / {job} / 취미: {hobby}"

# 위치 인자: 순서가 곧 의미입니다
print(make_profile("김철수", 25, "서울", "개발자", "등산"))
print(make_profile("김철수", "서울", 25, "등산", "개발자"))  # 순서가 꼬였어요!

# 키워드 인자: 이름표를 붙이면 순서는 상관없어요
print(make_profile(hobby="등산", job="개발자", name="김철수", city="서울", age=25))
```

두 번째 줄은 `김철수(서울) / 25 / 등산 / 취미: 개발자`로 나옵니다. 오류 없이 실행되니까 더 위험하죠. 세 번째 줄은 순서를 마구 섞었는데도 첫 줄과 똑같이 나옵니다.

헷갈리기 쉬운 이름이 하나 더 있습니다. **기본값 인자(default argument)** 는 `def greet(name, greeting="안녕하세요"):`처럼 **정의할 때** 매개변수에 기본값을 정해 두는 것이고, 키워드 인자는 **부를 때** 이름을 붙여 넘기는 방법입니다. 하나는 매개변수 쪽, 하나는 인자 쪽 이야기예요. 기본값이 있는 매개변수는 기본값이 없는 매개변수보다 뒤에 와야 한다는 규칙도 기억해 두세요.

### 인자가 몇 개 들어올지 모를 때

2명에서 8명까지 함께할 수 있는 게임이 있다고 해 봅시다. 참가자 점수를 받는 함수를 만들려는데, 인자가 2개일지 8개일지 미리 알 수 없어요. 이럴 때 매개변수 앞에 별표를 붙입니다.

- `*numbers`: 위치 인자를 몇 개든 받아 **튜플 하나로 묶습니다(packing)**.
- `**info`: 키워드 인자를 몇 개든 받아 **딕셔너리 하나로 묶습니다**.

반대로 함수를 **부를 때** 리스트 앞에 `*`를 붙이면 리스트를 **풀어서(unpacking)** 하나씩 넘겨줍니다.

```python
# 정의할 때의 * : 여러 인자를 튜플 하나로 묶기(packing)
def my_sum(*numbers):
    print(f"받은 값: {numbers}")
    return sum(numbers)

print(my_sum(1, 2, 3))        # 받은 값: (1, 2, 3) → 6

# 호출할 때의 * : 리스트를 풀어서 하나씩 넘기기(unpacking)
nums = [1, 2, 3, 4, 5]
print(my_sum(*nums))          # my_sum(1, 2, 3, 4, 5)와 같아요 → 15

# ** : 키워드 인자를 딕셔너리 하나로 묶기
def show_info(**info):
    print(info)

show_info(name="김철수", age=25)  # {'name': '김철수', 'age': 25}

# 함수 밖에서도 됩니다
first, *rest = [10, 20, 30, 40]
print(first, rest)            # 10 [20, 30, 40]
```

헷갈리면 이렇게 외워 두세요. **매개변수 쪽의 `*`는 묶기, 인자 쪽의 `*`는 풀기**입니다. 마지막 줄처럼 함수 밖에서도 별표를 쓸 수 있어요. 별표가 없는 변수에 값이 하나씩 먼저 들어가고, 남은 값이 모두 별표 변수에 리스트로 묶입니다(6.4절의 튜플 언패킹을 떠올려 보세요). 사실 `sum()`은 원래 리스트 하나를 받을 수 있으니 `my_sum`은 별표를 보여 주기 위한 예제일 뿐입니다.

### return: 값을 돌려주고 바로 끝내기

`return`에는 성질이 하나 더 있습니다. **`return`을 만나는 순간 함수가 그 자리에서 끝납니다.** 그 아래 코드는 실행되지 않아요.

이 성질은 반복문 안에서 특히 쓸모가 있습니다. 5장에서 `break`는 자신을 감싼 **가장 안쪽 반복 하나**만 끝낸다고 배웠죠. 표(2차원 리스트)에 어떤 숫자가 하나라도 있는지 확인하려면, 찾자마자 바깥 반복문까지 한 번에 멈추고 싶습니다. 함수로 만들어 `return`하면 간단해요.

```python
def contains(matrix, target):
    for row in matrix:
        for value in row:
            if value == target:
                return True   # 찾자마자 두 반복문을 한꺼번에 빠져나갑니다
    return False

matrix = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
print(contains(matrix, 5))   # True
print(contains(matrix, 10))  # False
```

`5`를 찾는 경우에는 두 번째 줄의 `5`를 만나자마자 `True`를 돌려주고 끝나서, 남은 `6, 7, 8, 9`는 쳐다보지도 않습니다. 끝까지 다 봤는데도 못 찾았을 때만 마지막 줄의 `return False`에 닿아요.

### 함수에 넣은 값이 바뀔까요?

어떤 값은 함수에 넣었다 빼면 바깥 값까지 바뀌고, 어떤 값은 그대로입니다. 차이는 6장에서 배운 **가변(mutable)** 과 **불변(immutable)** 에서 옵니다. 다음 예제를 실행하기 전에 결과를 먼저 예상해 보세요.

```python
def add_one(number):
    number = number + 1        # 새 정수 객체를 만들어 이름표만 옮깁니다
    print(f"함수 안: {number}")

def add_item(items):
    items.append(4)            # 들어온 리스트 객체 자체를 고칩니다
    print(f"함수 안: {items}")

n = 10
add_one(n)                     # 함수 안: 11
print(f"함수 밖: {n}")         # 함수 밖: 10

my_list = [1, 2, 3]
add_item(my_list)              # 함수 안: [1, 2, 3, 4]
print(f"함수 밖: {my_list}")   # 함수 밖: [1, 2, 3, 4]
```

파이썬은 함수를 부를 때 값을 복사하지 않습니다. 바깥의 객체에 매개변수라는 **이름표를 하나 더 붙여** 넘겨요. 이것을 **할당에 의한 전달(passed by assignment)** 이라고 합니다.

- 정수는 불변이라 고칠 수 없습니다. `number + 1`은 새 정수 `11`을 만들고, 매개변수 `number`라는 이름표만 그쪽으로 옮겨 붙여요. 바깥의 `n`은 여전히 `10`에 붙어 있습니다.
- 리스트는 가변이라 그 자리에서 고칠 수 있습니다. `items`와 `my_list`는 **같은 리스트**에 붙은 두 이름표라서, `items.append(4)`로 고친 결과가 바깥에서도 보입니다.

그래서 함수 안에서 리스트나 딕셔너리를 고칠 때는 "바깥 데이터도 바뀐다"는 것을 알고 써야 합니다. 원본을 지키고 싶다면 `items.copy()`로 복사본을 만들어 고치거나, 새 리스트를 만들어 `return`하세요.

## 9.2 이름이 사는 곳: 네임스페이스와 스코프

### 함수 안의 함수

`if` 안에 `if`를 넣을 수 있듯이, 함수 안에도 함수를 만들 수 있습니다. 영화 「인셉션」의 꿈속의 꿈처럼요. 그런데 함수 안에서 만든 함수는 **바깥에서 보이지 않습니다**. 라디오 속에 작은 라디오가 숨어 있어도, 겉의 라디오를 열어 보기 전에는 알 수 없는 것과 같아요. 함수마다 이름이 사는 공간이 따로 나뉘어 있기 때문입니다.

### 네임스페이스가 뭐죠?

이름이 아주 흔한 사람은 붐비는 거리에서 자기 이름이 불리면 두세 명이 함께 돌아본다고 하죠. 같은 반에 같은 이름이 넷이나 있어서 이름 뒤에 A, B, C를 붙여 구분하기도 하고요. 프로그램도 마찬가지입니다. 코드가 길어지면 모든 변수와 함수 이름을 겹치지 않게 짓기란 불가능에 가까워요.

그래서 파이썬은 이름을 **사는 동네별로** 나눠 둡니다. 이 동네를 **네임스페이스(namespace, 이름공간)** 라고 해요. 네임스페이스는 이름(문자열)과 그 이름이 가리키는 객체를 짝지어 둔 **딕셔너리**입니다. 동네가 다르면 같은 이름을 써도 서로 부딪히지 않아요.

- **내장(Built-in)**: `print`, `len` 같은 내장 함수의 이름이 사는 곳입니다. 파이썬이 시작될 때 생기고 끝날 때까지 남아요.
- **전역(Global)**: 모듈(파이썬 파일 하나)의 맨 바깥에서 만든 이름들입니다. `globals()`로 볼 수 있어요.
- **둘러싼 함수(Enclosing)**: 함수 안의 함수에서 볼 때, 바깥 함수의 이름들입니다.
- **지역(Local)**: 함수 안에서 만든 이름들입니다. 함수가 불릴 때 생기고 함수가 끝나면 사라져요. `locals()`로 볼 수 있습니다.

```python
a = "global"

def outer_func():
    a = "outer"

    def inner_func():
        a = "inner"
        print(f"inner_func: {a}")
        print(f"inner_func의 이름들: {locals()}")

    inner_func()
    print(f"outer_func: {a}")

outer_func()
print(f"모듈: {a}")
```

결과는 `inner`, `{'a': 'inner'}`, `outer`, `global` 순서입니다. 같은 이름 `a`가 세 동네에 하나씩 살고 있고, 각 `print`는 자기 동네의 `a`를 찾았어요. `locals()`가 돌려준 딕셔너리를 보면 네임스페이스가 정말 딕셔너리라는 것도 확인할 수 있습니다.

`inner_func` 안의 `a = "inner"` 줄을 지우고 다시 실행해 보세요. 이번에는 `inner_func: outer`가 나옵니다. 자기 동네에 `a`가 없으니 한 칸 바깥 동네로 나가 찾은 거예요. 파이썬은 이름을 이렇게 **지역 → 둘러싼 함수 → 전역 → 내장** 순서로 찾습니다. 머리글자를 따서 **LEGB 규칙**이라고 하고, 어떤 이름을 어디서부터 볼 수 있는지의 범위를 **스코프(scope)** 라고 합니다. 동네 짱은 동네를 벗어나면 아무도 모르지만, 전국 짱은 어느 동네에서나 다 아는 것과 같아요.

### global과 nonlocal

함수 안에서 바깥 변수를 **읽기만** 하는 것은 문제없습니다. 그런데 바깥 변수를 **바꾸려고** 하면 이야기가 달라져요.

```python
count = 0

def increase():
    count += 1          # 지역 변수 count에 아직 값이 없는데 1을 더하려 함

try:
    increase()
except UnboundLocalError as e:
    print(f"[X] {e}")

# 권장: 바깥 값은 매개변수로 받고, 결과는 return으로 돌려준다
def increase_from(value):
    return value + 1

count = increase_from(count)
print(f"[O] count = {count}")  # [O] count = 1
```

함수 안에서 `count`에 값을 넣는 문장(`count += 1`)이 있으면, 파이썬은 `count`를 **지역 변수**로 봅니다. 그런데 아직 값을 넣은 적이 없는 지역 변수에 1을 더하려 하니 `UnboundLocalError`가 나는 거예요.

함수 안에 `global count`라고 한 줄 적으면 "이 `count`는 전역 동네의 것"이라고 알려 줄 수 있습니다. 함수 안의 함수에서 바로 바깥 함수의 변수를 바꾸려면 `nonlocal`을 쓰고요(10장 10.5절의 카운터 예제에서 다시 봅니다). `nonlocal`은 둘러싼 **함수**의 변수에만 쓸 수 있어서, 중첩되지 않은 함수에서는 쓸 수 없습니다.

> **Q. 그럼 global을 쓰면 되지, 왜 매개변수로 받으라고 하나요?**
> `global`을 쓴 함수는 바깥의 어떤 변수를 몰래 바꾸는지 함수 이름과 매개변수만 봐서는 알 수 없습니다. 코드가 길어지면 "이 값을 누가 바꿨지?"를 찾느라 고생하게 되고, 그 함수를 다른 곳에 옮겨 쓰기도 어려워요. 위 예제의 `increase_from()`처럼 필요한 값은 매개변수로 받고 결과는 `return`으로 돌려주면, 함수가 무엇을 받아 무엇을 내놓는지 한눈에 보입니다. 이미 `global`이 쓰인 코드를 만나면 이 방식으로 고쳐 나가는 것이 좋습니다.

## 9.3 자기 자신을 부르는 함수: 재귀

"의논"이라는 낱말의 한자를 찾아본 적 있나요? 議(의논할 의) 論(논할 론)이라고 나옵니다. "의논"의 "의"가 "의논할 의"라니, 그럼 "의논"이 뭐냐고 다시 찾으면 또 "의논할 의"가 나오죠. 빠져나갈 수가 없습니다.

함수도 이렇게 **자기 자신을 부를 수** 있습니다. 이런 함수를 **재귀 함수(recursive function)** 라고 해요. 다만 의논과 달리 재귀 함수에는 반드시 **빠져나오는 문**이 있어야 합니다. 재귀 함수는 두 부분으로 이루어져요.

- **종료 부분(base case)**: 더 이상 자기를 부르지 않고 바로 답을 내는 경우입니다.
- **자기 호출 부분**: 문제를 조금 작게 만들어 자기 자신을 다시 부르는 경우입니다. 부를 때마다 문제가 작아져서 결국 종료 부분에 닿아야 해요.

가장 흔한 예가 팩토리얼입니다. `5! = 5 × 4 × 3 × 2 × 1 = 120`이죠. 그런데 `5!`은 `5 × 4!`이고, `4!`은 `4 × 3!`이고… 이렇게 내려가다 `1! = 1`에서 멈춥니다. 이 생각을 그대로 코드로 옮기면 재귀 함수가 됩니다.

```python
def factorial(n):
    if n == 1:                       # 종료 부분(base case)
        return 1
    return n * factorial(n - 1)      # 자기 호출 부분

def factorial_loop(n):
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

print(factorial(5))       # 120
print(factorial_loop(5))  # 120
```

`factorial(3)`을 부르면 어떤 일이 일어나는지 따라가 봅시다. 함수가 불릴 때마다 그 호출의 정보(어디서 불렸는지, 변수에 어떤 값이 들었는지)를 적은 메모 한 장이 **스택**에 쌓입니다. 스택은 접시 더미처럼 마지막에 올린 것을 먼저 꺼내는 구조예요.

1. `factorial(3)`: `n`은 3. 1이 아니니 `3 * factorial(2)`를 계산하려고 `factorial(2)`를 부릅니다. 메모 1장.
2. `factorial(2)`: `n`은 2. `2 * factorial(1)`을 위해 `factorial(1)`을 부릅니다. 메모 2장.
3. `factorial(1)`: `n`이 1이니 바로 `1`을 돌려줍니다. 메모 3장째가 치워져요.
4. `factorial(2)`가 `2 * 1 = 2`를 돌려주고 치워집니다.
5. `factorial(3)`이 `3 * 2 = 6`을 돌려주고 치워집니다. 스택이 텅 비었어요.

종료 조건을 빠뜨리거나 잘못 쓰면 함수가 끝없이 자기를 부르겠죠. 파이썬은 이런 사고를 막으려고 재귀 깊이에 한도를 두고 있어서(기본값은 1000단계, `sys.getrecursionlimit()`으로 확인할 수 있어요), 한도를 넘으면 `RecursionError`를 내고 멈춥니다.

> **Q. 복잡한데 그냥 반복문을 쓰면 안 되나요?**
> 됩니다. 오히려 권할 만한 일이에요. 재귀 함수는 대부분 반복문으로 바꿀 수 있고, 함수를 부를 때마다 스택에 메모를 쌓는 비용이 있어서 보통 반복문이 시간과 메모리를 덜 씁니다. 위의 `factorial_loop()`가 반복문 버전이에요. 재귀의 장점은 **문제의 정의를 그대로 코드로 옮길 수 있다**는 것입니다. 다음의 하노이의 탑처럼 반복문으로는 생각하기 어려운 문제가 재귀로는 몇 줄에 풀리기도 합니다.

하노이의 탑은 기둥 세 개와 크기가 다른 원반 여러 개로 하는 퍼즐입니다. 한 기둥에 큰 원반부터 쌓인 원반을 다른 기둥으로 모두 옮기는데, 규칙은 두 가지예요. 한 번에 원반 하나만 옮길 수 있고, 작은 원반 위에 큰 원반을 놓을 수 없습니다. 풀이는 세 단계로 생각하면 됩니다.

1. 가장 큰 원반을 뺀 나머지 n-1개를 보조 기둥으로 옮긴다. (재귀 호출)
2. 가장 큰 원반을 목표 기둥으로 옮긴다.
3. 보조 기둥의 n-1개를 목표 기둥으로 옮긴다. (재귀 호출)

"n-1개를 옮긴다"를 어떻게 하는지는 고민하지 않습니다. 같은 함수가 알아서 하도록 맡기는 거예요.

```python
def hanoi(n, source, target, auxiliary):
    if n == 0:
        return
    hanoi(n - 1, source, auxiliary, target)   # 1. 위의 n-1개를 보조 기둥으로
    print(f"원반 {n}: {source} → {target}")    # 2. 가장 큰 원반을 목표 기둥으로
    hanoi(n - 1, auxiliary, target, source)   # 3. 보조 기둥의 n-1개를 목표 기둥으로

hanoi(3, "A", "C", "B")
```

원반 3개를 A에서 C로 옮기는 데 7번 움직입니다. 출력의 네 번째 줄 `원반 3: A → C`가 가장 큰 원반이 옮겨지는 순간이고, 그 앞의 세 줄이 1단계, 뒤의 세 줄이 3단계예요. 이해가 어렵다면 종이에 기둥 셋을 그려 놓고 출력대로 직접 옮겨 보세요.
