## 들어가며: 멈췄다가 이어서 할 수 있는 함수

두꺼운 책을 읽다가 저녁을 먹으러 갈 때 어떻게 하나요? 책갈피를 꽂아 두고 덮죠. 밥을 먹고 와서 책을 펴면 처음부터가 아니라 책갈피 자리부터 이어서 읽습니다.

지금까지 만든 함수는 이렇게 하지 못했습니다. 누군가 부르면(call) 처음부터 실행되고, 결과를 돌려주면(return) 그대로 끝납니다. 함수 안에서 쓰던 변수도 함께 사라져요. 다음에 다시 부르면 또 처음부터 시작하고요. 그런데 이 장에서 만날 **제너레이터**와 **코루틴**은 책갈피를 꽂을 수 있는 함수입니다. 실행하다가 중간에 **멈추고(suspend)**, 값을 하나 건네준 뒤, 나중에 **멈춘 자리부터 다시 이어서(resume)** 실행할 수 있어요. 멈춰 있는 동안 변수들도 그대로 기억하고 있고요.

이게 왜 쓸모가 있을까요? 우리가 늘 쓰던 `range()`가 좋은 예입니다. `range(1000000000)`은 10억 개의 숫자를 미리 만들어 두지 않습니다. `for`문이 다음 숫자를 달라고 할 때마다 그때그때 하나씩 만들어 줘요. 그래서 `sys.getsizeof(range(10**9))`로 크기를 재 보면 고작 48바이트입니다(파이썬 3.12). 숫자 열 개짜리 리스트(136바이트)보다도 작아요. **필요할 때 필요한 만큼만** 만드는 것, 이것이 이 장의 첫 번째 주제입니다.

두 번째 주제는 **기다리는 동안 다른 일 하기**입니다. 식당 직원 한 명이 손님 열 테이블을 맡는다고 해 봅시다. 1번 테이블 주문을 주방에 넣고 음식이 나올 때까지 그 앞에 서서 기다린다면 나머지 아홉 테이블은 하염없이 기다려야겠죠. 실제 직원은 주문을 넣고 나면 바로 2번 테이블로 갑니다. 음식이 나왔다는 신호가 오면 그때 1번 테이블로 돌아가고요. 코루틴은 이 직원처럼 "기다려야 하는 순간"에 멈춰서 다른 일에 자리를 내주고, 기다리던 일이 끝나면 멈춘 자리부터 이어 갑니다. 파이썬에서는 `async`와 `await`, 그리고 `asyncio` 라이브러리가 이 일을 맡습니다.

정리하면 이 장의 세 주인공은 이런 관계입니다.

- **반복자(iterator)**: "다음 거 줘"라고 할 때마다 값을 하나씩 건네주는 객체. `for`문이 뒤에서 쓰는 규칙입니다.
- **제너레이터(generator)**: `yield`로 멈췄다 이어 가며 반복자를 아주 쉽게 만드는 함수. 코루틴의 한 형태예요.
- **코루틴(coroutine)**: `async def`로 만드는, 기다리는 동안 멈춰서 양보할 줄 아는 함수. 제너레이터 기반 코루틴과 구분해서 **네이티브 코루틴**이라고도 부릅니다.

## 15.1 반복자 프로토콜

### 반복자의 기본 개념

반복자는 Python에서 데이터를 순차적으로 처리하는 핵심 메커니즘입니다. `for` 문이 동작하는 원리를 이해해봅시다.

`for 도시 in 한국_도시:`라고 쓰면 파이썬은 뒤에서 두 가지 일을 합니다. 먼저 `iter(한국_도시)`로 리스트에서 **반복자**를 하나 받아 옵니다. 그다음 `next(반복자)`를 계속 불러서 값을 하나씩 꺼내요. 아래 코드는 이 과정을 손으로 직접 해 본 것입니다.

```python
# 기본적인 for 문
한국_도시 = ['서울', '부산', '인천', '대구', '대전']

# 이것이 실제로는 어떻게 동작하는지 보기
도시_반복자 = iter(한국_도시)
print(f"반복자 객체: {도시_반복자}")
print(f"첫 번째 도시: {next(도시_반복자)}")
print(f"두 번째 도시: {next(도시_반복자)}")
```

```text
# 실행 결과
반복자 객체: <list_iterator object at 0x...>
첫 번째 도시: 서울
두 번째 도시: 부산
```

`next()`를 부를 때마다 다음 도시가 나오죠. 반복자는 "지금 어디까지 꺼냈는지"를 스스로 기억하고 있습니다. 그럼 다섯 개를 다 꺼낸 뒤에 `next()`를 한 번 더 부르면 어떻게 될까요? `StopIteration`이라는 예외가 발생합니다. "더 줄 게 없어요"라는 신호예요. `for`문은 이 신호를 받으면 에러를 내지 않고 조용히 반복을 끝냅니다. 우리가 `for`문을 쓰면서 한 번도 끝을 걱정하지 않았던 이유죠.

### 반복 가능한 객체 vs 반복자

많은 개발자가 혼동하는 개념을 명확히 정리해봅시다. **반복 가능한 객체(iterable)** 는 책이고, **반복자(iterator)** 는 그 책에 꽂힌 책갈피라고 생각하면 쉽습니다. 책 한 권에 책갈피를 여러 개 꽂을 수 있듯, 리스트 하나로 `iter()`를 여러 번 부르면 서로 따로 움직이는 반복자가 여러 개 생깁니다. 반면 책갈피는 끝까지 가면 그걸로 끝이에요. 반복자를 `list()`로 한 번 다 꺼내고 나서 다시 `list()`를 하면 빈 리스트 `[]`가 나옵니다.

```python
from collections.abc import Iterable, Iterator

한국_도시 = ['서울', '부산', '인천', '대구', '대전']
도시_반복자 = iter(한국_도시)

print(f"리스트는 반복 가능? {isinstance(한국_도시, Iterable)}")        # True
print(f"리스트는 반복자? {isinstance(한국_도시, Iterator)}")           # False
print(f"반복자는 반복 가능? {isinstance(도시_반복자, Iterable)}")       # True
print(f"반복자는 반복자? {isinstance(도시_반복자, Iterator)}")         # True
```

**핵심 차이점:**
- **반복 가능한 객체**: `__iter__()` 메서드를 구현한 객체
- **반복자**: `__iter__()`와 `__next__()` 메서드를 모두 구현한 객체

반복자는 반복 가능한 객체이기도 하다는 점이 재미있죠? 반복자의 `__iter__()`는 자기 자신을 돌려주기 때문에, 반복자를 `for`문에 바로 넣어도 됩니다. 이렇게 "이 두 메서드를 이런 뜻으로 구현하면 `for`문에서 쓸 수 있다"는 약속을 **반복자 프로토콜**이라고 합니다.

### 커스텀 반복자 구현

프로토콜을 알았으니 직접 만들어 볼 수 있습니다. 한국어 카운터를 만들어 반복자 프로토콜을 완전히 이해해봅시다. 할 일은 두 가지예요. `__iter__()`에서 자기 자신을 돌려주고, `__next__()`에서 다음 값을 돌려주다가 끝에 도달하면 `StopIteration`을 일으키면 됩니다. 현재 위치는 `self.현재`라는 속성에 기억해 둡니다. 이것이 책갈피 역할을 하죠.

```python
class 한국어_카운터:
    """한국어로 카운트하는 반복자"""
    
    def __init__(self, 시작: int = 1, 끝: int = 10):
        self.시작 = 시작
        self.끝 = 끝
        self.현재 = 시작 - 1
        
        # 한국어 숫자 표현
        self.한국어_숫자 = {
            1: '하나', 2: '둘', 3: '셋', 4: '넷', 5: '다섯',
            6: '여섯', 7: '일곱', 8: '여덟', 9: '아홉', 10: '열'
        }
    
    def __iter__(self):
        """반복자 객체 자신을 반환"""
        return self
    
    def __next__(self):
        """다음 값 반환"""
        self.현재 += 1
        if self.현재 > self.끝:
            raise StopIteration
        
        한국어_표현 = self.한국어_숫자.get(self.현재, str(self.현재))
        return f"{한국어_표현}({self.현재})"

# 사용 예제
print("한국어 카운터 테스트:")
for 숫자 in 한국어_카운터(1, 5):
    print(f"  {숫자}")
```

```text
# 실행 결과
한국어 카운터 테스트:
  하나(1)
  둘(2)
  셋(3)
  넷(4)
  다섯(5)
```

`for`문 입장에서는 이 클래스가 리스트와 다를 게 없습니다. `__next__()`가 여섯 번째 호출에서 `StopIteration`을 일으키자 반복이 깔끔하게 끝났어요. 사전에 없는 11 이상의 숫자는 `.get(self.현재, str(self.현재))` 덕분에 그냥 숫자 문자열로 나옵니다.

### 더 실용적인 반복자 예제

한국 지역별 날씨 데이터를 처리하는 반복자를 만들어봅시다. 이번에는 값을 하나씩 돌려줄 때 `(지역, 날씨, 온도)` 튜플로 돌려줘서, `for 지역, 날씨, 온도 in ...`처럼 바로 풀어 받을 수 있게 했습니다. 정렬 메서드 `온도순_정렬()`이 `self`를 돌려주는 것도 눈여겨보세요. 그래서 `지역_날씨_반복자(...).온도순_정렬()`처럼 만들자마자 정렬한 반복자를 바로 받아 쓸 수 있습니다.

```python
from typing import Dict, Tuple, Optional
import json

class 지역_날씨_반복자:
    """한국 지역별 날씨 데이터 반복자"""
    
    def __init__(self, 날씨_데이터: Dict[str, Dict]):
        self.날씨_데이터 = 날씨_데이터
        self.지역_목록 = list(날씨_데이터.keys())
        self.현재_인덱스 = 0
    
    def __iter__(self):
        return self
    
    def __next__(self) -> Tuple[str, str, int]:
        if self.현재_인덱스 >= len(self.지역_목록):
            raise StopIteration
        
        지역 = self.지역_목록[self.현재_인덱스]
        날씨_정보 = self.날씨_데이터[지역]
        
        self.현재_인덱스 += 1
        
        return (
            지역,
            날씨_정보['날씨'],
            날씨_정보['온도']
        )
    
    def 온도순_정렬(self):
        """온도 순으로 지역 목록 정렬"""
        self.지역_목록.sort(
            key=lambda 지역: self.날씨_데이터[지역]['온도'],
            reverse=True
        )
        self.현재_인덱스 = 0
        return self

# 샘플 데이터
한국_날씨_데이터 = {
    '서울': {'날씨': '맑음', '온도': 25},
    '부산': {'날씨': '흐림', '온도': 28},
    '인천': {'날씨': '비', '온도': 22},
    '대구': {'날씨': '맑음', '온도': 30},
    '광주': {'날씨': '흐림', '온도': 26}
}

print("지역별 날씨 정보:")
날씨_반복자 = 지역_날씨_반복자(한국_날씨_데이터)
for 지역, 날씨, 온도 in 날씨_반복자:
    print(f"  {지역}: {날씨}, {온도}°C")

print("\n온도 높은 순으로 정렬:")
날씨_반복자_정렬 = 지역_날씨_반복자(한국_날씨_데이터).온도순_정렬()
for 지역, 날씨, 온도 in 날씨_반복자_정렬:
    print(f"  {지역}: {날씨}, {온도}°C")
```

첫 번째 반복은 사전에 넣은 순서(서울, 부산, 인천, 대구, 광주)대로, 두 번째는 대구(30°C), 부산(28°C), 광주(26°C), 서울(25°C), 인천(22°C) 순으로 나옵니다. 정렬된 결과를 보려고 반복자를 **새로 만들었다**는 점이 중요해요. 첫 번째 `for`문이 끝난 `날씨_반복자`는 책갈피가 이미 마지막 장에 가 있어서, 다시 `for`문에 넣으면 아무것도 나오지 않습니다.

### iter() 함수의 고급 활용

`iter()` 함수는 두 가지 형태로 사용할 수 있습니다. 첫 번째는 지금까지 본 `iter(리스트)`이고, 두 번째는 `iter(함수, 멈춤값)`입니다. 두 번째 형태는 "이 함수를 계속 부르다가 **멈춤값(sentinel, 보초)** 이 나오면 멈춰라"라는 뜻이에요. 끝이 언제인지 미리 알 수 없을 때 쓸모가 있습니다.

```python
import random
import time

# 형태 1: 반복 가능한 객체로부터 반복자 생성
한국_도시 = ['서울', '부산', '인천', '대구', '대전']
도시_반복자 = iter(한국_도시)

# 형태 2: 함수와 센티널 값으로 반복자 생성
def 랜덤_온도():
    """-10도에서 40도 사이의 랜덤 온도 생성"""
    return random.randint(-10, 40)

print("센티널 값을 활용한 반복자:")
온도_반복자 = iter(랜덤_온도, 0)  # 0이 나올 때까지 계속 호출

for i, 온도 in enumerate(온도_반복자):
    if i >= 5:  # 최대 5개만 출력
        break
    print(f"  현재 온도: {온도}°C")

# 파일 읽기에 활용
def 한국어_라인_읽기():
    """파일에서 한 줄씩 읽기 (빈 줄이 나오면 종료)"""
    sample_data = ['첫 번째 줄', '두 번째 줄', '세 번째 줄', '', '마지막 줄']
    index = 0
    
    def get_line():
        nonlocal index
        if index >= len(sample_data):
            return ''
        line = sample_data[index]
        index += 1
        return line
    
    return iter(get_line, '')  # 빈 문자열까지 읽기

print("\n파일 라인 읽기:")
for 라인 in 한국어_라인_읽기():
    print(f"  읽은 라인: '{라인}'")
```

온도는 무작위라서 실행할 때마다 다르게 나옵니다. 0이 나오면 그 자리에서 멈추고, 그 전에 다섯 개를 채우면 `break`로 멈춰요. 아래쪽 줄 읽기 예제는 결과가 조금 의외입니다. `'첫 번째 줄'`, `'두 번째 줄'`, `'세 번째 줄'` 세 줄만 나오고 `'마지막 줄'`은 끝내 나오지 않아요. 네 번째 자리에 있는 빈 문자열 `''`이 멈춤값이라, 그 뒤는 읽어 보지도 않고 반복이 끝났기 때문입니다. 멈춤값은 데이터 중간에 섞여 있어도 가차 없이 반복을 끊는다는 것을 기억해 두세요.

## 15.2 제너레이터 완전 가이드

### 제너레이터의 기본 개념

제너레이터는 반복자를 더 쉽게 만들 수 있는 방법입니다. `yield` 키워드를 사용하여 함수를 제너레이터로 만들 수 있습니다.

앞에서 반복자를 만들 때는 클래스를 만들고, `__iter__`와 `__next__`를 쓰고, 현재 위치를 속성에 저장하고, 끝에서 `StopIteration`까지 직접 일으켜야 했죠. 제너레이터를 쓰면 이 일을 파이썬이 다 해 줍니다. 함수 안에 `return` 대신 `yield`를 쓰기만 하면 돼요.

`yield`는 "이 값을 건네주고, **여기에 책갈피를 꽂고 잠깐 멈춰**"라는 뜻입니다. `return`은 값을 주고 함수를 끝내지만, `yield`는 값을 주고 멈춰서 다음 `next()`를 기다립니다. 다음 `next()`가 오면 멈춘 바로 그 줄부터 이어서 실행하고, 함수 끝에 도달하면 파이썬이 알아서 `StopIteration`을 일으켜 줘요. 그리고 제너레이터 함수는 불러도 본문이 바로 실행되지 않습니다. 함수를 부르면 실행 준비만 된 **제너레이터 객체**가 나오고, 본문은 첫 `next()`가 올 때 비로소 시작됩니다.

```python
def 한국_도시_생성기():
    """한국 주요 도시를 순차적으로 생성하는 제너레이터"""
    도시들 = ['서울', '부산', '인천', '대구', '대전', '광주', '울산', '세종']
    
    for 순번, 도시 in enumerate(도시들, 1):
        print(f"  {순번}번째 도시 '{도시}' 생성 중...")
        yield {'순번': 순번, '도시명': 도시}

print("제너레이터 기본 사용법:")
도시_생성기 = 한국_도시_생성기()
print(f"제너레이터 타입: {type(도시_생성기)}")

# 필요할 때마다 하나씩 생성
print("\n첫 세 개 도시:")
for i, 도시_정보 in enumerate(도시_생성기):
    if i >= 3:
        break
    print(f"  {도시_정보}")
```

실행 결과를 보면 제너레이터가 정말 하나씩 만든다는 것이 보입니다.

```
첫 세 개 도시:
  1번째 도시 '서울' 생성 중...
  {'순번': 1, '도시명': '서울'}
  2번째 도시 '부산' 생성 중...
  {'순번': 2, '도시명': '부산'}
  3번째 도시 '인천' 생성 중...
  {'순번': 3, '도시명': '인천'}
  4번째 도시 '대구' 생성 중...
```

"생성 중"과 출력이 번갈아 나오죠? 여덟 개를 미리 다 만들어 두는 게 아니라 `for`문이 하나 달라고 할 때마다 하나씩 만들고 있다는 증거입니다. 마지막 줄도 눈여겨보세요. 네 번째 도시 '대구'는 "생성 중"까지 찍혔는데 출력은 되지 않았습니다. `for`문은 일단 다음 값을 받아 온 다음에 `if i >= 3: break`를 검사하거든요. 대구는 만들어졌지만 쓰이지 않고 버려졌고, 광주부터는 아예 만들어지지도 않았습니다.

### 제너레이터 vs 리스트 컴프리헨션

리스트 컴프리헨션의 대괄호 `[]`를 소괄호 `()`로 바꾸면 **제너레이터 표현식**이 됩니다. 생김새는 거의 같지만 하는 일은 전혀 다릅니다. 리스트는 10만 개의 값을 지금 당장 다 만들어 메모리에 올려놓고, 제너레이터는 "필요하면 만들어 줄게"라는 약속만 들고 있어요. 메모리 효율성 비교:

```python
import itertools
import sys

# 리스트 컴프리헨션 - 모든 데이터를 메모리에 저장
큰_리스트 = [x**2 for x in range(100000)]
print(f"리스트 크기: {sys.getsizeof(큰_리스트):,} bytes")

# 제너레이터 표현식 - 필요할 때만 생성
큰_제너레이터 = (x**2 for x in range(100000))
print(f"제너레이터 크기: {sys.getsizeof(큰_제너레이터):,} bytes")

# 사용법은 동일하지만 메모리 효율성이 다름
print(f"리스트 첫 5개: {큰_리스트[:5]}")
# 제너레이터는 슬라이싱이 안 되므로 islice로 필요한 5개만 꺼냄
print(f"제너레이터 첫 5개: {list(itertools.islice(큰_제너레이터, 5))}")
```

파이썬 3.12에서 실행하면 리스트는 `800,984 bytes`, 제너레이터는 `200 bytes`가 나옵니다. 4,000배 차이죠. 게다가 리스트는 개수가 늘어날수록 커지지만 제너레이터는 개수와 상관없이 크기가 거의 그대로입니다. (`sys.getsizeof`는 리스트가 담고 있는 숫자 객체들의 크기까지는 세지 않으니 실제 차이는 이보다 더 큽니다.)

마지막 줄도 눈여겨보세요. 제너레이터는 `[:5]` 같은 슬라이싱을 할 수 없습니다. 그렇다고 `list(큰_제너레이터)[:5]`처럼 쓰면 10만 개를 **전부** 리스트로 만든 다음 앞 5개만 자르는 셈이라 제너레이터를 쓴 의미가 사라지죠. 그래서 `itertools.islice(큰_제너레이터, 5)`로 필요한 5개만 꺼냈습니다. 나머지 99,995개는 아직 만들어지지도 않았어요. 그리고 제너레이터도 반복자라서 **한 번 꺼낸 값은 다시 꺼낼 수 없습니다.** 여러 번 훑어야 하는 데이터라면 리스트가 맞는 선택이에요.

### 실무 중심 제너레이터 예제

한국 주식 데이터를 처리하는 제너레이터를 만들어봅시다. 하루치 데이터를 만들 때마다 `yield`로 건네주기 때문에, 1년치든 10년치든 메모리에는 늘 하루치만 있습니다. 반환 타입의 `Generator[Dict[str, Any], None, None]`은 "건네주는 값(yield)의 타입, `send()`로 받는 값의 타입, 끝날 때 `return`하는 값의 타입" 순서예요. 이 예제는 딕셔너리를 건네기만 하고 받거나 돌려주는 것은 없어서 뒤의 둘이 `None`입니다.

```python
from typing import Generator, Dict, Any
import json
from datetime import datetime, timedelta

def 주식_데이터_생성기(
    종목코드: str, 
    시작일: str, 
    일수: int = 30
) -> Generator[Dict[str, Any], None, None]:
    """한국 주식 데이터 시뮬레이션 제너레이터"""
    
    import random
    
    # 한국 주요 종목 정보
    종목_정보 = {
        '005930': {'회사명': '삼성전자', '기준가': 75000},
        '000660': {'회사명': 'SK하이닉스', '기준가': 130000},
        '035420': {'회사명': 'NAVER', '기준가': 350000},
        '051910': {'회사명': 'LG화학', '기준가': 800000},
        '006400': {'회사명': '삼성SDI', '기준가': 650000}
    }
    
    if 종목코드 not in 종목_정보:
        raise ValueError(f"지원하지 않는 종목코드: {종목코드}")
    
    회사_정보 = 종목_정보[종목코드]
    현재가 = 회사_정보['기준가']
    
    # 시작일 파싱
    시작_날짜 = datetime.strptime(시작일, '%Y-%m-%d')
    
    for i in range(일수):
        현재_날짜 = 시작_날짜 + timedelta(days=i)
        
        # 주말 건너뛰기
        if 현재_날짜.weekday() >= 5:  # 토요일(5), 일요일(6)
            continue
        
        # 가격 변동 시뮬레이션 (-5% ~ +5%)
        변동율 = random.uniform(-0.05, 0.05)
        현재가 = int(현재가 * (1 + 변동율))
        
        # 거래량 시뮬레이션
        거래량 = random.randint(100000, 2000000)
        
        yield {
            '날짜': 현재_날짜.strftime('%Y-%m-%d'),
            '종목코드': 종목코드,
            '회사명': 회사_정보['회사명'],
            '종가': 현재가,
            '거래량': 거래량,
            '변동율': round(변동율 * 100, 2)
        }

# 사용 예제
print("삼성전자 주식 데이터 (첫 10일):")
삼성전자_데이터 = 주식_데이터_생성기('005930', '2024-01-01', 20)

for i, 일일_데이터 in enumerate(삼성전자_데이터):
    if i >= 10:
        break
    print(f"  {일일_데이터['날짜']}: {일일_데이터['종가']:,}원 "
          f"({일일_데이터['변동율']:+.1f}%) "
          f"거래량: {일일_데이터['거래량']:,}")
```

가격과 거래량은 무작위라 실행할 때마다 다르지만, 날짜를 보면 `2024-01-05` 다음이 `2024-01-08`입니다. 6일(토)과 7일(일)은 `continue`로 건너뛰었기 때문이에요. 20일치를 요청했어도 화면에는 앞의 10건만 나오고, 그 뒤의 날짜는 만들어지지도 않습니다.

### 제너레이터 메서드: send(), throw(), close()

제너레이터는 단순히 데이터를 생성하는 것 이상의 기능을 제공합니다. 지금까지는 제너레이터가 값을 **주기만** 했죠. 그런데 `yield`는 사실 양방향 문입니다. `새_카테고리 = yield 값`처럼 쓰면, 값을 내보내고 멈췄다가 다시 깨어날 때 **바깥에서 넣어 준 값**을 받을 수 있어요. 바깥에서 값을 넣는 방법이 `send()`입니다. 여기에 예외를 던져 넣는 `throw()`, 제너레이터를 끝내는 `close()`까지 세 가지 메서드가 있습니다. 이렇게 값을 주고받으며 멈췄다 이어 가는 것이 바로 들어가며에서 말한 코루틴의 모습이에요.

```python
def 한국_뉴스_처리기():
    """한국 뉴스를 처리하는 제너레이터"""
    뉴스_카테고리 = '정치'  # 기본 카테고리
    뉴스_번호 = 1
    
    while True:
        try:
            # 외부에서 새로운 카테고리를 받을 수 있음
            새_카테고리 = yield f"[{뉴스_카테고리}] 뉴스 #{뉴스_번호}"
            
            if 새_카테고리:
                print(f"  카테고리를 '{뉴스_카테고리}'에서 '{새_카테고리}'로 변경")
                뉴스_카테고리 = 새_카테고리
            
            뉴스_번호 += 1
            
        except GeneratorExit:
            print("  뉴스 처리기 종료됨")
            break
        except Exception as e:
            print(f"  에러 발생: {e}")
            뉴스_번호 += 1  # 에러가 나도 계속 처리

# 제너레이터 메서드 사용 예제
print("제너레이터 메서드 활용:")
뉴스_처리기 = 한국_뉴스_처리기()

# 첫 번째 뉴스
print(f"1. {next(뉴스_처리기)}")

# send()로 카테고리 변경
print(f"2. {뉴스_처리기.send('경제')}")
print(f"3. {뉴스_처리기.send('스포츠')}")

# throw()로 예외 던지기 (제너레이터가 예외를 처리한 뒤 다음 뉴스를 돌려줌)
print(f"4. {뉴스_처리기.throw(RuntimeError('네트워크 연결 오류'))}")

print(f"5. {next(뉴스_처리기)}")

# close()로 제너레이터 종료
뉴스_처리기.close()
```

실행 결과는 다음과 같습니다.

```
제너레이터 메서드 활용:
1. [정치] 뉴스 #1
  카테고리를 '정치'에서 '경제'로 변경
2. [경제] 뉴스 #2
  카테고리를 '경제'에서 '스포츠'로 변경
3. [스포츠] 뉴스 #3
  에러 발생: 네트워크 연결 오류
4. [스포츠] 뉴스 #4
5. [스포츠] 뉴스 #5
  뉴스 처리기 종료됨
```

한 줄씩 따라가 볼까요? 처음에는 반드시 `next()`로 제너레이터를 첫 `yield`까지 데려가야 합니다. 아직 `yield`에 도착하지도 않은 제너레이터에게 `send('경제')`를 하면 받을 자리가 없어서 `TypeError`가 나요. 그다음 `send('경제')`는 멈춰 있던 `yield` 자리에 `'경제'`를 넣어 깨우고, 제너레이터는 카테고리를 바꾼 뒤 다음 `yield`까지 가서 `[경제] 뉴스 #2`를 내놓습니다. `send()`는 값을 넣는 동시에 다음 값을 받아 오는 거죠.

`throw()`는 멈춰 있던 `yield` 자리에서 예외를 일으킵니다. 제너레이터는 `except`에서 그 예외를 처리해 "에러 발생"을 찍고, 다시 반복문을 돌아 다음 `yield`에서 `[스포츠] 뉴스 #4`를 내놓아요. 이 값이 바로 **`throw()`의 반환값**입니다. 그래서 4번 줄은 `throw()`의 결과를 그대로 출력했어요. 만약 `throw()`의 반환값을 받지 않고 버린 채 `next()`를 부르면 `#4`는 사라지고 `#5`부터 받게 됩니다. `send()`와 `throw()`는 모두 "다음 값을 받아 오는" 호출이라는 것을 기억해 두세요.

마지막의 `close()`는 멈춰 있는 자리에 `GeneratorExit` 예외를 넣어서 제너레이터를 끝냅니다. 정리할 일이 있다면 이 예제처럼 `except GeneratorExit:`에서 하면 됩니다. 참고로 예제처럼 `throw(RuntimeError("네트워크 연결 오류"))`로 예외 **객체 하나**를 넘기세요. 오래된 코드에서 보이는 `throw(RuntimeError, "네트워크 연결 오류")`처럼 종류와 메시지를 따로 넘기는 방식은 파이썬 3.12부터 `DeprecationWarning`이 나옵니다. 더 이상 권장하지 않으며 앞으로 없어질 수 있다는 뜻이에요.

### yield from 활용

복잡한 제너레이터를 조합할 때 `yield from`이 유용합니다. `yield from 다른_제너레이터()`는 "이 제너레이터가 내놓는 값을 내가 하나씩 대신 넘겨줄게"라는 뜻이에요. `for 값 in 다른_제너레이터(): yield 값`을 한 줄로 줄인 것과 같습니다. 큰 일을 지역별 작은 제너레이터로 나눠 만들고, 바깥 제너레이터는 순서대로 이어 붙이기만 하면 되죠.

```python
def 지역별_관광지():
    """지역별 주요 관광지 제너레이터"""
    
    def 서울_관광지():
        서울_명소 = ['경복궁', '남산타워', '명동', '인사동', '강남']
        for 명소 in 서울_명소:
            yield f"서울 - {명소}"
    
    def 부산_관광지():
        부산_명소 = ['해운대', '광안리', '태종대', '감천문화마을', '자갈치시장']
        for 명소 in 부산_명소:
            yield f"부산 - {명소}"
    
    def 제주_관광지():
        제주_명소 = ['한라산', '성산일출봉', '우도', '천지연폭포', '협재해수욕장']
        for 명소 in 제주_명소:
            yield f"제주 - {명소}"
    
    # yield from을 사용하여 여러 제너레이터 연결
    print("서울 관광지:")
    yield from 서울_관광지()
    
    print("\n부산 관광지:")
    yield from 부산_관광지()
    
    print("\n제주 관광지:")
    yield from 제주_관광지()

# 사용 예제
print("전국 주요 관광지:")
for 관광지 in 지역별_관광지():
    print(f"  {관광지}")
```

출력에서 `서울 관광지:` 같은 제목이 지역마다 딱 그 지역의 관광지 바로 앞에 찍히는 것을 보세요. 제너레이터가 서울의 다섯 곳을 다 넘겨준 다음에야 다음 줄로 넘어가서 `부산 관광지:`를 출력하기 때문입니다. 제목 줄에 들여쓰기가 없는 것은 제너레이터 안의 `print`가 찍은 것이고, 들여쓰기된 줄은 바깥 `for`문이 찍은 것이에요. 두 코드가 번갈아 실행되고 있다는 게 눈에 보이죠.

### 실무 패턴: 배치 처리 제너레이터

대용량 데이터를 배치로 처리하는 제너레이터입니다. 데이터베이스에 고객 100만 명을 넣는다고 해 봅시다. 한 명씩 넣으면 너무 느리고, 100만 명을 한꺼번에 메모리에 올리면 컴퓨터가 버티지 못합니다. 그래서 50명, 100명처럼 적당한 크기의 묶음(배치)으로 나눠 처리하죠. 아래 `배치_처리기`는 어떤 반복자든 받아서 정해진 크기만큼 모일 때마다 리스트로 내놓고, 끝에 남은 자투리도 놓치지 않고 마지막 배치로 내놓습니다.

```python
from typing import Generator, List, Iterator, TypeVar

T = TypeVar('T')

def 배치_처리기(
    데이터: Iterator[T], 
    배치_크기: int = 100
) -> Generator[List[T], None, None]:
    """데이터를 지정된 크기의 배치로 나누는 제너레이터"""
    
    배치 = []
    
    for 항목 in 데이터:
        배치.append(항목)
        
        if len(배치) == 배치_크기:
            yield 배치
            배치 = []
    
    # 남은 데이터가 있으면 마지막 배치로 반환
    if 배치:
        yield 배치

# 한국 고객 데이터 시뮬레이션
def 고객_데이터_생성기():
    """한국 고객 데이터 생성기"""
    import random
    
    한국_성씨 = ['김', '이', '박', '최', '정', '강', '조', '윤', '장', '임']
    한국_이름 = ['민수', '영희', '철수', '지영', '현우', '소영', '동현', '수빈']
    한국_지역 = ['서울', '부산', '대구', '인천', '광주', '대전', '울산', '세종']
    
    for i in range(1, 1001):  # 1000명의 고객
        성 = random.choice(한국_성씨)
        이름 = random.choice(한국_이름)
        지역 = random.choice(한국_지역)
        
        yield {
            '고객ID': i,
            '이름': f'{성}{이름}',
            '지역': 지역,
            '나이': random.randint(20, 70)
        }

# 배치 처리 예제
print("고객 데이터 배치 처리:")
고객_데이터 = 고객_데이터_생성기()

배치_번호 = 1
for 배치 in 배치_처리기(고객_데이터, 배치_크기=50):
    print(f"배치 #{배치_번호}: {len(배치)}명 처리")
    
    # 첫 번째 배치만 상세 출력
    if 배치_번호 == 1:
        for 고객 in 배치[:5]:  # 처음 5명만
            print(f"  {고객}")
    
    배치_번호 += 1
    
    if 배치_번호 > 3:  # 처음 3개 배치만 처리
        break
```

`배치 #1: 50명 처리` 아래에 고객 다섯 명이 보이고, `배치 #2`, `배치 #3`이 이어진 뒤 멈춥니다. 고객 데이터 제너레이터와 배치 제너레이터가 **두 단계로 연결**되어 있다는 점이 핵심이에요. 1,000명을 만들 수 있는 생성기지만 세 배치에서 멈췄으니 실제로 만들어진 고객은 150명뿐입니다. 이렇게 제너레이터를 파이프처럼 이어 붙이면, 데이터가 아무리 커도 메모리에는 늘 한 배치만 머무릅니다.

## 15.3 비동기 프로그래밍 (async/await)

### 동기 vs 비동기 프로그래밍

들어가며의 식당 직원을 다시 떠올려 볼까요? 주문을 넣고 음식이 나올 때까지 그 자리에서 기다리는 직원이 **동기(synchronous)** 방식이고, 주문을 넣자마자 다른 테이블로 가는 직원이 **비동기(asynchronous)** 방식입니다.

프로그램에서 "기다리는 시간"은 대개 컴퓨터 바깥에서 생깁니다. 웹사이트에 요청을 보내고 응답을 기다리거나, 데이터베이스에 질문하고 답을 기다리거나, 파일을 읽어 오길 기다리는 시간이죠. 이런 작업을 **I/O 바운드(입출력 위주) 작업**이라고 합니다. CPU는 그동안 할 일이 없어서 놀고 있어요. 비동기 프로그래밍은 이 노는 시간에 다른 작업을 진행시켜 전체 시간을 줄입니다.

여러 일을 한꺼번에 처리하는 방법은 사실 세 가지가 있습니다.

- **멀티프로세싱(multiprocessing)**: 요리사를 여러 명 고용합니다. CPU 코어 여러 개가 각자 독립된 프로세스로 진짜 동시에 일해요. 계산이 많은 작업에 좋지만 프로세스를 띄우는 비용이 큽니다.
- **멀티스레딩(multithreading)**: 한 주방 안에 손을 여러 개 둡니다. 스레드끼리 메모리를 함께 써서 가볍지만, 파이썬(CPython)에는 한 번에 한 스레드만 파이썬 코드를 실행하게 하는 **GIL(전역 인터프리터 잠금)** 이 있어서 계산 위주 작업은 빨라지지 않습니다. 대신 기다리는 시간이 대부분인 I/O 작업에서는 효과가 있어요.
- **asyncio**: 직원 **한 명**(스레드 하나)이 기다리는 시간마다 다른 일로 옮겨 다닙니다. 스레드를 여러 개 만들지 않으니 수천 개의 연결도 가볍게 다룰 수 있어요.

스레드와 프로세스로 동시 작업을 하는 방법은 17장에서 다루고, 이 장에서는 asyncio에 집중합니다. 먼저 동기와 비동기 방식의 차이를 이해해봅시다:

```python
import time
import asyncio
from typing import List

# 동기 방식 - 한 번에 하나씩 처리
def 동기_뉴스_수집(url_목록: List[str]) -> List[str]:
    """여러 뉴스 사이트를 동기적으로 수집"""
    결과 = []
    시작_시간 = time.time()
    
    for i, url in enumerate(url_목록):
        print(f"  동기 처리: {i+1}번째 사이트 접속 중...")
        try:
            # 실제로는 HTTP 요청, 여기서는 시뮬레이션
            time.sleep(1)  # 네트워크 지연 시뮬레이션
            결과.append(f"뉴스 데이터_{i+1}")
        except Exception as e:
            결과.append(f"오류_{i+1}: {e}")
    
    소요_시간 = time.time() - 시작_시간
    print(f"  동기 처리 완료: {소요_시간:.2f}초")
    return 결과

# 비동기 방식 - 동시에 여러 개 처리
async def 비동기_뉴스_수집(url_목록: List[str]) -> List[str]:
    """여러 뉴스 사이트를 비동기적으로 수집"""
    
    async def 단일_사이트_수집(index: int) -> str:
        print(f"  비동기 처리: {index+1}번째 사이트 접속 시작...")
        await asyncio.sleep(1)  # 네트워크 지연 시뮬레이션
        print(f"  비동기 처리: {index+1}번째 사이트 완료!")
        return f"뉴스 데이터_{index+1}"
    
    시작_시간 = time.time()
    
    # 모든 사이트를 동시에 처리
    작업_목록 = [단일_사이트_수집(i) for i in range(len(url_목록))]
    결과 = await asyncio.gather(*작업_목록)
    
    소요_시간 = time.time() - 시작_시간
    print(f"  비동기 처리 완료: {소요_시간:.2f}초")
    return 결과

# 성능 비교
if __name__ == "__main__":
    가짜_url_목록 = ['site1.com', 'site2.com', 'site3.com', 'site4.com']
    
    print("성능 비교 테스트:")
    print("\n1. 동기 방식 (순차 처리):")
    동기_결과 = 동기_뉴스_수집(가짜_url_목록)
    
    print("\n2. 비동기 방식 (동시 처리):")
    비동기_결과 = asyncio.run(비동기_뉴스_수집(가짜_url_목록))
    
    print(f"\n결과 비교:")
    print(f"  동기 결과: {동기_결과}")
    print(f"  비동기 결과: {비동기_결과}")
```

이 예제는 실제로 인터넷에 접속하지 않고, 사이트 하나당 1초씩 기다리는 것으로 네트워크 지연을 흉내 냅니다. 동기 쪽은 `time.sleep(1)`, 비동기 쪽은 `await asyncio.sleep(1)`로 기다려요. 표준 라이브러리만 쓰니 따로 설치할 것은 없습니다. 실제로 웹 요청을 보낸다면 동기 쪽은 `requests`, 비동기 쪽은 `aiohttp` 같은 외부 라이브러리를 씁니다. 제 컴퓨터(파이썬 3.12)에서 실행한 결과는 이렇습니다.

```
1. 동기 방식 (순차 처리):
  동기 처리: 1번째 사이트 접속 중...
  동기 처리: 2번째 사이트 접속 중...
  동기 처리: 3번째 사이트 접속 중...
  동기 처리: 4번째 사이트 접속 중...
  동기 처리 완료: 4.01초

2. 비동기 방식 (동시 처리):
  비동기 처리: 1번째 사이트 접속 시작...
  비동기 처리: 2번째 사이트 접속 시작...
  비동기 처리: 3번째 사이트 접속 시작...
  비동기 처리: 4번째 사이트 접속 시작...
  비동기 처리: 1번째 사이트 완료!
  비동기 처리: 2번째 사이트 완료!
  비동기 처리: 3번째 사이트 완료!
  비동기 처리: 4번째 사이트 완료!

```

동기 방식은 1초씩 네 번, 4초가 걸렸습니다. 비동기 방식은 네 사이트에 **먼저 다 접속을 걸어 두고** 함께 기다렸기 때문에 1초 만에 끝났어요. "시작" 네 줄이 먼저 나온 뒤 "완료" 네 줄이 나오는 순서가 그 증거입니다. 그리고 결과 리스트의 순서는 두 방식이 똑같습니다. `asyncio.gather()`는 작업이 끝난 순서와 상관없이 **넣은 순서대로** 결과를 돌려주거든요.

### 비동기 함수와 코루틴

비동기 함수는 `async def`로 정의하고, `await` 키워드로 호출합니다. 용어를 먼저 정리해 둘게요. `async def`로 정의한 함수를 **코루틴 함수**, 그 함수를 불렀을 때 나오는 객체를 **코루틴 객체**라고 합니다. 제너레이터 함수를 불러도 본문이 바로 실행되지 않았던 것처럼, 코루틴 함수를 불러도 본문은 실행되지 않고 코루틴 객체만 만들어집니다.

`await`는 "이 작업이 끝날 때까지 나는 여기서 멈춰 있을게, 그동안 다른 코루틴 먼저 해"라는 뜻입니다. `await` 뒤에 올 수 있는 객체를 **어웨이터블(awaitable)** 이라고 하는데, 코루틴, 태스크(Task), 퓨처(Future)가 있어요. 그리고 이 모든 코루틴을 돌리는 지휘자가 **이벤트 루프**입니다. 식당으로 치면 "지금 어느 테이블로 가야 하지?"를 정해 주는 매니저죠. `asyncio.run(코루틴)`은 이벤트 루프를 새로 만들어 코루틴을 끝까지 실행하고, 다 끝나면 루프를 닫습니다. 그래서 보통 프로그램의 시작점에서 **한 번만** 부릅니다.

```python
import asyncio
from typing import AsyncGenerator

# 기본 비동기 함수
async def 한국어_인사(이름: str, 지연_시간: float = 1.0) -> str:
    """비동기적으로 한국어 인사를 생성"""
    print(f"  {이름}님에게 인사 준비 중...")
    await asyncio.sleep(지연_시간)  # 비동기 대기
    return f"안녕하세요, {이름}님!"

# 여러 사람에게 동시에 인사
async def 다중_인사():
    """여러 사람에게 동시에 인사하기"""
    사람들 = ['김철수', '이영희', '박민수', '정지영']
    
    # 모든 인사를 동시에 시작
    인사_작업들 = [한국어_인사(사람, 지연_시간=1.0) for 사람 in 사람들]
    
    # 모든 작업이 완료될 때까지 대기
    인사_결과들 = await asyncio.gather(*인사_작업들)
    
    for 인사 in 인사_결과들:
        print(f"  완료: {인사}")

# 실행
print("비동기 인사 시스템:")
asyncio.run(다중_인사())
```

네 사람에게 "인사 준비 중..."이 한꺼번에 찍히고, 약 1초 뒤 "완료"가 네 줄 나옵니다. 전체 실행 시간도 4초가 아니라 1초 남짓이에요. `인사_작업들` 리스트를 만드는 순간에는 코루틴 객체 네 개만 생기고 아무것도 실행되지 않습니다. `asyncio.gather()`가 이들을 받아서 이벤트 루프에 한꺼번에 올려 줘야 비로소 동시에 출발해요.

### 코루틴 그대로 await 할까, 태스크로 만들까

그렇다면 `async def`로 만들고 `await`만 붙이면 무조건 동시에 실행될까요? 아래 두 함수는 똑같이 1초, 2초를 기다리는 일을 합니다. 차이는 코루틴을 바로 `await` 했느냐, `asyncio.create_task()`로 **태스크**를 만들어 두고 `await` 했느냐뿐이에요.

```python
import asyncio
import time


async def say_after(delay, what):
    await asyncio.sleep(delay)
    print(what)


async def 순서대로():
    await say_after(1, 'hello')
    await say_after(2, 'world')


async def 태스크로():
    task1 = asyncio.create_task(say_after(1, 'hello'))
    task2 = asyncio.create_task(say_after(2, 'world'))
    await task1
    await task2


for main in (순서대로, 태스크로):
    시작 = time.perf_counter()
    asyncio.run(main())
    print(f"{main.__name__}: {time.perf_counter() - 시작:.2f}초")
```

```
hello
world
순서대로: 3.00초
hello
world
태스크로: 2.00초
```

비동기로 짰는데 `순서대로`는 왜 1초 + 2초 = 3초나 걸렸을까요? `await say_after(1, 'hello')`는 코루틴 객체를 만들자마자 "이게 끝날 때까지 기다려"라고 했기 때문입니다. 첫 번째가 끝나야 두 번째 코루틴이 만들어지고 실행되니, 결국 동기 방식과 다를 게 없어요.

`create_task()`는 코루틴을 태스크로 감싸서 이벤트 루프에 **"이것도 돌려 줘"라고 예약**합니다. 두 태스크를 먼저 다 예약해 두고 나서 `await`로 기다리니, 둘이 함께 출발해서 더 긴 쪽인 2초 만에 끝났어요. 정리하면, 여러 작업을 동시에 진행하려면 **태스크로 만들거나 `asyncio.gather()`로 한꺼번에 넘겨야** 합니다. 코루틴을 하나씩 바로 `await` 하면 순서대로 실행됩니다.

> **Q. `await`를 깜빡하고 코루틴 함수만 부르면 어떻게 되나요?**
> 아무 일도 일어나지 않습니다. 코루틴 객체만 만들어지고 본문은 실행되지 않아요. 에러가 나지 않아서 더 찾기 어려운데, 다행히 실행되지 못한 코루틴 객체가 버려질 때 파이썬이 `RuntimeWarning: coroutine '함수이름' was never awaited`라는 경고를 띄워 줍니다. 이 경고가 보이면 `await`를 빠뜨린 곳이 있다는 뜻입니다.

### asyncio에 대한 오해

"비동기는 빠르다"는 말은 반만 맞습니다. 앞의 예제들이 빨라진 것은 **기다리는 시간을 겹쳤기** 때문이지, 파이썬이 계산을 더 빨리 해서가 아니에요. 자주 하는 오해 몇 가지를 실험으로 확인해 봅시다.

**오해 1: asyncio를 쓰면 무조건 빨라진다.** 아래 코드에서 `잘못된_대기`는 `async def` 안에서 `time.sleep(1)`을 썼고, `올바른_대기`는 `await asyncio.sleep(1)`을 썼습니다. 세 개씩 `gather()`로 동시에 돌려 보겠습니다.

```python
import asyncio
import time


async def 잘못된_대기():
    time.sleep(1)  # 이벤트 루프 전체를 멈춤


async def 올바른_대기():
    await asyncio.sleep(1)  # 기다리는 동안 다른 코루틴에 양보


async def main():
    for 작업 in (잘못된_대기, 올바른_대기):
        시작 = time.perf_counter()
        await asyncio.gather(*(작업() for _ in range(3)))
        print(f"{작업.__name__}: {time.perf_counter() - 시작:.2f}초")

asyncio.run(main())
```

```
잘못된_대기: 3.01초
올바른_대기: 1.00초
```

`time.sleep()`은 `await`가 없어서 멈추는 동안 다른 코루틴에 자리를 내주지 않습니다. 식당 직원이 한 테이블 앞에 서서 꼼짝도 안 하는 셈이라 직원 한 명뿐인 이벤트 루프 전체가 멈춰 버려요. `async def` 안에서는 `requests`처럼 기다리는 동안 양보할 줄 모르는 라이브러리 대신 `aiohttp` 같은 비동기 라이브러리를 써야 하는 이유입니다. 같은 이유로, 기다림 없이 CPU로 계산만 하는 작업은 asyncio로 바꿔도 전혀 빨라지지 않습니다.

**오해 2: asyncio는 단일 스레드라서 GIL 문제를 없애 준다.** asyncio가 GIL의 영향을 받지 않는 것은 사실이지만, 그건 애초에 스레드를 하나만 쓰기 때문입니다. 문제를 해결한 게 아니라 문제가 생길 자리가 없는 거죠. 여러 CPU 코어를 동시에 쓰는 일은 asyncio로는 할 수 없습니다.

> **Q. asyncio는 스레드가 하나뿐이니 경합 조건(race condition)은 걱정 안 해도 되죠?**
> 그렇지 않습니다. 스레드 여러 개가 같은 메모리를 동시에 건드리는 종류의 문제는 줄어들지만, `await`로 멈춘 사이에 다른 코루틴이 같은 데이터를 바꿀 수 있습니다. 아래 예제가 그 경우입니다.

```python
import asyncio

잔액 = 0


async def 입금(금액):
    global 잔액
    현재 = 잔액                # 1. 잔액을 읽고
    await asyncio.sleep(0)     # 2. 잠깐 다른 코루틴에 양보한 뒤
    잔액 = 현재 + 금액         # 3. 읽어 둔 값에 더해 저장


async def main():
    await asyncio.gather(*(입금(1) for _ in range(100)))
    print(f"100번 입금한 뒤 잔액: {잔액}")

asyncio.run(main())
```

```
100번 입금한 뒤 잔액: 1
```

1원씩 100번 입금했는데 잔액이 1원입니다. 100개의 코루틴이 모두 `await` 전에 잔액 0을 읽어 두었다가, 깨어나서 각자 `0 + 1`을 저장했기 때문이에요. 이럴 때는 `asyncio.Lock()`을 만들어 두고 읽기부터 저장까지를 `async with 자물쇠:` 안에 넣으면, 한 번에 한 코루틴만 그 구간에 들어가서 잔액이 100으로 맞게 나옵니다. 화장실 열쇠가 하나뿐이면 한 사람씩만 들어갈 수 있는 것과 같은 원리예요.

### 비동기 제너레이터

`async def`와 `yield`를 결합하여 비동기 제너레이터를 만들 수 있습니다. 앞에서 본 제너레이터는 값을 하나씩 건네주었죠. 그런데 다음 값을 만들려면 네트워크에서 새 주가가 올 때까지 **기다려야** 한다면요? 일반 제너레이터 안에서 기다리면 프로그램 전체가 멈춥니다. 비동기 제너레이터는 값과 값 사이에 `await`로 기다릴 수 있고, 그동안 이벤트 루프는 다른 일을 합니다. 받는 쪽은 `for` 대신 **`async for`** 로 값을 꺼내요.

```python
import asyncio
import random
from datetime import datetime
from typing import AsyncGenerator, Dict, Any

async def 실시간_주가_스트림(
    종목코드: str,
    업데이트_간격: float = 1.0
) -> AsyncGenerator[Dict[str, Any], None]:
    """한국 주식의 실시간 가격 스트림을 시뮬레이션"""
    
    # 한국 주요 종목 정보
    종목_정보 = {
        '005930': {'회사명': '삼성전자', '현재가': 75000},
        '000660': {'회사명': 'SK하이닉스', '현재가': 130000},
        '035420': {'회사명': 'NAVER', '현재가': 350000}
    }
    
    if 종목코드 not in 종목_정보:
        raise ValueError(f"지원하지 않는 종목코드: {종목코드}")
    
    회사_정보 = 종목_정보[종목코드]
    현재가 = 회사_정보['현재가']
    
    while True:
        # 가격 변동 시뮬레이션 (-2% ~ +2%)
        변동율 = random.uniform(-0.02, 0.02)
        현재가 = int(현재가 * (1 + 변동율))
        
        주가_정보 = {
            '시간': datetime.now().strftime('%H:%M:%S'),
            '종목코드': 종목코드,
            '회사명': 회사_정보['회사명'],
            '현재가': 현재가,
            '변동율': round(변동율 * 100, 2),
            '거래량': random.randint(1000, 10000)
        }
        
        yield 주가_정보
        await asyncio.sleep(업데이트_간격)

async def 주가_모니터링():
    """실시간 주가 모니터링 시스템"""
    print("실시간 주가 모니터링 시작:")
    
    # 삼성전자 실시간 주가 스트림
    삼성전자_스트림 = 실시간_주가_스트림('005930', 1.5)
    
    # 첫 10개 업데이트만 모니터링
    count = 0
    async for 주가_정보 in 삼성전자_스트림:
        print(f"  [{주가_정보['시간']}] {주가_정보['회사명']}: "
              f"{주가_정보['현재가']:,}원 ({주가_정보['변동율']:+.1f}%)")
        
        count += 1
        if count >= 10:
            break

# 실행
print("\n비동기 제너레이터 활용:")
asyncio.run(주가_모니터링())
```

`while True`라서 이 제너레이터는 끝나지 않는 주가 스트림입니다. 실제 시세처럼 끝이 정해져 있지 않은 데이터를 표현하기에 딱 맞죠. 끝내는 것은 받는 쪽의 몫이라, `주가_모니터링()`이 10개를 받은 뒤 `break`로 빠져나옵니다. 실행하면 대략 1.5초 간격으로 시각이 바뀌며 삼성전자 주가가 10줄 찍히고, 가격은 무작위라 매번 다릅니다.

### 비동기 컨텍스트 매니저

`with open(...) as f:`처럼 `with`문은 "들어갈 때 준비하고, 나올 때 반드시 정리한다"를 보장해 줍니다(12장에서 파일을 다룰 때 봤죠). 그런데 데이터베이스 연결처럼 준비와 정리 자체가 **기다려야 하는 일**이라면 어떨까요? 이때 쓰는 것이 `async with`입니다. 일반 컨텍스트 매니저의 `__enter__`/`__exit__` 대신 `async def __aenter__`/`async def __aexit__`를 구현하면 되고, 함수 하나로 간단히 만들고 싶으면 `@asynccontextmanager` 데코레이터를 씁니다. 리소스를 안전하게 관리하는 비동기 컨텍스트 매니저:

```python
import asyncio
from contextlib import asynccontextmanager
from typing import AsyncGenerator

class 비동기_데이터베이스:
    """비동기 데이터베이스 시뮬레이션"""
    
    def __init__(self, db_name: str):
        self.db_name = db_name
        self.is_connected = False
    
    async def 연결(self):
        """데이터베이스 연결"""
        print(f"  {self.db_name} 데이터베이스 연결 중...")
        await asyncio.sleep(0.5)  # 연결 지연 시뮬레이션
        self.is_connected = True
        print(f"  {self.db_name} 데이터베이스 연결 완료!")
    
    async def 연결_해제(self):
        """데이터베이스 연결 해제"""
        print(f"  {self.db_name} 데이터베이스 연결 해제 중...")
        await asyncio.sleep(0.2)
        self.is_connected = False
        print(f"  {self.db_name} 데이터베이스 연결 해제 완료!")
    
    async def 쿼리_실행(self, query: str) -> str:
        """쿼리 실행"""
        if not self.is_connected:
            raise RuntimeError("데이터베이스가 연결되지 않았습니다")
        
        print(f"  쿼리 실행: {query}")
        await asyncio.sleep(0.3)  # 쿼리 실행 지연
        return f"쿼리 결과: {query}의 결과 데이터"
    
    # 비동기 컨텍스트 매니저로 사용하기 위한 메서드
    async def __aenter__(self):
        await self.연결()
        return self
    
    async def __aexit__(self, exc_type, exc_val, exc_tb):
        if exc_type:
            print(f"  오류 발생으로 롤백: {exc_val}")
        await self.연결_해제()

@asynccontextmanager
async def 데이터베이스_트랜잭션(db: 비동기_데이터베이스) -> AsyncGenerator[비동기_데이터베이스, None]:
    """데이터베이스 트랜잭션 컨텍스트 매니저"""
    print("  트랜잭션 시작")
    try:
        yield db
        print("  트랜잭션 커밋")
    except Exception as e:
        print(f"  트랜잭션 롤백: {e}")
        raise

async def 데이터베이스_작업_예제():
    """비동기 컨텍스트 매니저 사용 예제"""
    
    # async with를 사용한 리소스 관리
    async with 비동기_데이터베이스("한국_고객_DB") as db:
        
        # 중첩 컨텍스트 매니저로 트랜잭션 관리
        async with 데이터베이스_트랜잭션(db):
            결과1 = await db.쿼리_실행("SELECT * FROM 고객")
            print(f"    {결과1}")
            
            결과2 = await db.쿼리_실행("INSERT INTO 고객 VALUES ('김철수')")
            print(f"    {결과2}")

print("\n비동기 컨텍스트 매니저:")
asyncio.run(데이터베이스_작업_예제())
```

이 예제는 두 가지 방법을 모두 보여 줍니다. `비동기_데이터베이스` 클래스는 `__aenter__`/`__aexit__`를 직접 구현했고, `데이터베이스_트랜잭션`은 `@asynccontextmanager`로 만들었어요. 후자에서는 `yield` 앞이 들어갈 때, 뒤가 나올 때 할 일입니다. 여기서도 `yield`가 "잠깐 멈췄다 이어 가기"로 쓰인 거죠. 실행하면 다음 순서로 찍힙니다.

```
  한국_고객_DB 데이터베이스 연결 중...
  한국_고객_DB 데이터베이스 연결 완료!
  트랜잭션 시작
  쿼리 실행: SELECT * FROM 고객
    쿼리 결과: SELECT * FROM 고객의 결과 데이터
  쿼리 실행: INSERT INTO 고객 VALUES ('김철수')
    쿼리 결과: INSERT INTO 고객 VALUES ('김철수')의 결과 데이터
  트랜잭션 커밋
  한국_고객_DB 데이터베이스 연결 해제 중...
  한국_고객_DB 데이터베이스 연결 해제 완료!
```

양파 껍질처럼 바깥 `async with`(연결)가 먼저 열리고 안쪽(트랜잭션)이 나중에 열리며, 닫을 때는 안쪽부터 닫힙니다. 블록 안에서 예외가 나더라도 `__aexit__`는 반드시 실행되니 연결이 열린 채로 남는 일이 없어요.

### 비동기 반복자

`__aiter__`와 `__anext__`를 구현하여 비동기 반복자를 만들 수 있습니다. 15.1절의 반복자 프로토콜과 짝을 이루는 비동기 버전이에요. `__next__` 대신 `async def __anext__`를 쓰고, 끝에서는 `StopIteration` 대신 `StopAsyncIteration`을 일으킵니다. 비동기 제너레이터로도 같은 일을 할 수 있지만, 상태를 여러 속성으로 관리해야 할 때는 이렇게 클래스로 만드는 편이 읽기 쉽습니다.

```python
import asyncio
import json
from typing import AsyncIterator, Dict, Any

class 한국_뉴스_수집기:
    """한국 뉴스를 비동기적으로 수집하는 반복자"""
    
    def __init__(self, 카테고리_목록: list, 각_카테고리_뉴스_수: int = 3):
        self.카테고리_목록 = 카테고리_목록
        self.각_카테고리_뉴스_수 = 각_카테고리_뉴스_수
        self.현재_카테고리_인덱스 = 0
        self.현재_뉴스_인덱스 = 0
    
    def __aiter__(self) -> AsyncIterator[Dict[str, Any]]:
        return self
    
    async def __anext__(self) -> Dict[str, Any]:
        if self.현재_카테고리_인덱스 >= len(self.카테고리_목록):
            raise StopAsyncIteration
        
        현재_카테고리 = self.카테고리_목록[self.현재_카테고리_인덱스]
        
        # 뉴스 수집 시뮬레이션 (비동기 처리)
        print(f"  {현재_카테고리} 뉴스 #{self.현재_뉴스_인덱스 + 1} 수집 중...")
        await asyncio.sleep(0.5)  # 네트워크 지연 시뮬레이션
        
        뉴스_데이터 = {
            '카테고리': 현재_카테고리,
            '제목': f'{현재_카테고리} 뉴스 #{self.현재_뉴스_인덱스 + 1}',
            '내용': f'{현재_카테고리}에 관한 중요한 뉴스입니다.',
            '수집_시간': asyncio.get_event_loop().time()
        }
        
        # 다음 뉴스로 이동
        self.현재_뉴스_인덱스 += 1
        
        # 현재 카테고리의 모든 뉴스를 수집했으면 다음 카테고리로
        if self.현재_뉴스_인덱스 >= self.각_카테고리_뉴스_수:
            self.현재_카테고리_인덱스 += 1
            self.현재_뉴스_인덱스 = 0
        
        return 뉴스_데이터

async def 뉴스_수집_예제():
    """비동기 반복자 사용 예제"""
    print("한국 뉴스 비동기 수집:")
    
    뉴스_카테고리 = ['정치', '경제', '사회', '스포츠']
    뉴스_수집기 = 한국_뉴스_수집기(뉴스_카테고리, 2)
    
    수집된_뉴스 = []
    async for 뉴스 in 뉴스_수집기:
        print(f"    수집 완료: [{뉴스['카테고리']}] {뉴스['제목']}")
        수집된_뉴스.append(뉴스)
    
    print(f"\n총 {len(수집된_뉴스)}개의 뉴스를 수집했습니다.")

print("\n비동기 반복자:")
asyncio.run(뉴스_수집_예제())
```

정치, 경제, 사회, 스포츠 뉴스가 두 개씩 차례로 수집되어 `총 8개의 뉴스를 수집했습니다.`로 끝납니다. 걸린 시간은 0.5초씩 여덟 번, 약 4초예요. 비동기 반복자라고 해서 저절로 동시에 수집하는 것은 아닙니다. `async for`는 한 개를 다 받아야 다음 `__anext__`를 부르니까요. 비동기 반복자의 장점은 수집을 기다리는 그 0.5초 동안 **이벤트 루프가 다른 코루틴을 돌릴 수 있다**는 데 있습니다. 이 프로그램에는 다른 코루틴이 없어서 그 효과가 보이지 않을 뿐이에요.

## 실습 프로젝트: 한국 실시간 주가 모니터링 시스템

이제 배운 내용을 종합하여 실무에서 사용할 수 있는 실시간 주가 모니터링 시스템을 만들어봅시다. 코드가 길지만 역할별로 클래스가 나뉘어 있습니다.

- `한국_주식_시뮬레이터`: 가짜 주가를 만들어 내는 시장 역할
- `주가_데이터_수집기`: 구독한 종목의 주가를 **비동기 제너레이터**로 끝없이 흘려보내는 역할
- `주가_알림_시스템`: 급등, 급락, 거래량 급증 같은 조건을 검사하는 역할
- `주가_데이터_저장소`: 받은 데이터를 날짜별 JSON 파일로 저장하는 역할
- `실시간_주가_모니터`: 위 넷을 조립해서 정해진 시간 동안 돌리는 지휘자 역할

`시작()` 메서드의 `async for`가 이 장에서 배운 것들이 만나는 곳입니다.

```python
import asyncio
import json
import random
from datetime import datetime, timedelta
from typing import Dict, List, AsyncGenerator, Optional, Any
from pathlib import Path

class 한국_주식_시뮬레이터:
    """한국 주식 시장 시뮬레이터"""
    
    def __init__(self):
        self.종목_정보 = {
            '005930': {'회사명': '삼성전자', '현재가': 75000, '전일종가': 74500},
            '000660': {'회사명': 'SK하이닉스', '현재가': 130000, '전일종가': 128900},
            '035420': {'회사명': 'NAVER', '현재가': 350000, '전일종가': 355000},
            '051910': {'회사명': 'LG화학', '현재가': 800000, '전일종가': 795000},
            '006400': {'회사명': '삼성SDI', '현재가': 650000, '전일종가': 645000}
        }
        
        self.시장_개장 = True
    
    def 시장_상태_확인(self) -> bool:
        """주식 시장 개장 시간 확인 (9:00~15:30)"""
        현재_시간 = datetime.now()
        시간 = 현재_시간.hour
        분 = 현재_시간.minute
        
        # 주말이면 폐장
        if 현재_시간.weekday() >= 5:
            return False
        
        # 평일 9:00~15:30만 개장
        if 시간 < 9 or (시간 == 15 and 분 > 30) or 시간 > 15:
            return False
        
        return True
    
    def 주가_변동_생성(self, 종목코드: str) -> Dict[str, Any]:
        """실시간 주가 변동 데이터 생성"""
        if 종목코드 not in self.종목_정보:
            raise ValueError(f"존재하지 않는 종목코드: {종목코드}")
        
        종목 = self.종목_정보[종목코드]
        
        # 시장 상황에 따른 변동성 조정
        기본_변동성 = 0.005  # 0.5%
        if not self.시장_개장:
            기본_변동성 = 0.001  # 장외 시간엔 변동성 감소
        
        # 가격 변동 생성
        변동율 = random.uniform(-기본_변동성, 기본_변동성)
        새_가격 = int(종목['현재가'] * (1 + 변동율))
        
        # 가격 업데이트
        종목['현재가'] = 새_가격
        
        # 등락률 계산
        등락률 = ((새_가격 - 종목['전일종가']) / 종목['전일종가']) * 100
        등락액 = 새_가격 - 종목['전일종가']
        
        return {
            '시간': datetime.now().isoformat(),
            '종목코드': 종목코드,
            '회사명': 종목['회사명'],
            '현재가': 새_가격,
            '전일종가': 종목['전일종가'],
            '등락액': 등락액,
            '등락률': round(등락률, 2),
            '거래량': random.randint(1000, 50000),
            '시장_개장': self.시장_개장
        }

class 주가_데이터_수집기:
    """비동기 주가 데이터 수집기"""
    
    def __init__(self, 시뮬레이터: 한국_주식_시뮬레이터):
        self.시뮬레이터 = 시뮬레이터
        self.구독_종목 = set()
        self.실행_중 = False
    
    def 종목_구독(self, 종목코드: str):
        """종목을 구독 목록에 추가"""
        self.구독_종목.add(종목코드)
        print(f"  {종목코드} 구독 추가됨")
    
    def 종목_구독_해제(self, 종목코드: str):
        """종목을 구독 목록에서 제거"""
        self.구독_종목.discard(종목코드)
        print(f"  {종목코드} 구독 해제됨")
    
    async def 실시간_데이터_스트림(
        self, 
        업데이트_간격: float = 2.0
    ) -> AsyncGenerator[Dict[str, Any], None]:
        """실시간 주가 데이터 스트림"""
        
        self.실행_중 = True
        print(f"실시간 주가 스트림 시작 (구독 종목: {len(self.구독_종목)}개)")
        
        while self.실행_중 and self.구독_종목:
            for 종목코드 in self.구독_종목.copy():  # 구독 목록이 변경될 수 있으므로 복사
                try:
                    주가_데이터 = self.시뮬레이터.주가_변동_생성(종목코드)
                    yield 주가_데이터
                except Exception as e:
                    print(f"  {종목코드} 데이터 수집 오류: {e}")
            
            await asyncio.sleep(업데이트_간격)
    
    def 중지(self):
        """스트림 중지"""
        self.실행_중 = False
        print("  주가 스트림 중지됨")

class 주가_알림_시스템:
    """주가 알림 시스템"""
    
    def __init__(self):
        self.알림_규칙 = []  # (종목코드, 조건, 임계값) 형태
    
    def 알림_규칙_추가(self, 종목코드: str, 조건: str, 임계값: float):
        """알림 규칙 추가"""
        규칙 = {
            '종목코드': 종목코드,
            '조건': 조건,  # 'price_up', 'price_down', 'volume_high'
            '임계값': 임계값,
            '생성시간': datetime.now()
        }
        self.알림_규칙.append(규칙)
        print(f"  알림 규칙 추가: {종목코드} {조건} {임계값}")
    
    def 알림_확인(self, 주가_데이터: Dict[str, Any]) -> Optional[str]:
        """주가 데이터가 알림 조건에 해당하는지 확인"""
        종목코드 = 주가_데이터['종목코드']
        
        for 규칙 in self.알림_규칙:
            if 규칙['종목코드'] != 종목코드:
                continue
            
            조건 = 규칙['조건']
            임계값 = 규칙['임계값']
            
            if 조건 == 'price_up' and 주가_데이터['등락률'] >= 임계값:
                return f"{주가_데이터['회사명']} 급등! {주가_데이터['등락률']:+.1f}%"
            
            elif 조건 == 'price_down' and 주가_데이터['등락률'] <= -임계값:
                return f"{주가_데이터['회사명']} 급락! {주가_데이터['등락률']:+.1f}%"
            
            elif 조건 == 'volume_high' and 주가_데이터['거래량'] >= 임계값:
                return f"{주가_데이터['회사명']} 거래량 급증! {주가_데이터['거래량']:,}"
        
        return None

class 주가_데이터_저장소:
    """주가 데이터 저장소"""
    
    def __init__(self, 저장_경로: str = "stock_data"):
        self.저장_경로 = Path(저장_경로)
        self.저장_경로.mkdir(exist_ok=True)
        self.일일_데이터 = {}  # 종목별 일일 데이터
    
    async def 데이터_저장(self, 주가_데이터: Dict[str, Any]):
        """주가 데이터를 파일로 저장"""
        종목코드 = 주가_데이터['종목코드']
        날짜 = datetime.now().strftime('%Y-%m-%d')
        
        # 종목별 일일 데이터 파일
        파일명 = f"{종목코드}_{날짜}.json"
        파일_경로 = self.저장_경로 / 파일명
        
        # 기존 데이터 로드
        if 종목코드 not in self.일일_데이터:
            if 파일_경로.exists():
                with open(파일_경로, 'r', encoding='utf-8') as f:
                    self.일일_데이터[종목코드] = json.load(f)
            else:
                self.일일_데이터[종목코드] = []
        
        # 새 데이터 추가
        self.일일_데이터[종목코드].append(주가_데이터)
        
        # 파일로 저장 (일반 동기 I/O라서 쓰는 동안 이벤트 루프가 잠깐 멈춤)
        with open(파일_경로, 'w', encoding='utf-8') as f:
            json.dump(self.일일_데이터[종목코드], f, ensure_ascii=False, indent=2)

class 실시간_주가_모니터:
    """실시간 주가 모니터링 시스템 메인 클래스"""
    
    def __init__(self):
        self.시뮬레이터 = 한국_주식_시뮬레이터()
        self.수집기 = 주가_데이터_수집기(self.시뮬레이터)
        self.알림_시스템 = 주가_알림_시스템()
        self.저장소 = 주가_데이터_저장소()
        
        self.실행_중 = False
        self.처리된_데이터_수 = 0
    
    def 설정(self):
        """시스템 초기 설정"""
        print("=== 한국 실시간 주가 모니터링 시스템 ===")
        
        # 주요 종목 구독
        주요_종목 = ['005930', '000660', '035420']  # 삼성전자, SK하이닉스, NAVER
        for 종목 in 주요_종목:
            self.수집기.종목_구독(종목)
        
        # 알림 규칙 설정
        self.알림_시스템.알림_규칙_추가('005930', 'price_up', 3.0)    # 삼성전자 3% 이상 상승
        self.알림_시스템.알림_규칙_추가('000660', 'price_down', 3.0)   # SK하이닉스 3% 이상 하락
        self.알림_시스템.알림_규칙_추가('035420', 'volume_high', 30000) # NAVER 거래량 3만주 이상
    
    async def 시작(self, 실행_시간: int = 30):
        """모니터링 시스템 시작"""
        self.설정()
        self.실행_중 = True
        
        print(f"\n모니터링 시작 (실행 시간: {실행_시간}초)")
        print("-" * 80)
        
        시작_시간 = asyncio.get_event_loop().time()
        
        # 실시간 데이터 스트림 처리
        async for 주가_데이터 in self.수집기.실시간_데이터_스트림(업데이트_간격=1.0):
            # 경과 시간 확인
            현재_시간 = asyncio.get_event_loop().time()
            if 현재_시간 - 시작_시간 > 실행_시간:
                break
            
            # 주가 정보 출력
            self._주가_정보_출력(주가_데이터)
            
            # 알림 확인
            알림_메시지 = self.알림_시스템.알림_확인(주가_데이터)
            if 알림_메시지:
                print(f"    [!]  {알림_메시지}")
            
            # 데이터 저장
            await self.저장소.데이터_저장(주가_데이터)
            
            self.처리된_데이터_수 += 1
        
        print(f"\n모니터링 완료 (총 {self.처리된_데이터_수}건 처리)")
        self.수집기.중지()
    
    def _주가_정보_출력(self, 주가_데이터: Dict[str, Any]):
        """주가 정보를 보기 좋게 출력"""
        시간 = datetime.fromisoformat(주가_데이터['시간']).strftime('%H:%M:%S')
        회사명 = 주가_데이터['회사명']
        현재가 = 주가_데이터['현재가']
        등락률 = 주가_데이터['등락률']
        거래량 = 주가_데이터['거래량']
        
        # 등락률에 따라 상승 [+], 하락 [-], 보합 [=] 표시를 붙임
        등락률_표시 = f"{등락률:+.1f}%"
        if 등락률 > 0:
            등락률_표시 = f"[+] {등락률_표시}"
        elif 등락률 < 0:
            등락률_표시 = f"[-] {등락률_표시}"
        else:
            등락률_표시 = f"[=] {등락률_표시}"
        
        print(f"[{시간}] {회사명:>8} | {현재가:>7,}원 | {등락률_표시:>8} | 거래량: {거래량:>6,}")

# 실행 예제
async def 주가_모니터링_데모():
    """주가 모니터링 시스템 데모"""
    모니터 = 실시간_주가_모니터()
    
    try:
        await 모니터.시작(실행_시간=20)  # 20초간 실행
    except KeyboardInterrupt:
        print("\n사용자에 의해 중단됨")
    except Exception as e:
        print(f"오류 발생: {e}")

if __name__ == "__main__":
    print("실습 프로젝트: 한국 실시간 주가 모니터링 시스템\n")
    asyncio.run(주가_모니터링_데모())
```

실행하면 세 종목을 구독하고 알림 규칙 세 개를 등록한 뒤, 20초 동안 1초마다 SK하이닉스, 삼성전자, NAVER의 시세가 한 줄씩 찍힙니다. 등락률 앞에는 상승이면 `[+]`, 하락이면 `[-]`, 변동이 없으면 `[=]`가 붙어요. 조건에 걸리면 `[!]  NAVER 거래량 급증! 41,001`처럼 알림이 끼어들어요. 실행한 폴더에는 `stock_data/` 폴더가 생기고 종목별 JSON 파일이 쌓입니다. 종목 순서가 매번 달라질 수 있는 것은 구독 목록을 순서가 없는 `set`에 담았기 때문입니다.

한 가지 짚어 둘 점이 있습니다. `데이터_저장()`은 `async def`이지만 안에서 쓰는 `open()`과 `json.dump()`는 일반 함수라서, 파일을 쓰는 동안에는 앞의 `time.sleep()`처럼 이벤트 루프가 멈춥니다. 이 예제처럼 파일이 작으면 문제가 안 되지만, 큰 파일을 자주 쓴다면 아래 REFACTOR 절에서 쓰는 `asyncio.to_thread()`로 파일 쓰기를 별도 스레드에 맡기는 방법을 고려하세요.

### 메모리 효율적인 대용량 데이터 처리

두 가지 도구가 새로 나옵니다. 첫째, `mmap`(메모리 맵)은 파일을 통째로 읽어 들이지 않고 **메모리인 것처럼** 다루게 해 줍니다. 운영체제가 필요한 부분만 그때그때 읽어 오니, 수 GB짜리 파일도 `라인_제너레이터`로 한 줄씩 꺼낼 수 있어요. `__enter__`/`__exit__`가 있어서 `with`문으로 쓰면 파일과 메모리 맵이 자동으로 닫힙니다.

둘째, `asyncio.to_thread(함수, 인자)`는 일반 함수를 별도 스레드에서 실행하고, 그 결과를 `await` 할 수 있게 해 줍니다. 앞에서 `async def` 안에서 `time.sleep()` 같은 일반 함수를 부르면 이벤트 루프가 멈춘다고 했죠? 어쩔 수 없이 일반 함수를 써야 할 때 이렇게 다른 스레드에 맡기면 이벤트 루프는 계속 돌 수 있습니다. `비동기_스트림_처리`는 비동기 스트림에서 데이터를 배치로 모았다가, 한 번에 `동시_처리_수`만큼 스레드에 나눠 맡기고, 끝난 결과를 비동기 제너레이터로 내보냅니다.

```python
import asyncio
from typing import AsyncIterator, TypeVar, Callable, Any
import mmap
import os

T = TypeVar('T')

class 메모리_맵_파일_리더:
    """메모리 맵을 사용한 효율적인 대용량 파일 처리"""
    
    def __init__(self, 파일_경로: str):
        self.파일_경로 = 파일_경로
        self.파일_객체 = None
        self.메모리_맵 = None
    
    def __enter__(self):
        self.파일_객체 = open(self.파일_경로, 'rb')
        self.메모리_맵 = mmap.mmap(self.파일_객체.fileno(), 0, access=mmap.ACCESS_READ)
        return self
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        if self.메모리_맵:
            self.메모리_맵.close()
        if self.파일_객체:
            self.파일_객체.close()
    
    def 라인_제너레이터(self):
        """메모리 효율적인 라인별 읽기"""
        현재_위치 = 0
        
        while 현재_위치 < len(self.메모리_맵):
            라인_끝 = self.메모리_맵.find(b'\n', 현재_위치)
            if 라인_끝 == -1:
                라인_끝 = len(self.메모리_맵)
            
            라인_데이터 = self.메모리_맵[현재_위치:라인_끝]
            현재_위치 = 라인_끝 + 1
            
            try:
                yield 라인_데이터.decode('utf-8').strip()
            except UnicodeDecodeError:
                continue  # 인코딩 오류 라인 건너뛰기

async def 비동기_스트림_처리(
    데이터_스트림: AsyncIterator[T],
    처리_함수: Callable[[T], Any],
    배치_크기: int = 1000,
    동시_처리_수: int = 10
) -> AsyncIterator[Any]:
    """고성능 비동기 스트림 처리 시스템"""
    
    배치 = []
    
    async for 데이터 in 데이터_스트림:
        배치.append(데이터)
        
        if len(배치) >= 배치_크기:
            # 배치를 동시 처리
            처리_작업들 = [
                asyncio.create_task(asyncio.to_thread(처리_함수, 항목))
                for 항목 in 배치[:동시_처리_수]
            ]
            
            완료된_작업들 = await asyncio.gather(*처리_작업들, return_exceptions=True)
            
            for 결과 in 완료된_작업들:
                if not isinstance(결과, Exception):
                    yield 결과
            
            배치 = 배치[동시_처리_수:]
    
    # 남은 배치 처리
    if 배치:
        남은_작업들 = [
            asyncio.create_task(asyncio.to_thread(처리_함수, 항목))
            for 항목 in 배치
        ]
        
        완료된_남은_작업들 = await asyncio.gather(*남은_작업들, return_exceptions=True)
        
        for 결과 in 완료된_남은_작업들:
            if not isinstance(결과, Exception):
                yield 결과

# 사용 예제
async def 고성능_데이터_처리_데모():
    """고성능 데이터 처리 시스템 데모"""
    
    def 한국어_텍스트_처리(텍스트: str) -> dict:
        """한국어 텍스트 분석 (시뮬레이션)"""
        import time
        time.sleep(0.01)  # 처리 시간 시뮬레이션
        
        return {
            '원본': 텍스트,
            '길이': len(텍스트),
            '단어수': len(텍스트.split()),
            '한글포함': any('가' <= char <= '힣' for char in 텍스트)
        }
    
    # 가상의 텍스트 스트림
    async def 텍스트_스트림():
        텍스트_샘플 = [
            "안녕하세요 파이썬!",
            "대한민국의 아름다운 한글",
            "제너레이터와 코루틴 학습",
            "비동기 프로그래밍 마스터하기",
            "실시간 데이터 처리 시스템"
        ] * 100  # 500개 텍스트
        
        for 텍스트 in 텍스트_샘플:
            yield 텍스트
            await asyncio.sleep(0.001)  # 스트림 시뮬레이션
    
    print("고성능 비동기 스트림 처리 시작:")
    시작_시간 = asyncio.get_event_loop().time()
    
    처리_결과_수 = 0
    async for 처리_결과 in 비동기_스트림_처리(
        텍스트_스트림(),
        한국어_텍스트_처리,
        배치_크기=50,
        동시_처리_수=10
    ):
        처리_결과_수 += 1
        if 처리_결과_수 <= 5:  # 처음 5개만 출력
            print(f"  처리 결과: {처리_결과}")
    
    소요_시간 = asyncio.get_event_loop().time() - 시작_시간
    print(f"\n총 {처리_결과_수}개 항목을 {소요_시간:.2f}초에 처리 완료")
    print(f"처리 속도: {처리_결과_수/소요_시간:.1f} 항목/초")

# 실행
print("\n고성능 최적화 버전:")
asyncio.run(고성능_데이터_처리_데모())
```

텍스트 하나를 처리하는 데 0.01초가 걸리도록 만들었으니, 500개를 하나씩 처리하면 최소 5초가 걸립니다. 제 컴퓨터(파이썬 3.12)에서 실행하니 `총 500개 항목을 1.19초에 처리 완료`가 나왔어요. 10개씩 스레드에 나눠 맡긴 덕분입니다. 처리 시간은 컴퓨터마다 다르니 `동시_처리_수`를 바꿔 가며 직접 재 보세요.
